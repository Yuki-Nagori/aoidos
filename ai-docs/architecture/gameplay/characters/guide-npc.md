# 首个引导 NPC

引导者是首场景承担特定交代职责的角色，不是独立于角色模型之外的“NPC 类别”。其作用、故事身份、真值、认知、表面身份和场景在场分别建模。

## 选择

- 剧本最多指定一个固定引导者，必须通过 `isGuide: true` 显式标记已登记的 Character；配置还要给出明确的开场职责。玩家操控的主角不能同时是 guide。没有标记时，开局生成一个 run-local 引导角色；多个标记使剧本无效，不以数组顺序或模型猜测决定人选。
- `openingRole` 描述它为何在开局场景中承担引导，例如冒险者公会前台、守门人或长期同行伙伴。
- `openingRelationship` 描述开场时用何种叙事关系完成引导，不自动建立永久的亲密关系、亲缘或既有共同经历。只有作者真值或已提交世界事件可建立这些关系事实。
- 固定角色复用作者登记的规范 ID 和真值；生成角色由 engine 创建稳定 run-local ID，并将真值、认知和表面资料纳入 run 初始化快照。重新生成不能悄悄替换已冻结角色。

## 交代主线

引导者负责将开局唯一最终目标交给玩家，避免把任务目标包装成一个可选结局菜单。生成的对白可以自然化语气，但不能改变目标 ID、完成规则、角色档案或未授权世界事实。固定人物的名字和基础资料来自登记资源；开场生成可本地化对白，但不得随 locale 改写身份。

## 在场、关系与认知

被选为 guide 不意味着角色必然出现在当前场景、知道所有剧本内容、知道玩家背景或可以自由修改世界。初始化必须分别提交/恢复场景在场、允许该角色知道的事实和任务交代职责。即便角色在场，它也只应得到本次对白需要的最小认知投影。

若剧本没有固定 guide，生成结果必须通过 Character schema 与已有 ID / 角色引用验证，并与其他 run 内角色保持稳定引用。生成失败、ID 冲突、资料缺项或角色权限非法时，初始化整体保持不可玩；不能退回成无身份的自由旁白。

字段协议与实现状态由[剧本标准](../../../standards/scenarios.md)和 [056](../../../task/056-ending-flow-impl.md)维护。角色真值及其对外呈现的边界见[角色认知与呈现](knowledge-and-presentation.md)。
