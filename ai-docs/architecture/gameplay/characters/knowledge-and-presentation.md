# 角色认知、对外呈现与揭露

## 四层模型

角色互动涉及四个不同问题，必须保存在独立的数据域：

1. **真值**：当前故事实际成立的个人和世界事实，由可信剧本或明确提交的世界事件确定。
2. **角色认知**：某个角色在特定时点拥有的知识、来源、确定度、态度或误解。角色可能不知道自己的秘密，也可能相信一个错误说法。
3. **对外呈现**：角色向特定对象、在特定场景做出的自我介绍、主张或伪装。一个 claim 可以与真值冲突，但它本身仍只是“角色说过什么”。
4. **玩家可见事实**：经授权的叙事或互动已经让玩家获知的内容。玩家控制主角不等于自动获得主角真值或其他角色认知。

这些层不能互相覆盖。把一条 false claim 记录为公开陈述，不会修改被它否认的事实；错误信念也不能成为世界状态；显示资料不能反向授权角色知道该资料。

## 认知与获知证据

认知记录应描述主体、对象、事实 ID、来源、发生时间或历史锚点、确定度与适用范围。能够证明玩家或角色听见、观察或被告知某句话的 evidence，只证明传播事件发生；除非另有可信规则，它不证明句子内容为真。场景在场、身份注册、亲缘或同伴关系都不能单独生成知识。

记忆系统可以按其来源策略存储有证据支持的获知与态度，但它不是角色真值的第二份主库。记忆衰减表示难以回忆或降低可访问性，不代表历史事实消失，也不允许记忆反向校正真值。记忆边界见[数据域的记忆架构](../../data/memory.md)。

## 对外主张与谎言

表面身份可按 audience、场景和有效期间保存为 claim，例如自称来自某地、隐瞒真实职业或使用假名。claim 应能追溯到角色、原始 utterance / generation、受众、时间和状态；同一角色可对不同对象使用不同说法。claim 的真伪由授权读模型对照真值计算或由作者明确标注，不能由角色的表达语气推断。

模型可在获准的表演上下文中根据角色认知生成对白，但只能把对白当作待记录的主张。角色撒谎不是 engine 世界 mutation。剧情若要“揭穿”或确认秘密，须有明确的已提交揭露事件，记录公开的是哪条真值、谁获知、对象范围及来源；只有该事件应用后，玩家可见投影才改变。

## LLM 数据投影与防泄漏

每种请求在 engine 侧构造最小、类型化的输入投影，明确包含接收角色可用的认知、当前可见事实和本次允许生成的内容。默认不含其他角色档案、玩家未获知的主角真值、私有标签、无关 run 历史或内部调试信息。输出通过 schema 校验后，分别落入 narration、claim、world mutation 等既有权限边界；自由文本不能跳过已授权的 mutation 入口。

单纯提示模型“不要把秘密告诉玩家”不足以建立保密性，尤其当同一次请求同时读取秘密并输出面向玩家的公开文本。若产品要求强保证，应拆分私有推理与公开叙事的输入权限，或让敏感决定由确定性规则 / 人工创作承担；公开输出还需做服务器侧字段白名单和拒绝策略。模型自然语言仍无法获得绝对不泄漏保证，需把该限制明示为产品风险而不是宣称 prompt 已解决。

## 变化与回退

认知获得、表面陈述、玩家披露和真值修正都是不同事件。它们须绑定来源记录和当前 history branch；回退时只重建有效分支投影，不抹除审计历史。重复、未应用、失败、unknown 或位于分支外的事件都不能授权揭露或修改真值。
