# 角色身份与私有真值档案

更新日期：2026-10-23。剧本实体规范见[剧本标准](../../../standards/scenarios.md)；相关初始化与结局生成由 [056](../../../task/056-ending-flow-impl.md) 实施。

## 身份和控制主体分离

`characterId` 是稳定的故事身份，不由名字、翻译或显示文案推导。run 内的 protagonist binding 指向一个角色 ID，并标识该角色由玩家控制；控制权不能与角色全知权限合并。`player` 这样的注册实体可以是操作者的游戏内角色身份，但“玩家”这个控制主体不是角色档案本身。

所有有剧情作用的角色都要有 run-scoped 档案。它包含主要个人事实和能支撑剧情连续性的背景，不只覆盖 NPC；主角可以由作者、玩家设置或开局初始化生成。每条资料需记录来源类别、schema / source revision 和所属 run。生成结果一旦进入可玩状态便冻结；后续身份发现或纠正必须走显式世界事件和历史分支，不能静默覆盖旧真值。

## 档案层

概念上，档案由以下部分构成：

| 字段                 | 含义                                                                             |
| -------------------- | -------------------------------------------------------------------------------- |
| `characterId`        | 对应规范实体目录的稳定身份                                                       |
| `truth`              | 当前故事正史中的个人事实，可包含姓名、背景、身份、种族、年龄、性别和剧本特定秘密 |
| `truthSource`        | `script`、`player-authored` 或 `run-generated` 等来源及对应修订                  |
| `protagonistBinding` | 可选；明确本 run 中由玩家控制的 actor 身份                                       |
| `profileRevision`    | 档案 schema 和内容修订，用于冻结、审计和恢复                                     |

具体 schema 需要采用有版本、有限大小、严格字段的序列化结构。已由剧本确定的事实应填写明确值，不用 `null` 表示“作者还没想好”。当前 v1 的角色资料字段都是必填字符串，不支持“世界事实尚未设定”的状态：若故事确实要保留未知，须先扩展带版本的 schema 表达未知状态，不能让模型编造真值。与此不同，“真值已确定但暂不揭晓”应保存真实值，并通过 `initialKnowledge`、`presentation` 和获授权的玩家可见投影控制披露。不同来源相冲突时不能让模型自行择一，必须在开局验证或显式事件中解决。

私有真值回答“故事中实际成立什么”，不回答“谁知道什么”或“玩家看到了什么”。例如，一个 NPC 的真实年龄和种族可与公开身份说明不同；这两组数据分别保存，不以展示值反推真值。

当前实体目录中的 `canonicalName` 会被名称解析及部分叙事 UI 直接使用，因此它必须是可公开的规范称呼，不能填入隐藏真名或其他秘密。角色可以有私有真名时，使用安全的公开规范名登记实体，并在 `truth.personalName` 保存真名；玩家可见内容必须通过 `presentation.displayName` 或其他授权投影取得名字，不得回退读取私有真值。若未来需要按玩家认知改变实体显示名，应先提供统一的权限过滤投影，再改造所有 UI 和解析调用点。

## 主角模板与创建输入

主角档案由剧本模板决定，不应把 NPC 的六个基础字段当成所有主角共用的完整设定。模板可以选择以下任一模式，也可以按字段混合：

- **固定主角**：作者给出完整背景、身份、种族、年龄、性别、技能、性格等资料，玩家直接使用。模板仍要满足完整档案要求，不能以空白或 `null` 代表未完成。
- **受限自定义**：模板逐字段声明由作者固定、玩家从有限选项选择、玩家输入并受约束校验，或由剧本提供明确默认值。例如姓名可输入或从候选名选择，性别、年龄段、初始技能和性格特征可各有自己的选项与限制。用户提交的选择 / 文本属于 `player-authored` 来源；固定值属于 `script` 来源。
- **混合档案**：模板固定剧情必需的背景与秘密，只开放安全且不会破坏剧本一致性的字段给玩家选择。模板须标注字段是否公开、是否可修改、选项约束及默认项；隐藏真值不得因为被玩家修改或选择而变成可见事实。

模板自身须版本化，并在可玩前将玩家选择、输入、固定值及来源解析成完整的 run-scoped 真值档案并冻结。可信代码负责校验、规范化、分配稳定身份 ID 和合并选择；LLM 不能擅自覆盖玩家选择、扩充选项或改写由剧本固定的事实。技能、性格等扩展资料应是模板显式声明的有界字段，不塞进自由文本或把它们误当成已实现的引擎能力。玩家可见的创建表单和后续叙事只读取对应公开投影；表单默认值、隐藏答案和私有背景不能泄漏到无关界面、日志或模型请求。

当前 `cycle-input-v2.json` 用 `storyCharacterIds` 明确登记剧情角色集合，并允许初始化生成其中缺少固定档案的角色；它仍没有主角创建模板、字段策略或扩展技能 / 性格 schema。实现自定义主角前需再定义模板 DTO 与输入校验、处理自定义主角的 run-local 实体注册，并保证既有剧本和存档按原 schema 恢复；不能把玩家输入偷偷塞入现有六字段或用开局生成冒充玩家选择。

## 初始来源和冻结

作者固定档案随剧本 revision 发布，引用已登记 Character；它不能被开局模型改写。未固定的剧情角色由初始化流程产生 run-local 档案，主角也必须被覆盖；不在故事中发挥作用的目录实体不需要因此自动生成完整角色资料。所有被生成的身份 ID 由 engine 创建，结果与开局最终目标和规则一起冻结到不可变初始化快照。

运行期间允许可信剧情揭示新事实，但“玩家发现了事实”不能自动修改事实本身。修正真值需要明确来源、授权和应用事件，并保留原档案用于历史分支回退。模型生成的猜测、对白中的主张、记忆候选和叙事描述不能直接写入 `truth`。

## 生命周期与错误

初始化档案引用不存在或非 Character 的 ID、重复身份、缺少必需字段、超限或来源修订不匹配时，整份初始化拒绝；不能部分冻结再让 run 进入可玩态。恢复时读取原 run 快照，不因当前资源变化重新生成。角色真值不写入通用日志、错误详情、诊断码、默认 UI 快照或无关 LLM 请求。消费者必须显式请求经过授权的投影。
