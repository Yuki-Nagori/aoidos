## 语言与内容边界

首版支持 `zh-Hans` 与 `en`。Rust 使用 [sys-locale](https://docs.rs/sys-locale/latest/sys_locale/)读取系统语言并规范化 BCP 47 标签：任何 zh 区域 / 字体变体（包括 zh-TW / zh-HK / zh-Hant）映射 zh-Hans；en 及其区域映射 en；其他、空值和检测失败回退 en。繁体系统显示简体，不能宣称已提供繁体翻译。用户选择优先；system 模式在启动或显式选择 system 时重新检测，不持续监听系统设置。普通浏览器开发确定性使用 en，不从 navigator.language 或 localStorage 建第二份偏好。

界面语言只改变应用文案、辅助技术文案与显示格式，不改变实体 ID、枚举、错误码、骰式、玩家输入、既有记录和日志。剧本元数据可声明有效 BCP 47 `lang`，生成内容按已冻结的剧本 / 请求语言标注；未知语言省略标注，玩家原文不能机械套用剧本语言。界面切换不修改生成语言或重译记录。剧本目录中的 `i18n.json` 只提供选择器等界面的本地化展示名，不翻译正文标题、世界内容或记录，也不由应用翻译表承载。

## 前端与单一资源源

采用 vue-i18n v11 Composition 模式、`@intlify/unplugin-vue-i18n` 构建期预编译与生产 runtime-only；所有消息为随应用发布的可信资源，禁止运行期编译玩家 / 剧本字符串。保持严格 CSP，不加入 unsafe-eval。v11 默认 JIT / AST 与编译器移除设置需在锁定版本下检查实际产物，不能把“runtime-only”名称当作无编译器证据。[官方优化说明](https://vue-i18n.intlify.dev/guide/advanced/optimization)

根 `locales/en.json` 与 `locales/zh-Hans.json` 是发布资源，使用 `common / settings / game / errors / budget / memory / native` 命名空间；英文文件定义 MessageSchema，`bun run i18n:check` 以英文键和占位参数校验简体中文资源。Vite 插件预编译消息并移除生产编译器；ESLint Intl 插件检查裸文案和资源 key，动态错误码由显式映射处理。静态引用强类型。使用文本插值，不用 v-html 解释译文；用户参数按文本显示。数字、金额和日期由 `src-web/utils/format.ts` 的薄 Intl 包装格式化，不建立另一套 numberFormats。

两份资源全部预加载，切换不依赖异步网络。发布前缺键 / 无效消息 / 参数不一致直接失败；运行时异常采用 en 回退，再显示稳定通用文案与诊断码，不泄露插值参数。开发告警包含键名，不包含玩家原文。原生键也参与同键检查，不因前端未引用判为废键。

使用 `@intlify/eslint-plugin-vue-i18n` 检查缺键、未使用 key 与裸文案；ESLint 10 flat config 已在锁定版本下接入。脚本 `i18n:check` 以英文资源为基准校验两种资源的键树、占位参数及静态引用，并拒绝 035 / 031 尚未交付前使用 `budget` / `memory` 命名空间；新增豁免需限定范围。[官方规则目录](https://eslint-plugin-vue-i18n.intlify.dev/rules/)

## 偏好、IPC 与切换

Rust / SQLite 唯一持久真相源，LocalePreference 为 `{ version: 1, locale: "system" | "zh-Hans" | "en" }`，独立单项配置；不替换 ThemePreference 或 UiPreferences。缺项为 system，坏版本 / 枚举按 store.corrupt 处理，不覆盖坏记录。单项写入原子化，迁移 / IO 错误沿用 store.* / app.not-ready。

`locale_get_preference {}` 与 `locale_set_preference { preference }` 返回 `{ preference, resolvedLocale, nativeStatus }`；resolvedLocale 只能 zh-Hans / en；nativeStatus 为 applied / pending。Rust 与 TS 载荷同型，`invoke` 只透传；不支持的版本为 `app.bad-request`，存储沿用 `store.*` / `app.not-ready`。精确契约见[通信契约](ipc-contract.md)。

每应用最多一笔语言写入在飞，后续意图合并为最新值；先确认持久保存，再切 vue-i18n、html lang 与原生文案。旧请求 / 旧视图响应不能覆盖最新意图。保存失败保留上次确认语言；结果不确定主动 get 核验，不重复写来猜测。Rust 原生更新失败不伪装为偏好未保存：返回 pending，显示简短提示；下一次主动读取 / 重试或启动按最新持久值重建。不增加持续轮询、重载页面或改变在飞剧情。

## 首帧初始化与原生界面

`index.html` 静态根为 `<html lang="en">`，两种语言资源随包提供。`public/locale-bootstrap.js` 由 `src-web/locale-bootstrap.ts` 构建：无注入时确定性使用 en；合法 LocaleBootstrap 在首个脚本前设置 lang。每次文档加载时，`src-web/main.ts` 再从 Rust 读取当前持久偏好，更新 `html lang` 与 vue-i18n 后才挂载 Vue，并把已读结果注入组合式函数，避免重载使用旧 locale 或二次查询。读取期间根节点尚无 UI 内容；失败则保留受控 bootstrap 值并显示读取提示。

034 复用 026 受控 main 构建入口，同一个 initialization_script 注入独立版本的 ThemeBootstrap 与 LocaleBootstrap。LocaleBootstrap 为 `{ version: 1, locale: "zh-Hans" | "en", fallbackReason? }`；fallbackReason 仅 storageUnavailable / invalidPreference。枚举序列化进入受信任脚本，禁止拼接系统 locale 原始字符串。HTML head 在根节点创建后、CSS / module 之前应用 lang，Vue 首次挂载直接使用相同 locale；不等待 mounted invoke 修正文案。CSP、主 frame / 精确 dev origin、显式重载重新读偏好均沿用 026，不二次创建窗口。

Tauri setup 从共享数据库读取偏好后，将 LocaleBootstrap 与 026 的 ThemeBootstrap 合并注入同一主 WebView 初始化脚本，不重复创建窗口。该注入保证新进程启动的首个脚本使用已保存值；文档重载时由 main 的挂载前读取刷新，读取失败使用注入值并提示，不回写偏好。普通浏览器开发始终以 en 作为确定性 bootstrap，Rust IPC 不可用时保留该值并提示。初始化脚本只含版本、locale 与受约束的回退原因，不包含费用默认、密钥或业务状态。

原生范围含应用菜单、托盘、凭据对话框标题 / 内容 / 按钮与窗口标题。Rust build.rs 从同一 JSON 提取 `native.*`，在构建期互校键与占位后嵌入常量，不运行时读文件。凭据对话框由三平台原生输入实现消费相同的 `NativePromptText`；系统管理的对话框按钮等仍由操作系统控制。菜单动作 ID 不随文案变化，切换语言时更新菜单、托盘和窗口标题，不重启应用；更新失败返回 pending，保留已保存偏好。

Tauri 预定义菜单支持自定义 text；隐藏 / 退出等应用可命名标签使用 native.*，不能笼统称为随系统语言。操作系统管理的服务子菜单内容、文件选择器系统按钮等按系统语言，应用只控制其 API 允许设置的文案。[Tauri 菜单 API](https://v2.tauri.app/reference/javascript/api/namespacemenu/)

## 格式化、金额与错误

语言、币种、时区分别传入。显示时间使用显式 IANA 时区；业务月边界在 Rust 计算，Intl 不计算额度周期。非法日期 / 时区显示可诊断占位，不能悄悄改用浏览器本地时区。数字格式化不影响排序、比较或机器序列化。

金额 IPC 为十进制字符串 + CNY / USD；Rust 定点金额与 rust_decimal 转换，禁止 f64。前端不先 Number(amount)：在纯 utils 用字符串 / BigInt 精确舍入到显示位，再用 [Intl.NumberFormat.formatToParts](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/formatToParts) 的 BigInt 整数分组与货币模板组装小数。CNY / USD 主视图 2 位，请求计价详情最多 9 位；显示舍入 HALF_UP（正负对称），账本精度独立。大额、负额、负零、极小值和不同地区符号位置配黄金测试；若锁定 WebView 支持直接精确格式化十进制字符串，可作为经过实测的替代，不能依赖旧引擎隐式 Number 转换。

首次建预算按 resolvedLocale 冻结明确币种：zh-Hans 为 CNY，其余 USD；后续只能通过费用设置显式改，语言变化不重算已用 / 上限。系统语言、预算币种、预算时区各自持久化，不隐式联动。

示例界面错误按 code 映射到固定消息，每个 switch 有 default。未知码显示通用错误与码名；`CmdError.message` 不作为主要界面文案，不展开任意 detail。阶段、终态、结束原因及记录类型同样映射；玩家正文、剧本正文标题、实体 / 模型 ID 保持原文。剧本选择器显示该剧本目录 `i18n.json` 中与当前界面语言对应的展示名；主题选择器按稳定 ThemeId 使用界面资源中的名称。后续完整界面（025）、记忆设置（031）和计费（035）复用资源与格式化能力。

## 实施与验证

034 负责以英文资源为类型基准的翻译资源、偏好、bootstrap、原生界面、薄格式化、错误映射，以及主题和剧本选择器的本地化展示名。025 消费这些能力交付完整游戏 UI，031 接记忆高级设置，027 后续费用实施消费精确金额与 locale。设计不安装依赖，jiff 属费用月边界实现，rust_decimal 可与费用共享工作区版本。

验收覆盖英文基准资源与占位互校、缺键 / 裸文案门禁、bootstrap、偏好读写 / 失败 / 并发、原生文案、主题和剧本展示名、显式时区和精确金额。当前原生集成目标在三平台 CI 验证真实 WebView、菜单 / 托盘 / 窗口标题与平台输入适配；本地完整门禁为 `bun run verify` 十三项，Task 034 记录实际 CI 和最终结果。操作系统控制的系统文案不保证随应用切换，首版不提供繁体翻译或原文自动翻译。
