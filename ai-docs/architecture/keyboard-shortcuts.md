# 快捷键与键盘交互

更新日期：2026-10-20。本文记录 `aoidos-art` 提案中已采纳的快捷键设计。052 已提供只读速查和设置视觉层，所用数据只是静态展示；真实动作注册表、全局分发、改键与偏好持久化由 [057](../task/057-keyboard-shortcuts-impl.md) 承接。057 完成前，不得将展示内容宣称为已生效快捷键。设计来源：`aoidos-art` 提交 `1f19504ebc7390b7d9954b1c597fc3d98b6b7fde` 的 `docs/shortcuts.md`。

## 适用原则

- `Mod` 在 Windows / Linux 表示 Ctrl，在 macOS 表示 Cmd；界面提示按实际平台呈现。
- 输入法组字优先：`event.isComposing`、`event.key === "Process"` 或 composition 守卫有效期间，不拦截 Escape、Enter 或任何组合键；上屏后不补发快捷键。
- 普通单键快捷键只在焦点不位于 input、textarea、select 或 contenteditable 时生效。全局 `Mod` 组合不得覆盖系统编辑行为。
- 字符键按 `event.key` 匹配，统一字母大小写；不得依赖键盘布局相关的 `event.code` 判断 `/`、`?` 等字符。
- 快捷键按作用域栈从最内层开始分发：输入法 → 指令 / 上下文菜单 → 模态 → 面板 → 舞台 / 全局。命中后阻止默认行为并停止向外传播；已被其他组件消费的事件不能重复触发。
- 所有全局监听在作用域卸载时移除。不可把短暂 hover 状态持久化，也不能让按键直接发起收费请求或破坏性操作。

## 系统保留键

Aoidos 不处理系统编辑与窗口操作：`Mod+C/V/X/A/Z`、退出 / 关闭窗口（`Mod+Q`、`Alt+F4`）、刷新（`Mod+R`、`F5`）、查找 / 打印（`Mod+F`、`F3`、`Mod+P`）、缩放（`Mod+=/-/0`）、开发者工具组合、前进 / 后退组合，以及操作系统和输入法保留的切换键。具体保留组合按 Windows、macOS、Linux / 桌面环境分别核验，不用设计稿列表取代真实平台验证。

发布版 Windows WebView2 应关闭浏览器快捷键，调试版保留开发者工具能力；macOS「设置…」菜单和前端动作须走同一动作 ID，不能双触发；Linux WebKitGTK 的浏览器保留键由应用侧守卫处理。窗口关闭、平台菜单与原生 WebView API 的验收须记录实际平台证据，浏览器测试不能代替实机检查。

## 改键与存储

改键配置由 Rust 持有的 `UiPreferences` v2 校验并持久化，前端不得自己维护另一份真值。v1 迁移保留 `panelPinned` / `diceMode` 并为 `keymap` 初始化空覆盖；只存与默认不同的动作，`null` 表示显式解绑，空对象恢复默认。未知动作、锁定动作、保留键、非法组合和重复绑定须整份拒绝，不保存部分结果；写入失败回滚到上次已确认值。

录制状态可由 Escape 取消；忽略组字输入。系统保留键不能录入。发生冲突时提示玩家明确选择替换，替换操作要原子地解绑旧动作并绑定新动作。平台展示、帮助浮层、设置页、`aria-keyshortcuts` 和按键提示都由同一动作定义派生。

## 验收边界

025 已实现的 `Ctrl/Cmd+Shift+M`、Escape 优先级、输入发送 / 换行和设置模态焦点规则继续是现有行为契约。052 的速查与设置只呈现设计分组、说明、状态标记和平台按键；它们不是动作注册表，禁用的改键控件不会写入偏好。057 将用动作注册表取代静态展示数据并接入实际分发、筛选和改键；三平台原生行为未取得证据的平台须保持未验证。
