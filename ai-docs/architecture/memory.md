# 记忆系统

更新日期：2026-10-06。状态：**部分规则已确认，设计未定稿**。对应 [007](../task/007-memory-design.md) 与 [issue #13](https://github.com/Yuki-Nagori/mythos/issues/13)。本文先固定已认可的边界；待决策表中的方案不能作为实现依据。当前没有记忆运行时，实现任务在设计评审后另行规划。

## 真相、状态与投影

JSONL 保存可审计的记录与因果事实，SQLite 保存可纠正、可重建的当前状态；LLM 上下文是受预算约束的短寿命投影。具体提交、重放与回退协议沿用[记录引擎](record-engine.md)和[阶段机](turn-state-machine.md)，供应商 chat 历史不能替代本地持久化。

遗忘是产品行为，不是删除历史。归档、压缩、容量驱逐不删除原始玩家台词和已提交事实，也不使模型摘要自动获得修改世界的权限。模型摘要、角色认知和引擎确认的世界事实需要区分；回写能修改哪一类内容见 M01。

007 v1 不接入 006 投影热路径，不引入向量检索。日常生成仍使用冻结前缀、recap、最近记录窗口和有界世界投影。记忆的可选注入是后续实现范围，不能据此修改现有纯函数 `project` 的职责。

## 三个独立领域

| 领域                  | 生命周期             | 写入来源                            | 消费与退出                                                            |
| --------------------- | -------------------- | ----------------------------------- | --------------------------------------------------------------------- |
| 会话记忆              | 同一世 / 周目内      | 门控通过的有来源素材                | 后续可选注入；强化、衰减、归档、复活与遗忘回写                        |
| 轮回缓存 cycle        | 同一剧本跨周目       | 引擎授权规则 / 标签产生的结构化刻痕 | 新周目可选注入；独立去重与代际归档，不走会话 strength 删除 / 回写路径 |
| 段 / 节点收束 segment | 章、幕、场的节点边界 | 已确认的节点晋级                    | 可选收束与压缩；是否开启新 session 重冻前缀待 M02 决策                |

recap 是记录投影摘要，不等于会话记忆；segment 是收束边界，不是第四种回合 phase；cycle 也不是继续使用上一世的世界状态。`runId` 表示周目身份，`cycleGen` 表示代数；其与既有 `sessionId` 的映射尚未定型，不能当作已有字段或 IPC 类型。

## 会话记忆门控

```text
已提交、当前因果路径有效的素材
  → 回声强化（纯函数，只强化旧条）
  → 已记过粗筛（复述转强化，不新增重复条）
  → 值得记（有界 LLM JSON，默认拒绝）
  → 忠实门（来源与玩家逐字引用核验）
  → 受控保存
```

同一条素材在强化与复述分支之间不能重复计分；失败重试和记录重放不能重复强化或创建条目。具体匹配、计分、时间窗与幂等键在算法标定和存储协议定稿后确定。

值得记的候选评分维度为剧情、关系、玩家偏好、伏笔，权重待研。非 JSON、缺字段、越界值、护栏失败和无法核验的来源均拒绝候选，不默认接纳，不通过无限修复 JSON 请求补救。语义拒绝不是 `llm.quota`；余额 / 配额不足按 [005](llm.md) 的错误分类处理。

所有模型请求沿用 005 的冻结配置、护栏、超时和有限重试策略，并经 020 的全局单在飞协调。背景记忆工作不能绕过产品请求占用，也不能自动换供应商或开启额外收费链路。

### 忠实引用与因果有效性

凡声明为玩家原话的内容，必须指向 006 中玩家记录的 `seq`，并与该行原始 UTF-8 正文的合法字节区间逐字相同。不能先 trim、纠错、归一化或改标点再声称逐字引用；改写内容只能标作摘要。玩家输入 mode 必须保留，场外输入不能被转述为角色在场内说过的话。

来源核验还必须确认剧本 / session 身份、来源正文一致性及当前有效因果路径。单凭物理最大 `seq` 或文字相似不能证明来源有效。回退后失效来源不能参与注入、强化或新回写；生成期间发生回退的旧候选不能提交。跨 session 来源校验取决于 M02 的身份方案。

已显示但未完成的旁白不能被记成已经成立的结算结果。字面引用只证明文字存在，不证明模型从中推导的关系、偏好或世界事实成立；各类推导的允许范围仍需随 M01 定稿。

## 衰减、容量与复活

会话条目有 `active | archived` 状态；容量满时归档，不删除。复活重置该条目的衰减时钟，但不能恢复已经失效的因果来源，也不能重复计入同一强化原因。

时钟以活跃对局日 / 回合为主，墙钟为辅。有效时间单位、失败 / 取消回合是否计数、离线时间是否衰减，以及半衰期、强化系数、容量、排序与平局处理尚未确认。接口先固定输入职责和状态语义，公式候选、标定方法与对照实验见[算法附录](memory-algorithms.md)，不照抄 Herta 的终值。

归档后的正文与来源仍保留。归档容量、索引分页、单条正文和恢复扫描同样需要预算，不能把“归档不删”解释为全部历史常驻内存。

## 存储与失败边界

已确定载体为 SQLite manifest 与 `workspaces/<script-id>/memory/` 文件正文；覆写前保留 `backups/`。复用 [mythos-store 与存储基建](storage.md)，不引入 ORM；跨剧本不共享。cycle 使用独立表 / 目录和生命周期，不混入会话条目的 strength 归档流程。

manifest 需要关联条目身份、正文版本与校验信息、状态、来源、周目和计分原因，才能识别重复提交、过期候选与文件 / 索引不一致。此处是所需信息，尚非数据库 schema 或 Rust / TS API 定义。

原子替换文件不等于跨文件 / SQLite 原子事务。实现定稿必须补齐提交顺序、幂等标记、崩溃恢复与备份恢复规则。不能在正文落盘后索引失败时声称所有状态都未变，更不能先发布成功再补写持久化。

模型拒绝或提交前失败不修改既有人设。提交结果不确定时先核验与恢复，不能让未经确认的新状态继续参与生成。失败需要可审计诊断；新增 system.code / 事件 / 错误码须按 006 / 通信契约登记，不把本文的概念直接作为当前可用事件。

## 遗忘回写

回写目标分为关于玩家、世界 / 人设、NPC 三类桶；NPC 桶懒建。回写保留专名和来源，不能在压缩中静默丢弃专名；覆写前备份，失败可恢复。cycle 不走此路径。

issue 提出的“较新 + 更高强度”保留为冲突处理意图，暂不定义为自动覆盖规则：较新但较弱、较旧但较强、不同来源相互矛盾时，尚无唯一排序。strength 是记忆显著性，不能直接证明世界事实为真。M01 决定可改写的页面和冲突处理权限，算法附录再确定可验证规则。

纠正不能抹掉 JSONL 历史，也不能绕过 006 / 012 已定稿的类型化世界变更和审计协议。模型是否只能改派生记忆页、以及如何提交真正的人设 / 世界纠正，需要明确后才能实施。

## 触发、让位与预算

闲置后台、幕切、会话结束的记忆工作均默认关闭。启用收费后台前需要明确授权；触发不代表可以占用所有闲置时间或无上限扫描历史。用户返回时在安全边界让位，不中断已经开始的持久化提交。

012 已提交 `roundEnded/completed` 后的一次只读钩子可作为素材入口；重放不能再次自动收费。该钩子当前只提供来源身份，不意味着每回合都必须调用模型。007 的触发阈值独立标定，不套用 006 recap 的已定稿数值。

实现前必须给正文、条目数量、输入素材、候选 JSON、单轮扫描、模型调用、队列与诊断明确硬上限。模型请求受 005 的预算约束；具体数值在评审和标定后冻结，不把未填参数当无限。

## 轮回缓存

轮回缓存默认关闭，作用域是剧本。内容为结构化刻痕与有硬上限的短摘要，带周目身份和代数；由规则表或可信 `cycle:true` 标签授权。模型不能自行选定持久身份、授予跨周目权限或写任意长文。

压缩顺序为同 id 去重、按权重与代数进行独立归档、可选轮回提要。提要默认关闭；其调用预算与来源校验仍受共同规则约束。“权重 × 代数”的具体表达式待研，不能先实现为越旧越重要或据此删除正文。

新周目注入有 Top-K 与字数硬上限；角色 / 玩家 / NPC 各自能否读取以及防止未来剧情泄露的规则见 M03。cycle 不隐式继承上一世的死亡、关系或其他 SQL 世界状态。

注入若进入新 session 静态段，必须在创建 header 前完成冻结；内容变化会改变前缀字节与 hash，不能承诺供应商缓存继续命中。现有 session 内不热替换 `header.staticPrefix`。动态注入位置、预算及检索时机须经后续投影设计评审，007 v1 不提供该能力。

## 节点节奏与收束

章 / 幕 / 场是数据轴，不写死每章回合数。引擎维护 SQL 隐性计量，玩家原文中不加入计量值；模型不能自由修改计量或创建场景身份。晋级仍需遵守 012 的可信场景目录、条件校验与先提交后发布规则。

节点切换是段收束的主要触发点，可选压缩不能被默认开启。日常超预算首先尝试 006 已允许的确定性预算处理；必需内容仍放不下时沿用预算拒绝 / 压缩计划协议，不暗加付费请求或裁掉完整当前玩家输入。

安全阀需要防止永不晋级，但不能跳过可信场景条件、随机代替失败的场景提议或伪造结算。停滞阈值与合法出口方案待 M05；“下一段重冻前缀”的 session 边界待 M02。在决策前，现有场景推进继续通过动态 `WorldView`，不改既有 header。
