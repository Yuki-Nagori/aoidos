# 记忆系统

更新日期：2026-10-06。状态：**主要产品规则已确认，工程协议与算法待细化**。对应 [007](../task/007-memory-design.md) 与 [issue #13](https://github.com/Yuki-Nagori/mythos/issues/13)。本文先固定已认可的边界；已确认产品规则作为后续设计约束，未定型的工程协议和算法参数不能作为实现依据。当前没有记忆运行时，实现任务在设计评审后另行规划。

## 真相、状态与投影

JSONL 保存可审计的记录与因果事实，SQLite 保存可纠正、可重建的当前状态；LLM 上下文是受预算约束的短寿命投影。具体提交、重放与回退协议沿用[记录引擎](record-engine.md)和[阶段机](turn-state-machine.md)，供应商 chat 历史不能替代本地持久化。

遗忘是产品行为，不是删除历史。归档、压缩、容量驱逐不删除原始玩家台词和已提交事实，也不使模型摘要自动获得修改世界的权限。世界事实与角色记忆的权限边界已确认，见下方“遗忘回写”；认知冲突按“明确纠正更新、未决保留疑惑”处理，具体判定与提交协议仍需细化。

007 v1 不接入 006 投影热路径，不引入向量检索。日常生成仍使用冻结前缀、recap、最近记录窗口和有界世界投影。记忆的可选注入是后续实现范围，不能据此修改现有纯函数 `project` 的职责。

## 三个独立领域

| 领域                  | 生命周期             | 写入来源                            | 消费与退出                                                            |
| --------------------- | -------------------- | ----------------------------------- | --------------------------------------------------------------------- |
| 会话记忆              | 同一世 / 周目内      | 门控通过的有来源素材                | 后续可选注入；强化、衰减、归档、复活与遗忘回写                        |
| 轮回缓存 cycle        | 同一剧本跨周目       | 引擎授权规则 / 标签产生的结构化刻痕 | 新周目可选注入；独立去重与代际归档，不走会话 strength 删除 / 回写路径 |
| 段 / 节点收束 segment | 章、幕、场的节点边界 | 已确认的节点晋级                    | 同一 session 内更新动态状态、可选收束与压缩；不重冻前缀               |

recap 是记录投影摘要，不等于会话记忆；segment 是收束边界，不是第四种回合 phase；cycle 也不是继续使用上一世的世界状态。`runId` 表示周目身份，`cycleGen` 表示代数；段切不创建新 session；周目身份的具体存储映射尚未定型，不能当作已有字段或 IPC 类型。

## 会话记忆门控

```text
已提交、当前因果路径有效的素材
  → 回声候选（纯函数，只定位旧条，不提交强化）
  → 已记过粗筛（复述进入强化候选，不新增重复条）
  → 语义分类与值得记（合批、有界 LLM JSON，默认拒绝）
  → 忠实门（来源与玩家逐字引用核验）
  → 受控保存
```

同一条素材在强化与复述分支之间不能重复计分；失败重试和记录重放不能重复强化或创建条目。具体匹配、计分、时间窗与幂等键在算法标定和存储协议定稿后确定。

“值得记”的范围已确认，权重与接纳阈值待标定：

| 维度     | 值得记的范围               | 限制                                                   |
| -------- | -------------------------- | ------------------------------------------------------ |
| 剧情     | 重要经历、选择、承诺与后果 | 保留来源与事实 / 陈述 / 认知的区别，不把声明当成功结果 |
| 关系     | 信任、戒备、冲突等认知变化 | 限定对应角色实际获知的内容，不自动改变关系数值         |
| 玩家偏好 | 明确表达的体验偏好         | 一次行为不直接推断长期喜好，不自动赋予角色知识         |
| 伏笔     | 有来源支持的未解决线索     | 模型不能自行把普通细节升级为伏笔或泄露未经授权的信息   |

普通寒暄、重复措辞、没有新信息的提及不新增记忆；重提既有经历是否强化仍按回声规则判断。重要但有歧义的内容先询问确认，评分再高也不能绕过来源、权限与忠实门。

非 JSON、缺字段、越界值、护栏失败和无法核验的来源均拒绝候选，不默认接纳，不通过无限修复 JSON 请求补救。语义拒绝不是 `llm.quota`；余额 / 配额不足按 [005](llm.md) 的错误分类处理。

所有模型请求沿用 005 的冻结配置、护栏、超时和有限重试策略，并经 020 的全局单在飞协调。背景记忆工作不能绕过产品请求占用，也不能自动换供应商或开启额外收费链路。

### 结构化判定与程序消费（已确认）

LLM 返回有界结构化候选，分类为复述、补充、新事件、纠正、不值得记或不确定。候选包含涉及的稳定实体 ID、关联旧记忆、原始记录与文本区间、拟保存摘要、所属维度和简短理由；字段是否必需随分类约束，例如新事件无需凭空引用旧记忆，不值得记无需拟写正文。具体 JSON schema、枚举拼写与大小预算仍待协议定型，本文不声明已有 Rust / TS 类型。

程序核验来源有效性、权限、实体 / 旧记忆身份、逐字引用和重复处理情况后，才可提交对应修改。字符匹配只用于定位候选；回声和粗筛纯函数产生判断输入或强化候选，不自行将相似文本认定为语义一致后落盘加分。语义判定也不因模型给出高置信度而免除核验。

模型不能返回可执行 SQL、文件路径 / 覆写命令或自行登记新实体；模型提出的关联不能直接转成别名登记，仍需满足明确指向及冲突检查规则。简短理由只是判定依据摘要，不要求或保存模型内部推理过程。

有效且可核验的“不确定”分类按歧义询问规则处理。超时、非 JSON、缺字段、字段非法、护栏失败或无法核验的来源属于处理失败，拒绝本次候选，不把这些故障伪装成语义问题交给玩家回答；失败仍遵守 005 的错误分类和有限重试，不暗加修复请求。

### 素材资格（已确认）

素材进入管线前，先核验提交状态、来源身份与当前有效因果路径；通过资格检查不代表值得记，也不代表角色已经知道。资格检查适用于新增、强化和回写，不能仅在保存新条目时执行。

| 素材                           | 资格与使用边界                                                       |
| ------------------------------ | -------------------------------------------------------------------- |
| 当前有效因果路径上的已提交记录 | 可作为来源，仍需通过后续门控与可见性检查                             |
| 玩家原文                       | 保留场内 / 场外 mode；引用逐字一致，陈述不自动证明动作成功或事实成立 |
| 已完成旁白                     | 可提取角色经历；只有引擎确认的结果才属于世界事实                     |
| 已提交引擎结算                 | 可作为事实来源，角色是否获知须另查可见范围                           |
| 未完成、失败或取消的旁白       | 不提取新记忆；已保存正文仍保留，不作为强化或回写依据                 |
| 回退后失效的记录               | 不参与新增、强化或回写                                               |
| recap、记忆摘要、模型候选      | 仅辅助定位原始来源，不能单独证明事件发生，不以摘要自我引用形成证据链 |

玩家输入已经提交但后续生成失败时，原文仍可作为“玩家说过什么”的来源；不能据此认定声明的动作成功。旁白资格按其自身完成状态核验，回合失败不把已经确认的结算抹掉，也不把保留下来的 partial 升格为完成旁白。

场外输入可以用于玩家偏好，例如不喜欢恐怖描写；不能转成角色台词，也不能自动赋予 NPC 对该输入的知识。玩家偏好与角色认知在归属和消费权限上分开，不能因共用记忆载体混为一类。

### 角色获知范围（权限方向已确认）

引擎维护有来源的角色获知记录，模型只能提出候选，不能自行给角色授予知识。获知记录须关联具体角色、原始来源及有效因果路径；获知方式与角色对内容的理解分开，不把“听见某人说过”直接升级为世界事实或角色确信。

同处一个场景不自动代表听见或看到所有事件；旁白可用的信息不自动成为 NPC 的知识。传闻保留“听说”的来源与不确定性，不能经摘要、强化或复活变成无条件确信。玩家知道、场外确认及实体别名也不能替代角色实际获知的依据。

候选仍由程序核验来源与权限后提交；无法确定某角色是否获知时不自动赋予该知识。具体获知证据、字段、权限判定与纠正状态转换尚待设计；本节确认权限分工，不代表获知协议或运行时已实现。

### 回声强化约束（已确认）

- 仅强化同一记忆主体有权获知、来源仍有效的旧条目；素材先通过资格检查。
- 相同名字不构成强化依据。“我相信阿明”与“我不再相信阿明”不能因文字相似强化原有信任。
- 明确重提同一经历或印象，才可成为强化候选；模糊相似只用于定位，不直接加分。
- 纠正、否定、关系变化进入后续判断，不作为旧印象重复；强度仍不代表事实真实或角色已经相信。
- 同一来源对同一条记忆最多强化一次；重试、重放及后续重复筛选不能再次计分。

强化形状已确认：收益递减、单条封顶；同一经历跨不同回合的复述仍受限，不能仅通过不同来源反复刷强度。它与“同一来源只计一次”的幂等约束分别执行。再次发生的重要新经历独立判断，不能作为旧事件复述压掉。强化始终不改变真实性、角色权限或因果有效性。

单次增益、递减速度、封顶值、同经历重复强化窗口与次数待标定，当前不冻结数值或最终计算公式。

匹配阈值、加分幅度以及如何精确识别明确回指仍待算法设计 / 标定。纯函数只能处理已核验的输入，不能宣称字面相似足以判定语义一致；没有可靠依据时不自动强化。

### 重复分类（已确认）

| 分类                         | 处理                                                   |
| ---------------------------- | ------------------------------------------------------ |
| 同主体、同经历、同含义的复述 | 复用旧条目，可按强化规则处理，不新增或重复计分         |
| 同一人物的新事件             | 作为新候选，不因人物相同或措辞相似合并                 |
| 同事件的细节补充             | 作为旧条目更新候选，保留新增来源，不因增加细节重复加分 |
| 纠正或推翻旧理解             | 进入认知纠正流程，保留旧印象与变化过程                 |
| 无法确定是否重复             | 继续后续判断，不自动合并、强化或保存                   |

粗筛纯函数只定位候选；文字相似不能独自证明事件相同，匹配不到也不能证明是新事件。语义分类由 LLM 提供结构化候选并由程序核验；具体判定协议与批次参数尚待细化；歧义询问与未答复行为按下节已确认规则执行，不把产品分类当作字符匹配已解决语义判断的证据。

### 实体名称与自动别名（已确认）

规则适用于人物、地点、组织、物品与剧本术语。关联使用引擎登记的稳定实体 ID，正式名称和别名用于定位候选。AI 生成名称时需对照对应类别、范围内的目录与已登记别名检查冲突；重名、同音或过于近似时要求换名，不能仅靠 prompt 禁止就声称已经保证无冲突。近似检查用于发现歧义，不是合并不同实体的依据。具体近似算法、阈值与生成失败处理仍待设计 / 验证。

名称与别名校验按类别和范围执行：地名结合所属地区，例如不同城镇的“东门”不能全局合并；人物也不能仅凭当前场景缺少另一人就认定指向唯一。跨类别同名不自动共享别名或实体 ID，目录缺项不代表不存在歧义。

术语指向必须保留机制含义。“灵力”和“魔力”可能是不同机制，意思相近不构成别名依据；缩写或错字仍需明确指向。普通描述如“那座城”“那个法术”仅解析本次对象，不直接登记为永久别名。

采用“明确指向后的自动别名学习”：玩家在明确指向李雷的对话中输入“李磊”，且上下文没有其他候选时，可以将“李磊”自动登记为李雷的别名。多个候选、可能介绍新人物、别名在对应类别 / 范围内已被其他实体占用时，不自动登记；同音 / 字形相似或模型单次判断都不足以单独触发登记。

别名作用域限于当前周目，保留登记来源，支持纠正与撤销；不因轮回刻痕自动跨周目继承。纠正别名不能无审计地把既有记忆迁移到另一实体，受影响的关联需要重新核验。回退使登记来源失效时，派生别名也需按有效路径重建 / 排除，不能把无效来源留下的别名继续用于自动关联。

登记和关联只改变实体指向，不改写玩家原文或逐字引用。输入“李磊”确认指向李雷后，记忆可以关联李雷的 ID，引用仍写“李磊”；别名也不等于 NPC 已获知某件事或旧记忆应被强化。

“明确指向”、候选集合与冲突检查需要可验证的判定协议，自动登记的提交 / 撤销 / 回退恢复需遵守引擎类型化变更和审计约束。当前冻结产品边界，尚未新增实体目录字段、别名 API 或运行时实现。

### 歧义询问与默认继续（已确认）

识别出实体指向或记忆分类歧义时，直接询问玩家确认，给出具体候选并允许说明“新对象”或“都不是”；普通记忆歧义也不静默替玩家作决定。同一歧义只询问一次，不重复弹出或反复调用模型；何时判定存在歧义、问题身份与有界去重规则需在精确协议中定型。

玩家未答复或跳过时，沿用既有默认行为继续游戏流程，不等待记忆确认、不持有产品请求 lease，也不因问题未答阻止无关操作。未答复不等于确认任一候选：相关关联、新增、强化、合并、纠正与别名登记不提交，来源和待确认状态保留。继续仍须遵守既有阶段机、可信场景与事实提交规则，不能为推进而凭空选择实体或绕过校验。

确认回答只解决问题所指的关联 / 分类，不能顺带证明事件发生、动作成功或角色已获知 / 相信。登记别名仍须满足对应类别 / 范围与来源检查。确认属于场外交互，不计作场内回合，也不自动成为 NPC 知识。

迟到回答提交前重新核验来源有效性、实体目录、候选版本与当前状态；回退、纠正或周目切换后的旧回答不能覆盖新状态。有界待确认队列的具体容量、审计保留期限、问题呈现与恢复接口仍待预算和存储协议确定，不能将未回答问题全部常驻内存。

### 待确认问题生命周期（已确认）

待确认问题持久保存，进程重启后可在待确认入口继续回答，不反复弹窗。相同歧义合并为同一问题，保留有效来源关联；合并身份规则需避免仅凭措辞相似把不同事件的问题合并。

已回答、已解决或来源失效的问题退出待办列表，保留必要审计记录。本周目内不因玩家几天未登录就丢弃仍有效的问题；跨周目问题不自动带入新周目。回答前继续重查来源 / 当前状态，问题持久化不赋予过期回答提交权限。

待办列表分页，内存缓存与总数量均有上限；达到上限时明确提示，不无限堆积或静默覆盖旧问题。数量、存储预算与审计保留期限待标定，达到容量不能悄悄删除有效问题；原始来源仍保留，游戏未答复时沿用默认继续规则。

### 忠实引用与因果有效性

凡声明为玩家原话的内容，必须指向 006 中玩家记录的 `seq`，并与该行原始 UTF-8 正文的合法字节区间逐字相同。不能先 trim、纠错、归一化或改标点再声称逐字引用；改写内容只能标作摘要。玩家输入 mode 必须保留，场外输入不能被转述为角色在场内说过的话。

来源核验还必须确认剧本 / session 身份、来源正文一致性及当前有效因果路径。单凭物理最大 `seq` 或文字相似不能证明来源有效。回退后失效来源不能参与注入、强化或新回写；生成期间发生回退的旧候选不能提交。段切沿用当前 session 的来源和因果路径校验，不引入跨段 session 历史链；cycle 的跨周目来源另按其独立协议核验。

已显示但未完成的旁白不能被记成已经成立的结算结果。字面引用只证明文字存在，不证明模型从中推导的关系、偏好或世界事实成立；角色认知可以存在误解，但必须与世界事实区分；误解不能伪造玩家逐字台词，也不能作为引擎事实提交。

## 衰减、容量与复活

会话条目有 `active | archived` 状态；容量满时归档，不删除。复活重置该条目的衰减时钟，但不能恢复已经失效的因果来源，也不能重复计入同一强化原因。

**M04 计时口径已确认：**

- 基础时钟以已完成的场内回合计数；失败、取消、重放和场外聊天不计入。
- 离线或关闭游戏期间不衰减；现实时间仅用于后台触发与冷却，不参与记忆强度衰减。
- 剧情内时间跳跃不自动折算成大量遗忘；如需时间跳跃带来记忆变化，由剧本明确规定。

半衰期、强化系数、容量、排序与平局处理仍待标定。计时原因需幂等，不按事件到达次数计数；因果回退后的计数恢复必须与有效路径一致，具体存储 / 重放规则在实现协议中补齐。接口先固定输入职责和状态语义，公式候选、标定方法与对照实验见[算法附录](memory-algorithms.md)，不照抄 Herta 的终值。标定按减少错记、关键内容保留、防重复刷强度、费用 / 延迟的已确认优先级推进，指数 / 分段 / 无衰减先做对照，不预设胜出公式。

### 归档复活与防滥用（已确认，严格门控）

新素材明确重提同一经历，且通过来源有效性、记忆主体、角色可见权限和语义核验，才可复活归档条目。明确重提只产生候选，不直接改变状态。出现同名实体、模糊文本相似或检索命中都不能单独触发复活；检索不能产生写入副作用。

复活重置衰减时钟，但不清零已确认强化上限、同经历重复限制及来源幂等记录；不能借归档 / 复活循环绕过防刷约束。已处理来源的重试 / 重放不能再次触发复活；明确重提仍受同经历重复限制，不能通过不同措辞和不同回合无限重置时钟。复活冷却约束已确认：冷却窗口内的普通重提不再次重置时钟；新事件独立判断，不能借复活旧条目绕过限制。复活本身不自动加分，强化需独立满足已确认规则；冷却状态同样不能因归档 / 复活或正文换版清零。

冷却窗口按已确认的场内回合逻辑时钟衡量，不通过离线等待或场外聊天消耗；具体长度、频率限制与识别参数待标定，不能将未填限制解释为无上限。

复活作为可审计操作提交，保留原条目身份与历史，不能伪装成新增条目来刷新限制。容量满仍按活动容量规则处理，不能绕过上限；来源失效不能复活，回退使复活依据失效时撤回其效果。提交前复查状态与版本，重复 / 并发候选不能分别完成同一次复活。

### 活动容量与兜底归档（已确认）

每周目 1,000 条活动记忆作为宽松实验配置，计入各记忆主体的实际活动条目，不是每主体分别获得 1,000 条。该值尚无长对局实测依据，不作为已验证生产默认；普通长度对局应很少触发容量驱逐，长对局用样本检验。

归档作为容量兜底：先排除来源失效、损坏或无权读取的条目，再对健康有效条目排序。当前任务所需线索、未兑现承诺和未解决的关键关系问题优先保留，关联须有来源或引擎规则支持；其余按标定后的显著性选择，平局采用固定规则保证重放一致。优先保留内容也超限时明确提示容量不足，不无限扩容或静默丢弃。排除无效条目不代表恢复其效力，归档不删除历史。

活动条目上限、单次上下文预算和磁盘历史保留分别约束不同资源。1,000 条不是一次注入模型的量，也不是正文旧版本 / 备份 / 待确认问题的共同删除阈值；注入仍按场景、可见权限、相关性与已有上下文硬限选择。

规划估算仅用于造样本：假设每回合经门控 / 去重留下 0.5–1 条独立信息，50 / 100 / 200 回合对应 25–50 / 50–100 / 100–200 条；多个主体的不同认知会增加实际条目。该假设未经验证，不能宣称真实对局通常产生这些数量。

归档后的正文与来源仍保留。归档容量、索引分页、单条正文和恢复扫描同样需要预算，不能把“归档不删”解释为全部历史常驻内存。

## 存储与失败边界

已确定载体为 SQLite manifest 与 `workspaces/<script-id>/memory/` 文件正文；覆写前保留 `backups/`。复用 [mythos-store 与存储基建](storage.md)，不引入 ORM；跨剧本不共享。cycle 使用独立表 / 目录和生命周期，不混入会话条目的 strength 归档流程。

manifest 需要关联条目身份、正文版本与校验信息、状态、来源、周目和计分原因，才能识别重复提交、过期候选与文件 / 索引不一致。此处是所需信息，尚非数据库 schema 或 Rust / TS API 定义。

### 因果版本机制与剧情回退（已确认）

采用基于因果来源的版本化存储，复用 006 / 012 的不可变记录、`historyFork` 与有效因果路径；增加记忆正文版本、SQLite 当前指向及可审计操作记录，不另造分支系统，不将玩家数据放进 Git 仓库。当前不支持自动合并不同剧情分支。

正文损坏恢复与剧情回退是不同操作：前者仅恢复记忆内容，世界进度不变；后者改变有效因果路径，需要重建派生记忆、强度、别名与待确认状态。不得以记忆版本回滚代替世界回退。

| 派生数据           | 剧情回退后处理                                                     |
| ------------------ | ------------------------------------------------------------------ |
| 新增 / 强化 / 纠正 | 仅保留有效来源支持的结果，撤回失效来源带来的加分及认知变化         |
| 别名               | 登记来源失效则不再参与自动关联；仍有其他有效登记依据时可保留       |
| 待确认问题         | 来源失效则标记失效，旧回答不得继续提交                             |
| 混合来源摘要       | 不能只删来源标记却保留失效内容；先停用该版本，恢复可验证的有效版本 |
| 原始历史 / 旧版本  | 保留供审计，不因回退删除历史；恢复不自动调用 LLM                   |

操作记录需要关联来源及分支身份，支持幂等重放和有效路径核验；具体记录载体、注册类型及 schema 仍待定型。不能因物理 seq 较大就认定来源仍有效，也不能用缓存的高强度保留已被撤回的经历。

### 正文组织（已确认）

记忆正文保存简短、独立可读的摘要，完整原文通过来源引用查阅，不复制整段历史充当摘要。来源、主体与可见范围的结构化信息仍须保留，简短不代表可省略人物指向、否定、认知冲突或必要限定；逐字引用继续接受原文区间核验。

同一事件补充细节不能使单条正文无限增长。长事件可按有意义的信息拆成相互关联的条目，关系与各自来源可核验；不能为绕过单条长度 / 总量 / 批次限制机械切碎内容。不能用截断改变事件含义或把未完成事件写成完成事实。

单条长度、关联条目数量与模型输入上限待样本标定；独立可读的摘要也不代表可以脱离来源、角色权限或因果路径直接使用。历史正文和版本保留仍遵守存储 / 恢复协议。

### 版本正文与提交指向（已确认）

先写新版本正文，再由 SQLite 事务提交当前版本指向；不直接覆盖正在使用的正文。旧版本保留，覆写其他派生页前仍需备份。具体版本路径、操作记录 schema 与保留预算待定型，不把文件原子写描述成跨文件 / SQLite 原子事务。

1. 程序核验候选，持久保存本次操作身份及恢复所需信息；不能只存在进程内存中。
2. 写入新版本正文，完成持久化并核对内容哈希，旧版本保持可用。
3. 再次核验当前版本和来源没有失效，在 SQLite 事务中更新版本指向、来源与幂等标记。
4. 确认提交成功后，才让新版本参与读取并通知界面。事务返回结果不确定时先核验提交标记，不能立即重做或宣称失败回滚。

| 恢复情况                 | 已确认处理                                                             |
| ------------------------ | ---------------------------------------------------------------------- |
| SQLite 尚未提交新指向    | 继续读旧版本；新文件不因存在就生效。首次新增没有旧版本时，该条尚不生效 |
| SQLite 已提交新指向      | 核验所指正文，恢复新版本；同一操作不重复强化 / 更新                    |
| 指向的文件缺失或哈希不符 | 停止使用该条记忆，报告并恢复，不能作为正常空内容继续使用               |

恢复使用已持久保存的结果，不自动重新调用 LLM 或重复收费。文件落盘而事务未提交产生的未引用版本需要有界清理 / 恢复判定；未完成操作记录、正文和备份不能因一次扫描失败被误删。损坏旧版本恢复边界见下节；具体恢复状态机、多个旧版本选择顺序和清理顺序尚待细化。

### 正文损坏与旧版本恢复（已确认）

当前正文缺失或哈希不符时先停用并隔离损坏版本，保留诊断信息，不立即删除。旧版本只有正文完整、哈希正确且来源仍有效时才可作为恢复候选；恢复不能重新启用已经失效的因果来源。

有可验证旧版本时可以自动恢复，并明确提示“已恢复到较早版本”；没有可用旧版本时停用该条并提示。不能把损坏内容当空内容，也不能让模型猜测补写或自动收费重新生成。多个可用旧版本的选择顺序及失败诊断格式仍待协议定型。

恢复通过新的可审计操作提交，保留恢复原因和版本关联，不静默改当前指向。旧版本内容不能覆盖并发发生的更新，提交前需重查当前版本与来源。其他健康记忆和正常剧情流程继续使用，恢复不撤销已提交世界事实，仍遵守既有持久化和阶段机约束。

### 旧版本与备份清理（已确认）

清理由引擎按依赖关系执行，不简单按文件时间保留最近 N 个。当前版本、仍被保留因果分支引用的版本、未完成操作所需版本，以及承担损坏恢复用途的有效旧版本不能清理。恢复版本保留范围和数量需在预算协议中定型，不能将“可恢复”作为名义而先删唯一有效恢复版本。

只有超过保留策略且确认没有依赖的旧正文版本和备份才可删除。删除前重新检查当前指向、分支引用、未完成操作和恢复状态；检查失败时跳过。清理与提交 / 恢复需协调，不能在检查后并发新增引用仍直接删除。

原始剧情记录与记忆归档不因活动容量满被顺带删除。旧版本数量、期限和磁盘上限通过实验确定；无法安全回收时提示占用，不强删。扫描与清理批次有界，进程中断后可重试核验，不把删除失败当作恢复信息已经消失。

模型拒绝或提交前失败不修改既有人设。提交结果不确定时先核验与恢复，不能让未经确认的新状态继续参与生成。失败需要可审计诊断；新增 system.code / 事件 / 错误码须按 006 / 通信契约登记，不把本文的概念直接作为当前可用事件。

## 遗忘回写

**M01 权限边界已确认：**

- 世界事实：NPC 是否死亡、任务是否完成、关系数值等，只能由引擎按规则提交，记忆强度不能改变事实。
- 角色记忆：角色如何理解玩家、如何记得某件事，可以压缩、淡忘、强化，甚至存在误解；原始记录仍保留。

回写目标分为关于玩家、世界 / 人设、NPC 三类派生认知桶；这里的世界 / 人设桶描述角色认知，不是修改权威世界设定或引擎状态的入口。NPC 桶懒建。回写保留专名和来源，不能在压缩中静默丢弃专名；覆写前备份，失败可恢复。cycle 不走此路径。

**M01 记忆内部冲突规则已确认：**

- 明确纠正：角色获知纠正信息后，更新当前认知，保留旧印象、来源与认知变化过程；不覆盖原始记录。
- 尚无定论：保留疑惑与相互矛盾的来源，不强行选择单一答案。
- 重复或更强烈：可以强化印象，不能仅凭更新或 strength 更高判定另一条记忆错误。

玩家给出新解释，不自动意味着 NPC 已经获知或相信；纠正只能在对应角色可见、有效来源支持的范围内处理。强度表示显著性，不是真实性或可信度。“较新 + 更高强度”不作为覆盖规则，来源有效性先于任何排序。角色认知变化仍不能修改引擎世界事实。具体来源可见性、纠正分类与幂等提交协议需在实施设计中明确，不能让模型自行给自己授予事实权限。

纠正不能抹掉 JSONL 历史，也不能绕过 006 / 012 已定稿的类型化世界变更和审计协议。模型记忆回写只能改派生认知页；真正的人设 / 世界事实纠正由引擎按规则提交，沿用可审计的类型化变更。

## 触发、让位与预算

闲置后台、幕切、会话结束的记忆工作均默认关闭。启用收费后台前需要明确授权；触发不代表可以占用所有闲置时间或无上限扫描历史。用户返回时在安全边界让位，不中断已经开始的持久化提交。

012 已提交 `roundEnded/completed` 后的一次只读钩子可作为素材入口；重放不能再次自动收费。该钩子当前只提供来源身份，不意味着每回合都必须调用模型。007 的触发阈值独立标定，不套用 006 recap 的已定稿数值。

实现前必须给正文、条目数量、输入素材、候选 JSON、单轮扫描、模型调用、队列与诊断明确硬上限。模型请求受 005 的预算约束；具体数值在评审和标定后冻结，不把未填参数当无限。

### 统一预算与有界批次（已确认）

共用一套以费用为控制单位的 [LLM 调用预算](llm.md#统一调用预算与任务优先级)，不额外设记忆专属额度；同时检查每周目与全应用自然月金额额度，默认金额由参考 Token 用量及模型价格计算；Token 仅保留底层计量 / 单次限制，计价细化由 027 承接；预留 / 结算以该文档为唯一规则来源：先预留、完整 usage 后结算、未知消耗不当零退款，预算与请求身份持久化，恢复不自动重发收费请求。先前“记忆额度耗尽而剧情照常生成”的独立额度方案撤回。主流程必需的请求若额度不足则暂停推进；可选后台工作不足时跳过，不抢主流程额度。共享供应商余额或总额度也可能使剧情请求失败，不能承诺无限继续。

来源检查、候选定位、衰减与幂等等本地计算继续执行。语义分类与值得记判断合并为一次有界批次请求，避免每道门各调用一次；费用处理默认关闭，授权后仍有单批输入 / 输出硬限和统一调用限制。批次合并的质量影响、批次大小 / 触发频率与额度数值待对照标定，不将未经实测的合并策略宣称更准确。

未处理素材保留原始来源，不能当作已经形成新记忆；玩家未答确认问题不会触发反复模型调用。恢复仍使用已保存结果，不自动收费重生成。哪些记忆 / 上下文工作是推进前置条件必须由记录引擎明确，不因预算统一把所有后台工作变成主流程必需步骤。

### 批次触发（已确认）

启用已授权记忆处理后，先收集已提交且通过资格检查的素材，不对每句话立即调用模型。素材数量或输入 token 达到门槛时合批，节点切换可作为额外处理时机；具体门槛、单批大小和延迟目标待实验确定，不套用 006 recap 的固定门槛。

当前推进确实依赖尚未处理信息时，由引擎明确列出必要请求，不机械等待凑满批次，也不因关键字命中就擅自升级为必要处理。没有新素材不调用；记录重放、未答复确认问题及重复检测不触发额外请求。已覆盖来源和处理操作身份需用于去重，不能在取消 / 恢复后重新付费处理已持久完成的同一结果。

可选后台仍默认关闭，启用后让位于主流程；批次请求与必要请求共同遵守统一预算、005 请求约束和 020 单在飞门禁，不绕过纯函数 project 的职责。场外偏好素材按原 mode 处理，收集素材不等于增加场内回合时钟。

## 轮回缓存

轮回缓存默认关闭，作用域是剧本。内容为结构化刻痕与有硬上限的短摘要，带周目身份和代数；由规则表或可信 `cycle:true` 标签授权。模型不能自行选定持久身份、授予跨周目权限或写任意长文。

压缩顺序为同 id 去重、按权重与代数进行独立归档、可选轮回提要。提要默认关闭；其调用预算与来源校验仍受共同规则约束。“权重 × 代数”的具体表达式待研，不能先实现为越旧越重要或据此删除正文。

**M03 已确认：跨周目刻痕由剧本显式授权，默认表现为若有若无的感受。**

- 玩家本人对上一周目的了解，不自动成为当前角色的知识。
- 角色 / NPC 仅继承规则允许的刻痕，每条明确可见对象；旁白可用的信息不自动成为所有角色的知识。
- 默认表达为似曾相识、莫名亲近 / 戒备、模糊梦境或片段，不默认恢复完整前世记忆。确切人物、地点、事件细节须有对应剧本授权，不能把模糊刻痕展开成未经授权的剧情答案。
- cycle 不隐式继承上一世的死亡、任务结果、关系数值或其他 SQL 世界状态；确需延续的状态由引擎另按规则提交。主观亲近感不等于关系数值已经变化。

例如，上一周目玩家救过某 NPC，规则可以允许他产生说不清的信任感；是否记得救援细节由剧本决定。刻痕的柔和表现不改变其结构化来源、可见权限和审计要求，也不意味着每次出场都需要提示前世。

新周目注入仍有 Top-K 与字数硬上限，防止刻痕无界累积。

注入若进入新 session 静态段，必须在创建 header 前完成冻结；内容变化会改变前缀字节与 hash，不能承诺供应商缓存继续命中。现有 session 内不热替换 `header.staticPrefix`。动态注入位置、预算及检索时机须经后续投影设计评审，007 v1 不提供该能力。

## 后续可选记忆注入（选择原则已确认）

本节约束未来可选注入，不改变 007 v1 不接 006 检索热路径的边界，不代表现有 project 已实现记忆检索。

- 先过滤因果来源失效、正文损坏及当前角色无权获知的内容。
- 优先选择与当前场景、实体、目标和玩家输入相关的记忆，不只按 strength 排序；同名 / 字面相似不能自动证明实体或事件关联。
- 纠正后的认知及未决冲突保留必要限定，不能只注入旧印象而省略已获知纠正或疑惑，造成误导。
- 条目数与总 token 双重限额，不能将全部活动记忆注入上下文；注入须受 006 总上下文硬限约束，不能挤掉其必需字段。
- 摘要不足以支撑关键判断时，在预算内查阅原始来源；仍不能确认则询问玩家，未答复行为沿用已确认的默认继续规则，不能据此猜定事实。

具体候选检索、排序权重、原文读取边界及选择上限待实验 / 协议定型；不引入向量作为默认实现，也不为一次检索无界扫描全部历史。主观记忆、玩家偏好及轮回刻痕仍遵守各自可见范围和已授权使用规则。

## 节点节奏与收束

章 / 幕 / 场是数据轴，不写死每章回合数。引擎维护 SQL 隐性计量，玩家原文中不加入计量值；模型不能自由修改计量或创建场景身份。晋级仍需遵守 012 的可信场景目录、条件校验与先提交后发布规则。

节点切换是段收束的主要触发点，可选压缩不能被默认开启。日常超预算首先尝试 006 已允许的确定性预算处理；必需内容仍放不下时沿用预算拒绝 / 压缩计划协议，不暗加付费请求或裁掉完整当前玩家输入。

安全阀需要防止永不晋级，但不能跳过可信场景条件、随机代替失败的场景提议或伪造结算。**M05 产品规则已确认：**

- 章 / 幕 / 场按剧本条件推进，例如获得线索、完成目标、作出关键选择，不固定每章回合数。
- 引擎维护隐藏进度，模型负责叙述和提议，不能自行修改计量或绕过晋级条件。
- 长时间无进展时，优先使用剧本预设的提示、替代线索或合法出口；触发安全阀不代表自动晋级。
- 没有合法出口时提示当前受阻，让玩家选择继续探索或结束；不凭空生成出口。
- 可选记忆压缩失败不阻止已经满足条件的场景推进；必要持久化失败仍按既有恢复协议处理，不能跳过提交。

具体停滞阈值、提示频率、剧本条件结构与受阻选择的交互仍需细化。**M02 已确认：段切保持同一 session，通过动态 `WorldView` 更新场景状态，可选压缩历史，`header.staticPrefix` 保持不变。** 段切不重冻前缀、不创建新 session、不改变现有恢复与因果回退协议。将来确需改变静态规则或前缀时，另行设计新 session 衔接，不属于本次节点收束范围。
