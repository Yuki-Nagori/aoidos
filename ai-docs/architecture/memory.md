## 真相、状态与投影

JSONL 保存可审计的记录与因果事实，SQLite 保存可纠正、可重建的当前状态；LLM 上下文是受预算约束的短寿命投影。具体提交、重放与回退协议沿用[记录引擎](record-engine.md)和[阶段机](turn-state-machine.md)，供应商 chat 历史不能替代本地持久化。

遗忘是产品行为，不是删除历史。归档、压缩、容量驱逐不删除原始玩家台词和已提交事实，也不使模型摘要自动获得修改世界的权限。世界事实与角色记忆的权限边界见“遗忘回写”；认知冲突按“明确纠正更新、未决保留疑惑”处理，具体判定与提交协议仍需细化。

007 v1 不接入 006 投影热路径，不引入向量检索。日常生成仍使用冻结前缀、recap、最近记录窗口和有界世界投影。记忆的可选注入是后续实现范围，不能据此修改现有纯函数 `project` 的职责。

## 角色获知与认知

### 角色获知范围（权限方向已确认）

引擎维护有来源的角色获知记录，模型只能提出候选，不能自行给角色授予知识。获知记录须关联具体角色、原始来源及有效因果路径；获知方式与角色对内容的理解分开，不把“听见某人说过”直接升级为世界事实或角色确信。

同处一个场景不自动代表听见或看到所有事件；旁白可用的信息不自动成为 NPC 的知识。传闻保留“听说”的来源与不确定性，不能经摘要、强化或复活变成无条件确信。玩家知道、场外确认及实体别名也不能替代角色实际获知的依据。

候选仍由程序核验来源与权限后提交；无法确定某角色是否获知时不自动赋予该知识。获知方式的产品分类已确认，见下表；证据字段、权限判定与纠正状态转换见工程协议 v1，不代表获知协议或运行时已实现。

| 获知方式   | 保留的来源与认知边界                                                       |
| ---------- | -------------------------------------------------------------------------- |
| 亲眼见到   | 保存角色实际观察的来源与范围；观察不自动证明未观察到的原因或完整世界事实   |
| 直接被告知 | 保存告知者与原始陈述；知道对方这样说，不自动等于相信陈述成立               |
| 听到传闻   | 保存可核验的传闻来源与不确定性；不虚构未记录的传播链，也不升级为亲历或确信 |

“是否获知”与“是否相信”分别判断。例如 NPC 听见玩家说“国王死了”，先记为“玩家如此声称”，不能据此提交国王死亡的世界事实或认定 NPC 已确信。模型可提取获知候选，来源与权限仍由引擎核验。

### 角色推断（已确认）

角色自行推断可以保存为有来源的主观记忆，保留“推测”标记及其依据。例如看到血迹可以怀疑有人受伤，不能记成“亲眼见到某人受伤”，也不能据此修改世界事实。推断不是新的亲历证据，不因重复、强化、压缩或复活升级为已确认事实。推断标记及其依据单独保存，可与观察、告知或传闻等获知方式并存，不作为互斥的第四种获知方式。

获得纠正后，按既有认知冲突规则更新当前认知，保留原推测、来源及变化过程；听到相反说法不自动等于已接受纠正。推断候选继续经过来源、角色权限与受控提交核验，不借主观记忆绕过门控。

### 获知与认知的数据结构（结构方向已确认）

来源、角色主体、获知方式与认知状态分别保存，摘要只表达内容，不承担权限判定。获知方式说明内容如何进入角色的认知范围，认知状态说明角色如何理解或相信该内容；两者不能合成一个强弱分数。

| 信息     | 职责                                                         |
| -------- | ------------------------------------------------------------ |
| 来源     | 关联可核验的原始记录与有效因果路径，保留陈述、观察或推断依据 |
| 角色主体 | 标明这是谁的记忆或认知，不由摘要中的人名推定归属             |
| 获知方式 | 区分观察、告知、传闻等来源方式，保留相应范围与限制           |
| 认知状态 | 表达角色的理解、相信或疑惑，与世界事实及记忆强度分开         |
| 摘要     | 表达内容与必要限定，不能替代上述结构化信息或授予权限         |

同一条认知可以关联多个来源，每个来源分别保存获知方式、范围和因果引用，保留后续变化过程；不能只用最新获知方式覆盖旧来源。例如先听到传闻、后来亲眼观察，两种来源均保留各自限定，观察不追溯性地把此前传闻变成亲历。来源失效与混合来源正文继续遵守既有因果回退规则。

因此“听说但怀疑”和“亲眼看到却误解”可以分别表达，不根据摘要里是否出现“听说”“相信”等关键词决定权限。字段、枚举与版本映射见工程协议 v1；尚未创建 Rust / TS 类型或数据库字段。

### 默认认知状态（已确认）

角色获知一条消息但没有表达态度时，默认记为“未表态”，不自动算相信或怀疑。“未表态”表示尚无可核验的态度依据，不等于角色不知道该消息，也不等于已经否定。

态度变化依据角色在有效记录中表达的态度，或引擎按明确规则确认的变化；模型只提候选，不能由后台模型根据角色设定和上下文自行推定未表达的态度并提交。后续有上述有效来源支持，再更新角色态度；告知者可信、记忆强度高或反复听到，都不能单独把“未表态”自动转换为确信。态度候选仍由引擎核验来源、主体与权限后受控提交，保留变化过程。首版认知态度采用下表四种，不设置数值可信度；字段与转换条件见工程协议 v1。

| 认知态度 | 含义                                   |
| -------- | -------------------------------------- |
| 未表态   | 已获知内容，但没有可核验的态度依据     |
| 相信     | 角色相信该内容，不代表世界事实成立     |
| 存疑     | 角色对内容保持疑惑                     |
| 否定     | 角色否定该内容，不代表引擎已判定其为假 |

“推测”“传闻”的限定与认知态度分别保存，不因变为“相信”而消失。模型置信百分比不作为态度自动转换的依据；记忆强度仍只表达显著性，不兼任可信度。

## 遗忘回写

**M01 权限边界已确认：**

- 世界事实：NPC 是否死亡、任务是否完成、关系数值等，只能由引擎按规则提交，记忆强度不能改变事实。
- 角色记忆：角色如何理解玩家、如何记得某件事，可以压缩、淡忘、强化，甚至存在误解；原始记录仍保留。

回写目标分为关于玩家、世界 / 人设、NPC 三类派生认知桶；这里的世界 / 人设桶描述角色认知，不是修改权威世界设定或引擎状态的入口。NPC 桶懒建。回写保留专名和来源，不能在压缩中静默丢弃专名；覆写前备份，失败可恢复。cycle 不走此路径。

**M01 记忆内部冲突规则已确认：**

- 明确纠正：角色获知纠正信息后，更新当前认知，保留旧印象、来源与认知变化过程；不覆盖原始记录。
- 尚无定论：保留疑惑与相互矛盾的来源，不强行选择单一答案。
- 重复或更强烈：可以强化印象，不能仅凭更新或 strength 更高判定另一条记忆错误。

玩家给出新解释，不自动意味着 NPC 已经获知或相信；纠正只能在对应角色可见、有效来源支持的范围内处理。强度表示显著性，不是真实性或可信度。“较新 + 更高强度”不作为覆盖规则，来源有效性先于任何排序。角色认知变化仍不能修改引擎世界事实。具体来源可见性、纠正分类与幂等提交协议需在实施设计中明确，不能让模型自行给自己授予事实权限。

纠正不能抹掉 JSONL 历史，也不能绕过 006 / 012 已定稿的类型化世界变更和审计协议。模型记忆回写只能改派生认知页；真正的人设 / 世界事实纠正由引擎按规则提交，沿用可审计的类型化变更。

## 会话记忆门控

```text
已提交、当前因果路径有效的素材
  → 回声候选（纯函数，只定位旧条，不提交强化）
  → 已记过粗筛（复述进入强化候选，不新增重复条）
  → 语义分类与值得记（合批、有界 LLM JSON，默认拒绝）
  → 忠实门（来源与玩家逐字引用核验）
  → 受控保存
```

同一条素材在强化与复述分支之间不能重复计分；失败重试和记录重放不能重复强化或创建条目。候选定位、计分与幂等身份见工程协议 v1，时间窗 / 增益的开发值见算法文档；生产数值仍需标定。

“值得记”的范围已确认；v1 使用分类与维度，不要求模型输出数值评分，语义接纳效果与 prompt 仍待标定：

| 维度     | 值得记的范围               | 限制                                                   |
| -------- | -------------------------- | ------------------------------------------------------ |
| 剧情     | 重要经历、选择、承诺与后果 | 保留来源与事实 / 陈述 / 认知的区别，不把声明当成功结果 |
| 关系     | 信任、戒备、冲突等认知变化 | 限定对应角色实际获知的内容，不自动改变关系数值         |
| 玩家偏好 | 明确表达的体验偏好         | 一次行为不直接推断长期喜好，不自动赋予角色知识         |
| 伏笔     | 有来源支持的未解决线索     | 模型不能自行把普通细节升级为伏笔或泄露未经授权的信息   |

普通寒暄、重复措辞、没有新信息的提及不新增记忆；重提既有经历是否强化仍按回声规则判断。重要但有歧义的内容先询问确认，评分再高也不能绕过来源、权限与忠实门。

非 JSON、缺字段、越界值、护栏失败和无法核验的来源均拒绝候选，不默认接纳，不通过无限修复 JSON 请求补救。语义拒绝不是 `llm.quota`；余额 / 配额不足按 [005](llm.md) 的错误分类处理。

所有模型请求沿用 005 的冻结配置、护栏、超时和有限重试策略，并经 020 的全局单在飞协调。背景记忆工作不能绕过产品请求占用，也不能自动换供应商或开启额外收费链路。

### 素材资格（已确认）

素材进入管线前，先核验提交状态、来源身份与当前有效因果路径；通过资格检查不代表值得记，也不代表角色已经知道。资格检查适用于新增、强化和回写，不能仅在保存新条目时执行。

| 素材                           | 资格与使用边界                                                       |
| ------------------------------ | -------------------------------------------------------------------- |
| 当前有效因果路径上的已提交记录 | 可作为来源，仍需通过后续门控与可见性检查                             |
| 玩家原文                       | 保留场内 / 场外 mode；引用逐字一致，陈述不自动证明动作成功或事实成立 |
| 已完成旁白                     | 可提取角色经历；只有引擎确认的结果才属于世界事实                     |
| 已提交引擎结算                 | 可作为事实来源，角色是否获知须另查可见范围                           |
| 未完成、失败或取消的旁白       | 不提取新记忆；已保存正文仍保留，不作为强化或回写依据                 |
| 回退后失效的记录               | 不参与新增、强化或回写                                               |
| recap、记忆摘要、模型候选      | 仅辅助定位原始来源，不能单独证明事件发生，不以摘要自我引用形成证据链 |

玩家输入已经提交但后续生成失败时，原文仍可作为“玩家说过什么”的来源；不能据此认定声明的动作成功。旁白资格按其自身完成状态核验，回合失败不把已经确认的结算抹掉，也不把保留下来的 partial 升格为完成旁白。

场外输入可以用于玩家偏好，例如不喜欢恐怖描写；不能转成角色台词，也不能自动赋予 NPC 对该输入的知识。玩家偏好与角色认知在归属和消费权限上分开，不能因共用记忆载体混为一类。

### 结构化判定与程序消费（已确认）

LLM 返回有界结构化候选，分类为复述、补充、新事件、纠正、不值得记或不确定。候选包含涉及的稳定实体 ID、关联旧记忆、程序提供的来源片段引用 ID、拟保存摘要、所属维度和简短理由；字段是否必需随分类约束，例如新事件无需凭空引用旧记忆，不值得记无需拟写正文。具体字段与预算见工程协议 v1 和算法文档；它们是推荐设计，不声明已有 Rust / TS 实现类型。

程序核验来源有效性、权限、实体 / 旧记忆身份、逐字引用和重复处理情况后，才可提交对应修改。字符匹配只用于定位候选；回声和粗筛纯函数产生判断输入或强化候选，不自行将相似文本认定为语义一致后落盘加分。语义判定也不因模型给出高置信度而免除核验。

程序在请求前提供有界来源片段及引用 ID，维护引用 ID 到不可变原始记录和合法 UTF-8 字节区间的映射。模型选择引用 ID，不自行计算字符或字节偏移；逐字引文由程序从对应原文提取，模型生成的是摘要，不将模型拟写文本作为逐字引文。引用生命周期与切分原则见下节；字段见工程协议 v1，大小上限见算法文档。

程序核验引用属于本次提供的来源集合，且映射的原始记录、区间与因果来源仍有效。未知引用或映射区间不正确时拒绝该候选，不自动搜索重定位、修正偏移或改引另一段原文。此规则校验引用定位与忠实性，语义关联仍按已确认的实体 / 重复分类规则处理。

候选出现未知字段时拒绝对应候选，不忽略字段后继续消费；顶层协议版本不支持时拒绝整个输出，不猜测其含义。字段白名单、协议版本及分类对应的必填约束见工程协议 v1，结构校验失败不转成玩家歧义确认或暗加修复请求。

模型不能返回可执行 SQL、文件路径 / 覆写命令或自行登记新实体；模型提出的关联不能直接转成别名登记，仍需满足明确指向及冲突检查规则。简短理由只是判定依据摘要，不要求或保存模型内部推理过程。

有效且可核验的“不确定”分类按歧义询问规则处理。超时、非 JSON、缺字段、字段非法、护栏失败或无法核验的来源属于处理失败，拒绝本次候选，不把这些故障伪装成语义问题交给玩家回答；失败仍遵守 005 的错误分类和有限重试，不暗加修复请求。

### 来源片段与批次引用（已确认）

引用 ID 属于具体批次，批次身份及引用映射持久保存，供已保存结果的校验与恢复使用。引用须结合所属批次解析，不仅凭同名 ID 查找当前素材；旧响应不能引用新批次中同名 ID 对应的内容。恢复继续核验原始记录与当前有效因果路径，不因映射已经持久保存而免除来源检查，也不重新调用 LLM。

提供素材时优先保留完整记录行；超长时拆成有界片段，并提供理解所需的邻接上下文，保留各片段到原始记录区间的映射。片段与上下文均计入请求输入预算，不以补上下文为由无限扩大输入；必须引用的上下文同样通过来源引用核验，不能成为无来源的证据。

切分不能让断开的句子被当成完整含义，尤其需保留否定、转述、指代与纠正的必要限定。切分 / continuation 标记与工程上限见工程协议 v1 和算法文档，语义保留仍待样本验证；不宣称任意切片都能保留完整语义。

### 忠实引用与因果有效性

凡声明为玩家原话的内容，必须指向 006 中玩家记录的 `seq`，并与该行原始 UTF-8 正文的合法字节区间逐字相同。逐字引文由程序按已校验的来源片段映射提取，不由模型重新拟写。不能先 trim、纠错、归一化或改标点再声称逐字引用；改写内容只能标作摘要。玩家输入 mode 必须保留，场外输入不能被转述为角色在场内说过的话。

来源核验还必须确认剧本 / session 身份、来源正文一致性及当前有效因果路径。单凭物理最大 `seq` 或文字相似不能证明来源有效。回退后失效来源不能参与注入、强化或新回写；生成期间发生回退的旧候选不能提交。段切沿用当前 session 的来源和因果路径校验，不引入跨段 session 历史链；cycle 的跨周目来源另按其独立协议核验。

已显示但未完成的旁白不能被记成已经成立的结算结果。字面引用只证明文字存在，不证明模型从中推导的关系、偏好或世界事实成立；角色认知可以存在误解，但必须与世界事实区分；误解不能伪造玩家逐字台词，也不能作为引擎事实提交。

### 回声强化约束（已确认）

- 仅强化同一记忆主体有权获知、来源仍有效的旧条目；素材先通过资格检查。
- 相同名字不构成强化依据。“我相信阿明”与“我不再相信阿明”不能因文字相似强化原有信任。
- 明确重提同一经历或印象，才可成为强化候选；模糊相似只用于定位，不直接加分。
- 纠正、否定、关系变化进入后续判断，不作为旧印象重复；强度仍不代表事实真实或角色已经相信。
- 同一来源对同一条记忆最多强化一次；重试、重放及后续重复筛选不能再次计分。

强化形状已确认：收益递减、单条封顶；同一经历跨不同回合的复述仍受限，不能仅通过不同来源反复刷强度。它与“同一来源只计一次”的幂等约束分别执行。再次发生的重要新经历独立判断，不能作为旧事件复述压掉。强化始终不改变真实性、角色权限或因果有效性。

单次增益、递减速度、封顶值、同经历重复强化窗口与次数待标定，当前不冻结数值或最终计算公式。

匹配阈值、加分幅度以及如何精确识别明确回指仍待算法设计 / 标定。纯函数只能处理已核验的输入，不能宣称字面相似足以判定语义一致；没有可靠依据时不自动强化。

### 重复分类（已确认）

| 分类                         | 处理                                                   |
| ---------------------------- | ------------------------------------------------------ |
| 同主体、同经历、同含义的复述 | 复用旧条目，可按强化规则处理，不新增或重复计分         |
| 同一人物的新事件             | 作为新候选，不因人物相同或措辞相似合并                 |
| 同事件的细节补充             | 作为旧条目更新候选，保留新增来源，不因增加细节重复加分 |
| 纠正或推翻旧理解             | 进入认知纠正流程，保留旧印象与变化过程                 |
| 无法确定是否重复             | 继续后续判断，不自动合并、强化或保存                   |

粗筛纯函数只定位候选；文字相似不能独自证明事件相同，匹配不到也不能证明是新事件。语义分类由 LLM 提供结构化候选并由程序核验；判定协议与批次开发参数见工程协议 v1 和算法文档，实测效果仍待验证；歧义询问与未答复行为按下节已确认规则执行，不把产品分类当作字符匹配已解决语义判断的证据。

## 实体关联与歧义确认

### 实体名称与自动别名（已确认）

规则适用于人物、地点、组织、物品与剧本术语。关联使用引擎登记的稳定实体 ID，正式名称和别名用于定位候选。AI 生成名称时需对照对应类别、范围内的目录与已登记别名检查冲突；重名、同音或过于近似时要求换名，不能仅靠 prompt 禁止就声称已经保证无冲突。近似检查用于发现歧义，不是合并不同实体的依据。近似候选与阈值见算法文档；冲突生成结果拒绝登记，等待下一次授权生成或用户改名，不自动增加修复调用，效果仍待样本验证。

名称与别名校验按类别和范围执行：地名结合所属地区，例如不同城镇的“东门”不能全局合并；人物也不能仅凭当前场景缺少另一人就认定指向唯一。跨类别同名不自动共享别名或实体 ID，目录缺项不代表不存在歧义。

术语指向必须保留机制含义。“灵力”和“魔力”可能是不同机制，意思相近不构成别名依据；缩写或错字仍需明确指向。普通描述如“那座城”“那个法术”仅解析本次对象，不直接登记为永久别名。

采用“明确指向后的自动别名学习”：玩家在明确指向李雷的对话中输入“李磊”，且上下文没有其他候选时，可以将“李磊”自动登记为李雷的别名。多个候选、可能介绍新人物、别名在对应类别 / 范围内已被其他实体占用时，不自动登记；同音 / 字形相似或模型单次判断都不足以单独触发登记。

别名作用域限于当前周目，保留登记来源，支持纠正与撤销；不因轮回刻痕自动跨周目继承。纠正别名不能无审计地把既有记忆迁移到另一实体，受影响的关联需要重新核验。回退使登记来源失效时，派生别名也需按有效路径重建 / 排除，不能把无效来源留下的别名继续用于自动关联。

登记和关联只改变实体指向，不改写玩家原文或逐字引用。输入“李磊”确认指向李雷后，记忆可以关联李雷的 ID，引用仍写“李磊”；别名也不等于 NPC 已获知某件事或旧记忆应被强化。

“明确指向”、候选集合与冲突检查需要可验证的判定协议，自动登记的提交 / 撤销 / 回退恢复需遵守引擎类型化变更和审计约束。当前冻结产品边界，尚未新增实体目录字段、别名 API 或运行时实现。

### 歧义询问与默认继续（已确认）

识别出实体指向或记忆分类歧义时，直接询问玩家确认，给出具体候选并允许说明“新对象”或“都不是”；普通记忆歧义也不静默替玩家作决定。同一歧义只询问一次，不重复弹出或反复调用模型；歧义判定、questionKey / revision 与有界去重规则见工程协议 v1，识别效果由 033 标定。

玩家未答复或跳过时，沿用既有默认行为继续游戏流程，不等待记忆确认、不持有产品请求 lease，也不因问题未答阻止无关操作。未答复不等于确认任一候选：相关关联、新增、强化、合并、纠正与别名登记不提交，来源和待确认状态保留。继续仍须遵守既有阶段机、可信场景与事实提交规则，不能为推进而凭空选择实体或绕过校验。

确认回答只解决问题所指的关联 / 分类，不能顺带证明事件发生、动作成功或角色已获知 / 相信。登记别名仍须满足对应类别 / 范围与来源检查。确认属于场外交互，不计作场内回合，也不自动成为 NPC 知识。

迟到回答提交前重新核验来源有效性、实体目录、候选版本与当前状态；回退、纠正或周目切换后的旧回答不能覆盖新状态。有界待确认容量、问题呈现与恢复契约见工程协议 v1 和算法文档；审计随原始来源 / 保留分支保留，不自动到期删除，不能将未回答问题全部常驻内存。

### 待确认问题生命周期（已确认）

待确认问题持久保存，进程重启后可在待确认入口继续回答，不反复弹窗。相同歧义合并为同一问题，保留有效来源关联；合并身份规则需避免仅凭措辞相似把不同事件的问题合并。

已回答、已解决或来源失效的问题退出待办列表，保留必要审计记录。本周目内不因玩家几天未登录就丢弃仍有效的问题；跨周目问题不自动带入新周目。回答前继续重查来源 / 当前状态，问题持久化不赋予过期回答提交权限。

待办列表分页，内存缓存与总数量均有上限；达到上限时明确提示，不无限堆积或静默覆盖旧问题。容量与资源预算见算法文档，审计依赖保留策略见工程协议 v1，达到容量不能悄悄删除有效问题；原始来源仍保留，游戏未答复时沿用默认继续规则。

## 衰减、容量与复活

会话条目有 `active | archived` 状态；容量满时归档，不删除。复活重置该条目的衰减时钟，但不能恢复已经失效的因果来源，也不能重复计入同一强化原因。

**M04 计时口径已确认：**

- 基础时钟以已完成的场内回合计数；失败、取消、重放和场外聊天不计入。
- 离线或关闭游戏期间不衰减；现实时间仅用于后台触发与冷却，不参与记忆强度衰减。
- 剧情内时间跳跃不自动折算成大量遗忘；如需时间跳跃带来记忆变化，由剧本明确规定。

半衰期、强化系数、容量、排序与平局处理仍待标定。计时原因需幂等，不按事件到达次数计数；因果回退后的计数恢复必须与有效路径一致，存储 / 重放规则见工程协议 v1。接口先固定输入职责和状态语义，公式候选、标定方法与对照实验见[算法附录](memory-algorithms.md)，不照抄 Herta 的终值。标定按减少错记、关键内容保留、防重复刷强度、费用 / 延迟的已确认优先级推进，指数 / 分段 / 无衰减先做对照，不预设胜出公式。

### 归档复活与防滥用（已确认，严格门控）

新素材明确重提同一经历，且通过来源有效性、记忆主体、角色可见权限和语义核验，才可复活归档条目。明确重提只产生候选，不直接改变状态。出现同名实体、模糊文本相似或检索命中都不能单独触发复活；检索不能产生写入副作用。

复活重置衰减时钟，但不清零已确认强化上限、同经历重复限制及来源幂等记录；不能借归档 / 复活循环绕过防刷约束。已处理来源的重试 / 重放不能再次触发复活；明确重提仍受同经历重复限制，不能通过不同措辞和不同回合无限重置时钟。复活冷却约束已确认：冷却窗口内的普通重提不再次重置时钟；新事件独立判断，不能借复活旧条目绕过限制。复活本身不自动加分，强化需独立满足已确认规则；冷却状态同样不能因归档 / 复活或正文换版清零。

冷却窗口按已确认的场内回合逻辑时钟衡量，不通过离线等待或场外聊天消耗；具体长度、频率限制与识别参数待标定，不能将未填限制解释为无上限。

复活作为可审计操作提交，保留原条目身份与历史，不能伪装成新增条目来刷新限制。容量满仍按活动容量规则处理，不能绕过上限；来源失效不能复活，回退使复活依据失效时撤回其效果。提交前复查状态与版本，重复 / 并发候选不能分别完成同一次复活。

### 活动容量与兜底归档（已确认）

每周目 1,000 条活动记忆作为宽松实验配置，计入各记忆主体的实际活动条目，不是每主体分别获得 1,000 条。该值尚无长对局实测依据，不作为已验证生产默认；普通长度对局应很少触发容量驱逐，长对局用样本检验。

归档作为容量兜底：先排除来源失效、损坏或无权读取的条目，再对健康有效条目排序。当前任务所需线索、未兑现承诺和未解决的关键关系问题优先保留，关联须有来源或引擎规则支持；其余按标定后的显著性选择，平局采用固定规则保证重放一致。优先保留内容也超限时明确提示容量不足，不无限扩容或静默丢弃。排除无效条目不代表恢复其效力，归档不删除历史。

活动条目上限、单次上下文预算和磁盘历史保留分别约束不同资源。1,000 条不是一次注入模型的量，也不是正文旧版本 / 备份 / 待确认问题的共同删除阈值；注入仍按场景、可见权限、相关性与已有上下文硬限选择。

规划估算仅用于造样本：假设每回合经门控 / 去重留下 0.5–1 条独立信息，50 / 100 / 200 回合对应 25–50 / 50–100 / 100–200 条；多个主体的不同认知会增加实际条目。该假设未经验证，不能宣称真实对局通常产生这些数量。

归档后的正文与来源仍保留。归档容量、索引分页、单条正文和恢复扫描同样需要预算，不能把“归档不删”解释为全部历史常驻内存。

## 参数配置与策略版本

### 策略版本与参数生效（已确认）

每周目固定记忆算法策略版本；新参数用于新周目，不静默重算当前周目的强度、衰减或冷却。周目恢复、因果回退与操作重放沿用所属周目的策略，不能因应用默认参数更新而换用新规则。策略身份及所用参数须可恢复、可核验；配置快照、版本保存与兼容协议见工程协议 v1。

首版记忆功能就在高级设置开放强化增益、半衰期等底层算法参数，用户修改后的配置用于新周目，当前周目仍使用原策略版本。设置需说明用途与生效范围，并校验参数合法性；可编辑字段、合法约束和开发初值见算法文档，生产默认仍待标定，开放设置不代表任意值均可提交。高级设置的校验、持久化、IPC 与界面接入由 [031](../task/031-memory-settings-queries-impl.md) 承接，[025](../task/025-ui-shell-impl.md) 当前的记忆系统非目标边界保持。策略版本固定不代表已经选定公式或数值，也不改变用户可手动调整周目 / 月度费用额度的已确认规则；费用预算继续由 027 负责。

### 参数配置作用域与保存（已确认）

应用提供记忆算法默认配置，剧本可覆盖；新周目解析最终生效配置并冻结，保留所用配置版本以便恢复与审计。剧本按字段覆盖，显式覆盖项优先于应用默认，未覆盖项继承应用默认；新周目冻结解析后的完整配置，不在运行期重新读取默认来补字段。应用默认后续变化只影响新周目的继承项，已有周目策略不变。解析后仍须整组校验；配置来源映射及持久化契约见工程协议 v1。

剧本设置中的“恢复默认”清除剧本覆盖，重新继承应用默认，不写入一套出厂值作为剧本覆盖。该操作先作用于编辑草稿，仍须点击保存并通过整组校验后生效；取消编辑或保存失败不清除已经确认的覆盖，已有周目的冻结配置保持不变。

用户编辑后点击保存，程序对整组配置进行校验，成功持久保存后生成已确认配置版本；不逐字段自动保存，不把尚未保存的草稿当成生效配置。非法配置不提交，保存失败保留上次已确认版本并报告失败。新周目使用最终已确认且合法的配置，当前周目继续使用原策略；保存 / 新周目冻结的一致性协议见工程协议 v1。

## 存储与失败边界

manifest 需要关联条目身份、正文版本与校验信息、状态、来源、周目和计分原因，才能识别重复提交、过期候选与文件 / 索引不一致。此处是所需信息，尚非数据库 schema 或 Rust / TS API 定义。

### 因果版本机制与剧情回退（已确认）

采用基于因果来源的版本化存储，复用 006 / 012 的不可变记录、`historyFork` 与有效因果路径；增加记忆正文版本、SQLite 当前指向及可审计操作记录，不另造分支系统，不将玩家数据放进 Git 仓库。当前不支持自动合并不同剧情分支。

正文损坏恢复与剧情回退是不同操作：前者仅恢复记忆内容，世界进度不变；后者改变有效因果路径，需要重建派生记忆、强度、别名与待确认状态。不得以记忆版本回滚代替世界回退。

| 派生数据           | 剧情回退后处理                                                     |
| ------------------ | ------------------------------------------------------------------ |
| 新增 / 强化 / 纠正 | 仅保留有效来源支持的结果，撤回失效来源带来的加分及认知变化         |
| 别名               | 登记来源失效则不再参与自动关联；仍有其他有效登记依据时可保留       |
| 待确认问题         | 来源失效则标记失效，旧回答不得继续提交                             |
| 混合来源摘要       | 不能只删来源标记却保留失效内容；先停用该版本，恢复可验证的有效版本 |
| 原始历史 / 旧版本  | 保留供审计，不因回退删除历史；恢复不自动调用 LLM                   |

操作记录需要关联来源及分支身份，支持幂等重放和有效路径核验；载体为记忆派生域操作日志，schema 与版本注册见工程协议 v1。不能因物理 seq 较大就认定来源仍有效，也不能用缓存的高强度保留已被撤回的经历。

### 正文组织（已确认）

记忆正文保存简短、独立可读的摘要，完整原文通过来源引用查阅，不复制整段历史充当摘要。来源、主体与可见范围的结构化信息仍须保留，简短不代表可省略人物指向、否定、认知冲突或必要限定；逐字引用继续接受原文区间核验。

同一事件补充细节不能使单条正文无限增长。长事件可按有意义的信息拆成相互关联的条目，关系与各自来源可核验；不能为绕过单条长度 / 总量 / 批次限制机械切碎内容。不能用截断改变事件含义或把未完成事件写成完成事实。

单条长度、关联条目数量与模型输入上限待样本标定；独立可读的摘要也不代表可以脱离来源、角色权限或因果路径直接使用。历史正文和版本保留仍遵守存储 / 恢复协议。

### 版本正文与提交指向（已确认）

先写新版本正文，再由 SQLite 事务提交当前版本指向；不直接覆盖正在使用的正文。旧版本保留，覆写其他派生页前仍需备份。具体版本路径、操作记录 schema 与保留预算见工程协议 v1，不把文件原子写描述成跨文件 / SQLite 原子事务。

1. 程序核验候选，持久保存本次操作身份及恢复所需信息；不能只存在进程内存中。
2. 写入新版本正文，完成持久化并核对内容哈希，旧版本保持可用。
3. 再次核验当前版本和来源没有失效，在 SQLite 事务中更新版本指向、来源与幂等标记。
4. 确认提交成功后，才让新版本参与读取并通知界面。事务返回结果不确定时先核验提交标记，不能立即重做或宣称失败回滚。

| 恢复情况                 | 已确认处理                                                             |
| ------------------------ | ---------------------------------------------------------------------- |
| SQLite 尚未提交新指向    | 继续读旧版本；新文件不因存在就生效。首次新增没有旧版本时，该条尚不生效 |
| SQLite 已提交新指向      | 核验所指正文，恢复新版本；同一操作不重复强化 / 更新                    |
| 指向的文件缺失或哈希不符 | 停止使用该条记忆，报告并恢复，不能作为正常空内容继续使用               |

恢复使用已持久保存的结果，不自动重新调用 LLM 或重复收费。文件落盘而事务未提交产生的未引用版本需要有界清理 / 恢复判定；未完成操作记录、正文和备份不能因一次扫描失败被误删。损坏旧版本恢复边界见下节；恢复状态机与清理顺序见工程协议 v1；旧版本选择遵守下节已确认规则。

### 过期候选与操作分组（已确认）

提交前发现当前版本已经变化时，拒绝过期候选，不覆盖新版本或静默套用旧判断。仍需重新判断的素材进入下一次已授权批次，不立即追加收费请求；重新处理仍核验来源有效性，并遵守统一预算与同源幂等约束。

互不依赖的修改分别提交，一个操作失败不撤销已经成功的独立操作。相互依赖的修改组成同一操作：持久保存该操作的恢复信息，准备并核验全部所需正文后，在同一 SQLite 事务中切换相关指向、来源与幂等标记，不能只完成其中一半。任一必要候选过期或准备失败时，该依赖操作不提交新指向；文件准备不是跨文件 / SQLite 原子事务。依赖识别、分组上限与恢复状态机见工程协议 v1。

### 正文损坏与旧版本恢复（已确认）

当前正文缺失或哈希不符时先停用并隔离损坏版本，保留诊断信息，不立即删除。旧版本只有正文完整、哈希正确且来源仍有效时才可作为恢复候选；恢复不能重新启用已经失效的因果来源，也不能绕过后续有效纠正重启已撤回认知。

有可验证旧版本时可以自动恢复，并明确提示“已恢复到较早版本”；没有可用旧版本时停用该条并提示。不能把损坏内容当空内容，也不能让模型猜测补写或自动收费重新生成。选择顺序已确认：沿当前版本的历史链向前查找，选最近的正文完整、哈希正确且来源仍有效的版本，不按文件时间或所有分支的创建时间排序。历史链以持久版本关联为依据，不能从文件名猜测；扫描上限、历史链异常与诊断见工程协议 v1。

恢复通过新的可审计操作提交，保留恢复原因和版本关联，不静默改当前指向。旧版本内容不能覆盖并发发生的更新，提交前需重查当前版本与来源。其他健康记忆和正常剧情流程继续使用，恢复不撤销已提交世界事实，仍遵守既有持久化和阶段机约束。

### 旧版本与备份清理（已确认）

清理由引擎按依赖关系执行，不简单按文件时间保留最近 N 个。当前版本、仍被保留因果分支引用的版本、未完成操作所需版本，以及承担损坏恢复用途的有效旧版本不能清理。恢复版本保留范围和数量需在预算协议中定型，不能将“可恢复”作为名义而先删唯一有效恢复版本。

只有超过保留策略且确认没有依赖的旧正文版本和备份才可删除。删除前重新检查当前指向、分支引用、未完成操作和恢复状态；检查失败时跳过。清理与提交 / 恢复需协调，不能在检查后并发新增引用仍直接删除。

原始剧情记录与记忆归档不因活动容量满被顺带删除。旧版本数量、期限和磁盘上限通过实验确定；无法安全回收时提示占用，不强删。扫描与清理批次有界，进程中断后可重试核验，不把删除失败当作恢复信息已经消失。

模型拒绝或提交前失败不修改既有人设。提交结果不确定时先核验与恢复，不能让未经确认的新状态继续参与生成。失败需要可审计诊断；新增 system.code / 事件 / 错误码须按 006 / 通信契约登记，不把本文的概念直接作为当前可用事件。

## 触发、让位与预算

闲置后台、幕切、会话结束的记忆工作均默认关闭。启用收费后台前需要明确授权；触发不代表可以占用所有闲置时间或无上限扫描历史。用户返回时在安全边界让位，不中断已经开始的持久化提交。

012 已提交 `roundEnded/completed` 后的一次只读钩子可作为素材入口；重放不能再次自动收费。该钩子当前只提供来源身份，不意味着每回合都必须调用模型。007 的触发阈值独立标定，不套用 006 recap 的已定稿数值。

实现前必须给正文、条目数量、输入素材、候选 JSON、单轮扫描、模型调用、队列与诊断明确硬上限。模型请求受 005 的预算约束；具体数值在评审和标定后冻结，不把未填参数当无限。

### 统一预算与有界批次（已确认）

共用一套以费用为控制单位的 [LLM 调用预算](llm.md#统一调用预算与任务优先级)，不额外设记忆专属额度；同时检查每周目与全应用自然月金额额度，默认金额由参考 Token 用量及模型价格计算；Token 仅保留底层计量 / 单次限制，计价细化由 027 承接；预留 / 结算以该文档为唯一规则来源：先预留、完整 usage 后结算、未知消耗不当零退款，预算与请求身份持久化，恢复不自动重发收费请求。主流程必需的请求若额度不足则暂停推进；可选后台工作不足时跳过，不抢主流程额度。共享供应商余额或总额度也可能使剧情请求失败，不能承诺无限继续。

来源检查、候选定位、衰减与幂等等本地计算继续执行。语义分类与值得记判断合并为一次有界批次请求，避免每道门各调用一次；费用处理默认关闭，授权后仍有单批输入 / 输出硬限和统一调用限制。批次合并的质量影响、批次大小 / 触发频率与额度数值待对照标定，不将未经实测的合并策略宣称更准确。

未处理素材保留原始来源，不能当作已经形成新记忆；玩家未答确认问题不会触发反复模型调用。恢复仍使用已保存结果，不自动收费重生成。哪些记忆 / 上下文工作是推进前置条件必须由记录引擎明确，不因预算统一把所有后台工作变成主流程必需步骤。

### 批次触发（已确认）

启用已授权记忆处理后，先收集已提交且通过资格检查的素材，不对每句话立即调用模型。素材数量或输入 token 达到门槛时合批，节点切换可作为额外处理时机；具体门槛、单批大小和延迟目标待实验确定，不套用 006 recap 的固定门槛。

当前推进确实依赖尚未处理信息时，由引擎明确列出必要请求，不机械等待凑满批次，也不因关键字命中就擅自升级为必要处理。没有新素材不调用；记录重放、未答复确认问题及重复检测不触发额外请求。已覆盖来源和处理操作身份需用于去重，不能在取消 / 恢复后重新付费处理已持久完成的同一结果。

可选后台仍默认关闭，启用后让位于主流程；批次请求与必要请求共同遵守统一预算、005 请求约束和 020 单在飞门禁，不绕过纯函数 project 的职责。场外偏好素材按原 mode 处理，收集素材不等于增加场内回合时钟。

## 轮回缓存

轮回缓存默认关闭，作用域是剧本。内容为结构化刻痕与有硬上限的短摘要，带周目身份和代数；由规则表或可信 `cycle:true` 标签授权。模型不能自行选定持久身份、授予跨周目权限或写任意长文。

压缩顺序为同 id 去重、按权重与代数进行独立归档、可选轮回提要。提要默认关闭；其调用预算与来源校验仍受共同规则约束。“权重 × 代数”的具体表达式待研，不能先实现为越旧越重要或据此删除正文。

**M03 已确认：跨周目刻痕由剧本显式授权，默认表现为若有若无的感受。**

- 玩家本人对上一周目的了解，不自动成为当前角色的知识。
- 角色 / NPC 仅继承规则允许的刻痕，每条明确可见对象；旁白可用的信息不自动成为所有角色的知识。
- 默认表达为似曾相识、莫名亲近 / 戒备、模糊梦境或片段，不默认恢复完整前世记忆。确切人物、地点、事件细节须有对应剧本授权，不能把模糊刻痕展开成未经授权的剧情答案。
- cycle 不隐式继承上一世的死亡、任务结果、关系数值或其他 SQL 世界状态；确需延续的状态由引擎另按规则提交。主观亲近感不等于关系数值已经变化。

例如，上一周目玩家救过某 NPC，规则可以允许他产生说不清的信任感；是否记得救援细节由剧本决定。刻痕的柔和表现不改变其结构化来源、可见权限和审计要求，也不意味着每次出场都需要提示前世。

新周目注入仍有 Top-K 与字数硬上限，防止刻痕无界累积。

注入若进入新 session 静态段，必须在创建 header 前完成冻结；内容变化会改变前缀字节与 hash，不能承诺供应商缓存继续命中。现有 session 内不热替换 `header.staticPrefix`。动态注入位置、预算及检索时机须经后续投影设计评审，007 v1 不提供该能力。

## 节点节奏与收束

章 / 幕 / 场是数据轴，不写死每章回合数。引擎维护 SQL 隐性计量，玩家原文中不加入计量值；模型不能自由修改计量或创建场景身份。晋级仍需遵守 012 的可信场景目录、条件校验与先提交后发布规则。

节点切换是段收束的主要触发点，可选压缩不能被默认开启。日常超预算首先尝试 006 已允许的确定性预算处理；必需内容仍放不下时沿用预算拒绝 / 压缩计划协议，不暗加付费请求或裁掉完整当前玩家输入。

安全阀需要防止永不晋级，但不能跳过可信场景条件、随机代替失败的场景提议或伪造结算。**M05 产品规则已确认：**

- 章 / 幕 / 场按剧本条件推进，例如获得线索、完成目标、作出关键选择，不固定每章回合数。
- 引擎维护隐藏进度，模型负责叙述和提议，不能自行修改计量或绕过晋级条件。
- 长时间无进展时，优先使用剧本预设的提示、替代线索或合法出口；触发安全阀不代表自动晋级。
- 没有合法出口时提示当前受阻，让玩家选择继续探索或结束；不凭空生成出口。
- 可选记忆压缩失败不阻止已经满足条件的场景推进；必要持久化失败仍按既有恢复协议处理，不能跳过提交。

停滞开发值、提示频率、条件端口和受阻选择见工程协议 v1，实测值仍待剧本样本验证。**M02 已确认：段切保持同一 session，通过动态 `WorldView` 更新场景状态，可选压缩历史，`header.staticPrefix` 保持不变。** 段切不重冻前缀、不创建新 session、不改变现有恢复与因果回退协议。将来确需改变静态规则或前缀时，另行设计新 session 衔接，不属于本次节点收束范围。

## 后续可选记忆注入（选择原则已确认）

本节约束未来可选注入，不改变 007 v1 不接 006 检索热路径的边界，不代表现有 project 已实现记忆检索。

- 先过滤因果来源失效、正文损坏及当前角色无权获知的内容。
- 优先选择与当前场景、实体、目标和玩家输入相关的记忆，不只按 strength 排序；同名 / 字面相似不能自动证明实体或事件关联。
- 纠正后的认知及未决冲突保留必要限定，不能只注入旧印象而省略已获知纠正或疑惑，造成误导。
- 条目数与总 token 双重限额，不能将全部活动记忆注入上下文；注入须受 006 总上下文硬限约束，不能挤掉其必需字段。
- 摘要不足以支撑关键判断时，在预算内查阅原始来源；仍不能确认则询问玩家，未答复行为沿用已确认的默认继续规则，不能据此猜定事实。

具体候选检索、排序权重、原文读取边界及选择上限待实验 / 协议定型；不引入向量作为默认实现，也不为一次检索无界扫描全部历史。主观记忆、玩家偏好及轮回刻痕仍遵守各自可见范围和已授权使用规则。

## 工程协议 v1（已评审设计）

本节将前文规则收敛为拟实施契约，不表示已有表、命令或运行时。v1 保留不接投影检索热路径的范围；语义分类的效果需独立样本验证，程序的来源校验不能被宣传为已经证明全部语义正确。资源值及算法初始参数的性质见[算法标定](memory-algorithms.md#参数约束与初始实验配置)。

### 身份、来源与可信获知证据

记忆新增的持久身份由 Rust 生成 UUID，script / entity 等外部身份沿用可信登记目录；`runId` 标识周目，v1 一个 run 绑定一个游戏 session，同 session 段切不更换 run；跨 session 衔接仍是未来独立设计，不提前合成因果路径。绑定表 `memory_run_sessions(run_id, session_id)` 必须唯一且指向引擎登记的会话，不从名称或文件路径推断归属。周目创建事务保存完整策略快照和配置来源版本，恢复不依赖当前设置。

| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SourceRef         | scriptId、runId、sessionId、recordSeq、bodyHash、startByte、endByte、mode；区间为原始正文 UTF-8 的 `[startByte,endByte)`，非 JSON 转义行偏移                        |
| Batch             | batchId、runId、historyRevision、policyHash、输入摘要 inputDigest、状态；inputDigest 覆盖来源映射、实体目录 revision / 旧记忆版本及可信证据快照                     |
| SourceSpan        | batchId + 短引用 ID `s1…sN`、SourceRef、片段正文 / 上下文角色；引用 ID 的唯一约束包含 batchId                                                                       |
| KnowledgeEvidence | 引擎分配的 evidenceId、subjectId、SourceRef、获知方式、告知者（适用时）、范围及所依据的可信规则 / 记录身份                                                          |
| MemoryVersion     | entryId、versionId、parentVersionId（首版省略）、restoredFromVersionId（恢复时必有）、subject、dimension、summary、attitude、inferred、来源集合、可信证据集合、hash |

recordSeq / historyRevision 沿用 006 / 012 的安全整数范围；正文 hash 为原始正文 SHA-256，不与 006 recap 的整行 sourceHash 混用。mode、完成状态、speakerId 从原始记录读取，模型不能覆盖。来源有效性必须调用 022 提供的有效路径视图，并核验 hash、区间、提交状态和素材资格。

获知证据由引擎根据明确的观察范围、对话接收对象、已登记传闻交付或规则事件建立，不因同场景自动建立。模型只能选择本批提供的证据 ID。没有对应角色的有效证据时，不提交该角色认知；玩家偏好使用独立 subject，不伪装成 NPC 证据。来源方式逐来源保存；inferred 是独立标记，不替换 observed / told / rumor。

片段优先完整记录行，超长时在 UTF-8 字符边界按句 / 段切分，带 continuation 标记和有界邻接上下文；上下文也有引用 ID。否定、转述或指代所需上下文仍不完整时，该素材记为 deferred，不强行输出完整事件结论，不把切片故障交给玩家猜。批次映射在请求前持久化；原始记录保留，恢复可重新核验，模型响应不能重新定义映射。

### 候选 schema 与 prompt 骨架

模型顶层仅允许 `{ version: 1, candidates }`；batchId / inputDigest / turnId 由调用方的冻结上下文绑定并写入持久响应封装，不要求模型抄写长身份或 hash，也不信任模型重定义批次。候选字段如下。字段名固定 lowerCamelCase，可选字段省略，不使用 null，未知字段拒绝对应候选；顶层未知字段、不支持版本、调用方身份不符、非 JSON、重复 JSON 键或整体超限拒绝整个输出；只有完成的单个 JSON 文档可接纳，截断 / 多文档不部分消费。每个候选的引用数组不得重复身份，不同候选可引用同一来源；空 candidates 表示无候选，不声明所有素材都已成功处理；没有对应逐项结果的素材保持 needsExplicitRetry，不被定时重扫反复收费。

| 字段                | 类型 / 约束                                                                                                                             |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| candidateId         | 本批内唯一 ASCII 短 ID；只用于关联响应，不作持久幂等键                                                                                  |
| classification      | `repeat / supplement / new / correction / notWorthy / uncertain`                                                                        |
| sourceIds           | 本批提供的片段 ID 数组，至少 1 项                                                                                                       |
| subjectRef          | 本批提供的主体引用；角色主体或当前玩家偏好主体                                                                                          |
| entityIds           | 已登记的稳定实体 ID 数组，可为空；不能创建实体                                                                                          |
| evidenceIds         | 本批提供的可信获知证据；角色可保存分类为非空数组，uncertain / notWorthy 可省略，玩家偏好省略                                            |
| targetRef           | 旧条目 entryId + expectedVersionId + expectedStateRevision；repeat / supplement / correction 必有，new / notWorthy 省略，uncertain 可选 |
| dimension           | `plot / relationship / preference / clue`；可保存分类必有                                                                               |
| summary             | 可保存分类必有，非空白、有界；notWorthy 省略，uncertain 只给问题说明                                                                    |
| attitude            | 角色可保存分类必有：`unexpressed / believes / doubts / rejects`；偏好省略                                                               |
| attitudeEvidenceIds | 改变态度或首建非 unexpressed 状态时必有非空数组，指向提供的角色表达 / 引擎规则证据                                                      |
| inferred            | 可保存分类必有布尔值；true 时保留推断依据，不成为新亲历证据                                                                             |
| reason              | 有界依据摘要，非内部思维链                                                                                                              |

角色主体仅使用 plot / relationship / clue，玩家偏好主体仅使用 preference；态度证据须明确属于本 subject，转述另一人的态度不能更新自己的态度。已知反话、表演 / 伪装、仅引用他人说法的来源不作为真实认知变化证据，不能用“相信”关键词直接转换。

候选没有 strength、分数、文件路径、SQL、事实 patch、自由引文、实体登记或权限覆盖字段。新事件没有旧 targetRef；无法确定关联须 uncertain。repeat 只计划有效强化 / 复活或 no-op，不用其摘要或态度覆盖旧内容；有内容 / 态度变化须 supplement 或 correction。classification=new 的源素材主体 / 维度 anchor 已处理时拒绝或转待关联问题，不能换 candidateId 创建重复 entry。分类相互依赖时由程序形成依赖操作组，模型不能用任意组号改变原子边界。

PromptPlan 由 Rust 构造：可信任务说明 / schema → 冻结批次身份 → 主体 / 实体目录与旧记忆版本 → 来源片段和获知证据 → 输出要求。玩家 / 历史文本标作数据，沿 006 的保留括号转义规则生成 prompt 副本，原文与引用映射不变。任务要求只返回上述 JSON，不创造实体或权限，不以强度判真，无法关联返回 uncertain，不值得记返回 notWorthy；不请求内部推理。目标为 `[MYTHOS:MEMORY-PROPOSAL]`，由 GrammarSpec 注册目标闭合 stop 与 outer / forged-close 护栏，不新增正式 JSONL kind。

逐字引文由程序按 sourceIds 提取；模型摘要是认知内容，不能当原话。独立候选的局部拒绝不撤销其他合格候选；输入 / 顶层失败则不处理整批。拒绝原因保存脱敏诊断，不增加自动 JSON 修复调用。

#### 最小候选示例

程序给出 s1 对应玩家已提交的场外原文“不喜欢恐怖描写”，p1 对应玩家偏好主体；模型可返回以下完整 JSON。引文由程序提取，不在模型输出中重复原文：

```json
{
  "version": 1,
  "candidates": [
    {
      "candidateId": "c1",
      "classification": "new",
      "sourceIds": ["s1"],
      "subjectRef": "p1",
      "entityIds": [],
      "dimension": "preference",
      "summary": "希望避免恐怖描写。",
      "inferred": false,
      "reason": "玩家明确表达了体验偏好。"
    }
  ]
}
```

恢复重复收到同一个结果时复用持久计划和 entryId；若同源偏好已经处理，不再创建新条目。把 p1 改成未提供角色、加 strength 字段、引用未知 s2 或将 summary 当玩家逐字引文，分别在主体 / schema / 引用 / 展示边界拒绝。

### 纯函数门控、实体与幂等

纯函数输入均为已冻结的有界值，不自行查询数据库或网络。以下签名是设计职责，具体 Rust 类型在实施时定义并同步 TS 消费类型。

```text
qualify(source, causalView, runBinding) -> Eligible | Deferred | Rejected(reason)
locate(material, entitySnapshot, memoryWindow) -> CandidateRefs
validateCandidate(candidate, batchSnapshot) -> Validated | Uncertain | Rejected(reason)
planChanges(validated, policySnapshot, logicalClock) -> Vec<DependentChangeSet>
score(entry, validEffects, clock, policy) -> BoundedScore
selectArchive(entries, capacity, relevance) -> ArchivePlan | CapacityBlocked
```

顺序固定：输入 / 身份 → 来源有效性与资格 → subject / 实体 / target 版本 → 获知 / 态度证据 → 分类字段及摘要 → 幂等 / 同经历限额 → 变更计划。评分不抵消任何拒绝。repeat 只有同主体、旧条目关联及有效重提证据均通过时才计划强化；事件语义仍来自有来源候选，不声称字符计算能够证明同事件。旧条目无可靠关联时询问而非自动合并。

实体解析使用引擎登记目录，不建第二份 canonical 目录。精确名称 / 已确认别名按类别、地区 / 规则范围查索引；文本查找可用 NFC 副本，但原文引用不归一化。近似 / 同音仅召回候选；生成名称冲突检查按[算法候选](memory-algorithms.md#参数约束与初始实验配置)执行，不能改名已有实体。自动别名登记须有可信明确指向：例如引擎登记的对话接收对象或玩家已确认的关联，再核验完整目录内唯一性 / 别名未占用。单次模型猜测或缓存里只找到一个名字不构成证明；目录完整性 / revision 无法核验或候选扫描未完成时只保留 deferred，不自动登记；其余情况生成待确认问题。

| 幂等身份    | 组成与用途                                                                          |
| ----------- | ----------------------------------------------------------------------------------- |
| 操作        | UUID + 规范化计划 hash；同 operationId 不同计划为损坏                               |
| 来源处理    | runId + subject + 原始 SourceRef + 处理类别；不使用片段短 ID，防拆片 / 新批次重计   |
| 强化 / 复活 | runId + entryId + 有效来源集合 hash + effectKind；同源幂等之外另查同经历窗口 / 冷却 |
| 场内时钟    | sessionId + roundId 的 completed 回执；重放 / 重复回执不增量                        |
| 别名        | runId + entityId + 类别 / 范围 + aliasKey + 有效登记来源                            |
| 歧义问题    | runId + subject + 归一化关联目标 + 原始来源 / 事件身份 + 问题类别                   |

修改同一 entry、共享一个素材覆盖标记或彼此引用新结果的候选属于同一依赖组；同组按原始素材逻辑位置 / candidateId 稳定排序后顺序计算窗口与增量，不能各自按旧 n 加分。received 响应的候选 / 计划 hash 持久保存，恢复只执行既定计划，不重新生成 entryId。素材覆盖标记在该单元全部已登记候选有结果后写入，deferred 不标已覆盖。来源处理使用稳定素材单元身份，切片映射在当前 run 内持久固定，后续批次只复用，不能通过重新切片制造新素材。强化 / 复活对同一 entry 的同一原始 recordSeq 最多接纳一次对应效果，不能只凭区间变化再计分。SourceRef 身份使用原始记录及精确区间；包含重叠片段的同一处理计划先合并区间，不能换一个片段 ID 就绕过已处理标记。questionKey 不按文字相似生成；同一原始事件的候选集合变化更新既有问题 revision，迟到回答须同时匹配 questionId / revision / historyRevision。新来源能否并入旧问题必须有相同事件身份，否则另建问题。

别名绑定采用 `active / revoked`，待确认问题采用 `pending / resolved / invalidated` 状态；提交答案在事务内重查来源 / 目录 / 条目版本，结果唯一性约束与 applied 操作同提交。回答只授权其明确关联，不赋予 NPC 知识或证明世界事实。来源回退使登记失效时撤销关联；仍有其他有效登记依据时保留。队列满则保留原素材和 deferred 身份、提示待处理，不能标作已处理或无界创建问题。

### 批次请求与结果持久化

批次状态为 `queued / dispatched / received / completed / rejected / unknown`：queued 已持久冻结映射及 inputDigest；dispatched 在网络发送前登记独立 turnId / 027 物理请求身份与预留；received 代表有界完整响应及 usage 引用已持久保存；completed 代表全部候选已得到应用 / 拒绝 / 待确认 / deferred 的逐项结果，不要求全部成功。输出 malformed / 超限为 rejected；网络尝试是否发送或用量不可核验时为 unknown，不当零退款。全部结果在 completed 状态下仍逐项区分 applied / no-op / rejected / pending / deferred，命令 partial 表示存在待处理项而不是事务半提交。

已接纳 private 输出后不重发，完整结果先通过受控原子写保存到 `memory/runs/<run-id>/batches/<batch-id>/result.json`，再标 received；文件含调用方封装的 batchId / inputDigest / turnId / responseHash，不由模型提供。写入或提交结果不确定时核验预登记文件 / hash / ledger。崩溃后 received 可继续本地校验和操作准备；dispatched 缺完整结果保持 unknown / deferred，不自动重发，不伪造已完成。重新发起判断须进入新的已授权批次并使用新的物理请求身份，已完成的同源操作仍幂等。

原始结果已经持久保存而因待确认容量 / 本地资源暂时不能提交的候选，保留 localDeferred 原因与计划；空间释放后只重新做本地核验，不再调用模型。输入切片不足时同样等新上下文，不对同一不足输入反复收费。网络 / 顶层 schema 失败的素材标 needsExplicitRetry，只有用户主动重试 / 恢复或新的有效输入改变判定前提时才能重新排收费批次，不能用定时重扫暗中修复 JSON。

网络 / 顶层 schema 失败计入连续批次失败；app.busy、余额不足跳过、过期候选和本地 deferred 不作为模型失败累计。结果 / 计划文件与来源保留受依赖保护，不能在批次尚未 complete 时清理。

### manifest、操作状态机与恢复

SQLite 拟新增窄表：memory_runs（完整策略与时钟）、memory_run_sessions、memory_materials / memory_batches / memory_spans、memory_entries / memory_versions / memory_version_sources、memory_effects、memory_operations / memory_operation_targets、memory_aliases / memory_questions。实体 canonical 数据只经可信引擎端口访问。表名是迁移设计，尚未创建；迁移由 mythos-store 的有序事务 / user_version 管理，业务 crate 拥有 schema 和读写逻辑。

entries 当前指向 versions，并保存 stateRevision；正文指向、强度效果、归档 / 复活状态等任一确认变化都递增它，避免正文未变时旧数值计划仍通过 CAS。versions 保留父版本、正文 hash / 长度与有效来源；effects 保留 event / source 依据及加分 / 复活原因，计算时仅装载当前有效路径。外键、唯一幂等索引与 `(run_id,status,entry_id)` 分页索引在迁移中建立；应用字段长度校验与 SQL CHECK 联合保证合法状态。状态 / applied / targets 在同一事务更新，不依赖内存标记。没有正文变化的 no-op / notWorthy 仅事务保存处理结果；需要正文时才准备新 version 文件，不能为记一个拒绝原因反复复制正文。

正文路径为 `workspaces/<script-id>/memory/runs/<run-id>/entries/<entry-id>/<version-id>.json`，操作身份不会进入玩家 Git 仓库；cycle 使用独立 `memory/cycle/` 域。UUID 与受控路径由 Rust 分配，模型不能提供路径。来源集合持久保存于不可变关联表，单版本最多 128 项有效正文来源 / 获知证据，超过时拒绝继续扩张并提示拆分；强化来源另存 effects，不把每次复述都复制进正文引用集。版本 JSON 包含 version=1、版本身份、结构化认知内容、sourceSetHash / evidenceSetHash 和策略身份；SHA-256 校验文件原始字节，禁止改写已发布版本。

| 状态        | 持久含义 / 下一步                                                            |
| ----------- | ---------------------------------------------------------------------------- |
| prepared    | 校验过的完整计划、期望版本、来源、策略、文件身份已入库；写正文前即存在       |
| ready       | 全部新正文已持久写入并核验 hash；尚未改变当前指向                            |
| applied     | 事务 CAS 成功，全部 targets / effects / 来源处理标记已提交；操作不可再次执行 |
| rejected    | 来源 / 版本已失效或计划不合法；不切指向，保留原因与待重新处理的素材          |
| quarantined | 计划 / 文件 / hash / 身份冲突无法核验；隔离受影响条目，保留诊断              |

prepared → ready → applied 是正常路径。文件落盘成功而 ready 回执丢失时按预登记文件核验；ready 提交前 CAS 比较全部 expectedVersionId / expectedStateRevision，并重查 historyRevision / 来源及策略。任何 target 过期使整个依赖组 rejected，独立操作不受牵连。SQL 提交不确定时只核验操作状态与 targets / effect 标记，不能先改为 rejected 或重做。

恢复持有实例锁、使用同一业务单写者，分页核验非终态操作：prepared 若全部预登记正文健康则推进 ready，缺少正文则 rejected / deferred，不调用模型补写；ready 在前置条件仍成立时提交，过期则 rejected；applied 校验当前 / 历史指向，不重复效果或收费。哈希 / 身份冲突为 quarantined，不能继续当空正文。 applied 标记与 targets 不能解释为同一事务结果时，报告 store.corrupt 并暂停受影响域修改。

损坏恢复沿版本 parent 链查找，使用 visited 集合识别循环，按批次上限续扫；父链断裂 / 越域 / 自循环是损坏，不能跨分支猜版本。候选还须避免重新启用被后续有效纠正撤回的认知；旧来源存在不等于旧认知仍可安全作为当前内容。无法保留有效纠正限定时停用该条，不自动恢复旧错误印象。找到最近健康且满足这些条件的祖先后创建新的恢复版本与审计操作，保留其历史关联和当前 expectedVersionId，不能直接改旧版本或覆盖并发更新。扫描额度耗尽保留游标、条目暂不可用，下次主动 / 打开恢复续扫；不把“尚未扫到”报告为无可用版本。

清理只处理已终态、超过保留策略且无依赖的文件；当前版本、保留因果分支、非终态操作及恢复所需旧版本的元数据 / 文件受保护。检查引用与取得删除资格在同一单写者边界内，删除期间禁止新增对候选的引用；失败保存清理状态，下次核验后继续。磁盘不足不删原始记录或强删唯一恢复版本；保留策略目前为不自动删除有因果保留价值的版本，未来支持显式历史裁剪需另行设计。

### 高级设置与跨端接口

配置保存包含 configVersion、algorithmVersion 与完整类型化参数；剧本配置仅保存显式覆盖字段。unset 与合法零值分开表达，不用“假值”判断继承。解析顺序为已确认应用默认 → 已确认剧本覆盖 → 整组校验 → 新周目完整快照 / policyHash。跨字段约束失败时提示冲突并拒绝创建使用该配置的新周目，不默默清掉覆盖或混用旧 / 新策略；已有周目继续使用原快照。

保存命令携带 expectedConfigVersion，剧本保存同时携带 expectedAppConfigVersion，事务 CAS、校验和版本递增同时完成，冲突保留草稿并要求重新读取当前确认值；应用默认与剧本覆盖按同一一致读取版本校验，默认变化导致旧预览过期时拒绝保存并重新读取，不偷偷提交另一套继承值；前端一配置作用域至多一个保存请求在飞，不自动覆盖更新。默认值 / 覆盖的读取与周目创建在同一数据库一致边界完成。恢复默认只清除覆盖草稿，点击保存后才提交；应用恢复默认取内置受版本管理的参数，而剧本恢复默认取继承。

拟实施 DTO 使用 camelCase、可选字段省略、UUID 字符串、安全整数与有限数值；Rust enum / struct 定型后 TS 立即声明同型，invoke 仍透传。范围端口固定为 GetConfig(scope)、SaveConfig(scope,expectedVersion,params)、ListQuestions(run,cursor,limit)、ResolveQuestion(id,revision,answer)、ListEntries(run,cursor,limit)、GetEntry(entry,version)、ProcessBatch(run,expectedHistoryRevision)、GetBatchStatus(batchId)。具体 Tauri 命令注册与 DTO 展开由后续设置 / 查询任务同 commit 纳入通信契约，不把端口声明当现有 IPC。

配置返回已确认值、继承来源与生效范围，保存返回新配置版本，不宣称当前周目已重算；问题答案支持指定已提供的稳定对象、新对象说明、都不是。新对象说明只提交登记提议，不让记忆命令直接创建权威实体；目录未登记前相关记忆保持待确认。ProcessBatch 在接纳前拒绝参数 / 租约错误；接纳后命令异步等待该有界批次结束并返回 BatchResult，结果含 batchId、runId、historyRevision、completed / partial / failed / cancelled 及逐项摘要 / 脱敏 error，不把接纳后的失败当“未执行”命令错误。响应丢失后主动 GetBatchStatus 可读持久结果，不自动重发命令；UI 换 run / historyRevision 后忽略旧响应。

查询使用绑定 run / historyRevision / 固定读边界的游标，回退或跨 run 的旧游标拒绝，按公共分页 / 载荷预算返回，不输出文件路径。

### 持久结构约束与版本兼容

内部存储 schema version 由有序迁移登记，业务 payload 另带 version=1；不把 payload 版本当 user_version。UUID 为 TEXT、hash 为 32 字节 BLOB、计数 / revision 为 INTEGER 且限制在安全整数范围、规范化计划 / 策略 / 来源集合为经类型校验的 UTF-8 JSON BLOB；SQLite 不是类型校验替代品。

| 表组                 | 关键字段 / 唯一约束                                                                                                                                                                                                               |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| runs / run_sessions  | runId、scriptId、algorithmVersion、完整 policyJson / policyHash、配置来源版本；sessionId 唯一绑定 run，v1 runId 也唯一绑定 session                                                                                                |
| materials            | materialId、run / session / recordSeq、稳定 unitOrdinal、原始区间 / hash、资格 / 处理状态；原始记录和 ordinal 唯一，不因重启重新切片                                                                                              |
| batches / spans      | batchId、turnId、inputDigest、historyRevision、policyHash、请求 / 结果状态；(batchId,sourceId) 唯一，span 引用 materialId                                                                                                         |
| entries / versions   | entryId、runId、subjectRef、当前 versionId、stateRevision、active / archived / unavailable；versionId 唯一，parent / restoredFrom 属于同 entry，JSON hash / 长度 / 结构化元信息不可改写，引用集合用 sourceSetHash 关联 sources 表 |
| sources / effects    | versionId 关联 SourceRef / evidenceId；effectId、entryId、来源 / 事件、逻辑位置、gain / revival；同来源对同 entry 的同类效果唯一                                                                                                  |
| operations / targets | operationId、planHash、inputHistoryRevision、state、planJson；(operationId,entryId) 唯一，保存 expected / next versionId 及 expected / next stateRevision                                                                         |
| aliases              | aliasId、runId、entityId、类别 / 范围 / aliasKey、状态及有效登记来源；同范围 active aliasKey 只能指向一个实体                                                                                                                     |
| questions            | questionId、questionKey、runId、revision、historyRevision、候选版本、来源集合、状态；pending questionKey 唯一，回答只能 CAS 当前 revision                                                                                         |
| configs              | scope、configVersion、algorithmVersion、完整参数或显式覆盖；每作用域只有一个已确认当前版本，旧版本保留供 run 引用                                                                                                                 |

公开 DTO 的 mode 沿用 inCharacter / outOfCharacter；非玩家记录不伪造玩家 mode。sourceIds 为 `s1…s128`，candidateId 匹配 `[A-Za-z0-9_-]{1,32}`，subjectRef / 证据 / 旧条目引用须来自本批白名单。原始候选不能携带自由文件名，材料分片表与引用表分开，避免同一原文在新批次换短 ID 就变成“新来源”。

在同一个工作区数据库的事务与业务单写者边界内校验 confirmed historyRevision、无 pending 世界 / fork 恢复、各目标正文版本 / stateRevision、策略 hash、实体目录 revision 及可信证据版本，随后 CAS 提交。022 在写回退 / 世界意图前登记 pending，直到 applied / 恢复完成；记忆写入等待该边界，不在 JSONL 已变而 SQLite 尚未 applied 时抢先提交。此协调接口不让 memory crate 直接写世界表或改记录。

已预登记的版本文件存在时先核验 hash，内容一致可复用，不一致隔离报错，不能用 write_atomic 覆盖身份冲突。旧版本正文内容不可变；恢复版本 parent 指向提交前当前版本，restoredFrom 指向选中的健康祖先，形成新的可审计状态。全部 targets / 当前指向 / effect / 来源处理标记和 applied 状态一个事务确认。

读取遇到未知未来 payload / algorithmVersion 时返回 policyUnavailable / app.not-ready，诊断和原始历史只读可用；不套当前默认、不破坏未知数据。兼容实现保留已发布的版本解析 / 整数率表；显式迁移只能形成新派生版本并留下原 snapshot，不静默改已有周目策略。已有派生 schema 迁移失败按 store.migration 冻结所需写入域。

### 轮回与节点的类型化接入

刻痕拟使用 CycleMarkV1：markId、scriptId、cycleGen、ruleId / ruleVersion、subjectIds、源 run / session / 因果路径锚点、sourceRefs、kind、detailPolicy、priority、短摘要。kind 为 familiarity / affinity / wariness / fragment；detailPolicy 为 vague / explicit，explicit 必须有对应剧本规则授权。priority 为剧本登记的 0–1,000 整数，不由模型评分填写。刻痕稳定身份由规则 ID、对象和引擎登记的 imprintKey 决定，按来源幂等添加，不以摘要措辞生成新 ID。

授权处理只有本地规则能产生刻痕，模型可在已授权范围内提出摘要。首轮开发活动刻痕上限每剧本合计 64，绝对 256；每条摘要 ≤512 字节、每次拟选最多 8 条且摘要总计 ≤2 KiB。超限独立归档，不删除来源；去重合并来源前重查每个分支锚点。同一规则的新一代实例保留 generation 和来源版本，不把旧 cycle strength 套入会话公式。

新周目仅从当前选定且有效的来源分支建立授权快照；快照绑定原始因果锚点并保护被引用历史，不能因后来打开另一个分支偷换来源。来源损坏或授权撤销时相应刻痕不可使用。v1 保存 / 查询刻痕及准备投影端口；实际可选注入按后续独立投影设计实施，不以缓存已存储宣称角色已获得该知识。若以后进入 header 静态段，仍在创建 header 前冻结，不能热改现有前缀。

节点接口只读取 012 定义、023 交付的可信 SceneRuleView：sceneId、advanceRuleIds、progressRuleIds、hintRules 和 exitRuleIds；条件计算复用[阶段机的只读求值端口](turn-state-machine.md#场景规则视图与只读求值端口)，返回 matched、确认 revision 与可信依据引用，不接收任意 SQL / 模型谓词。hintRule 有 hintId、whenRuleId、固定提示文本和目标范围；替代线索 / 出口也必须引用已有登记规则，不能直接补写事实。

scene.progress 是 032 维护的派生进度，不是新增世界属性或公开 phase；只有 progressRuleIds 匹配结果出现新的有效依据时改变，规则持续为 true 或重复返回相同引用不算新进展。进入场景时记录已有依据作为基线，不能把任意世界 revision 变化当有效进展。每个已完成场内回合至多更新一次停滞计数；可信进展 / 场景改变后重置，失败 / 取消 / OOC / 重放不计。开发起点为 8 个无进展回合后提供可用提示、提示冷却 5 回合、每场最多 3 个已登记提示，均需剧本配置和样本验证；这不是自动晋级阈值。

提示选择纯函数按 rule priority / hintId 稳定排序，先核验条件，返回预置文本 / 合法操作，不追加模型调用；提示只读展示，不自动兑现替代线索或出口。没有可用出口时允许继续探索或结束游玩，后者保存 / 关闭当前对局，不伪造剧情胜利或结束条件。接入由 D 完成，复用阶段机提交结果与同型查询，不扩展世界事实权限。
