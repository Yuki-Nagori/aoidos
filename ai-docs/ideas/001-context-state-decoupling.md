# 001 — 上下文与对局时长解耦：本地状态库 + 对局文档 + 索引

- 状态：已立 task（[006 对局记录与上下文·设计](../task/006-record-design.md)，planned）
- 记录日期：2026-10-05
- 来源：产品思考

## 问题

仅靠 LLM 对话缓存跑对局：历史全部进上下文，越到后面消耗越多、响应越慢、越吃力，长对局在成本与体验上都不可持续。

## 构想

Mythos 在本地维护持久状态，LLM 不回放对话缓存，而是按索引跳转得知「现状与下一步」：

- 世界状态数据库：记录属性等结构化数据（角色属性、NPC、人物关系、关键事件）。
- 一组对局文档：专门维护的场景摘要、事件日志等叙述性记录。

每轮按索引取用「当前状况 + 相关片段」组装上下文，上下文占用与对局时长解耦，故事再长也不再天然变贵变慢。

## 若立项，待决策

- 本地存储引擎选型（如 SQLite）与 schema。
- 对局文档的格式与粒度（场景 / 章 / 幕）。
- 索引与检索策略：每轮如何决定取哪些片段。
- 状态写回：由谁在何时把新对话蒸馏进状态库与文档。
