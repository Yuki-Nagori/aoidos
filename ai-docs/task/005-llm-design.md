## 设计复核结论

issue #8 的方案 A、双形态、玩家共享 stop 前缀、空输出例外、quota 独立分类和有限快照缓存可以作为设计基础。复核后补齐：

1. reqwest 本身也有默认重试，显式禁用后由单一调度器控制；温度和传输两条重试路径互斥，物理请求总数不叠加。
2. DeepSeek Chat 默认 thinking，叙事显式关闭；FIM 能力与 token 上限按具体端点维护，不能套通用模型上限。
3. 服务端子串 stop 不能代替行首护栏；跨分片扣留、EOF、取消和部分标签行为写成黄金样例。
4. 首字符以共享输出写入方接纳为准，不依赖窗口是否监听；心跳 / reasoning 不重置业务截止时间。
5. 快照须包含三个事件的 seq 基线，订阅先于快照；记录、状态和序号更新有明确顺序，终态恰一次；终态事件附 chunkSeq，避免独立事件计数漏检正文缺失。
6. ring buffer 还需限制文本 / SSE / 队列大小，驱逐连同 seq 清退，不能仅按回合数承诺内存有界。
7. 保持明文不进 Webview 的现有规则，set_key 使用 Rust 原生输入，不放宽明文边界；019 先验证三平台可行性。
