## 目标与背景

布局基调已定（[UI 规范](../standards/ui.md)）：中央游戏舞台 + 右侧悬停可收起的对话面板。本 task 是**设计任务**：把面板状态机、双 register 的行类型细则、游戏进行中的输入交互敲定成结构文档——这是首个真实界面实现 task 的直接输入。

## 产出物

`ai-docs/architecture/ui-shell.md`（界面结构与交互规范），需敲定：

1. 舞台区：游戏主视图容器、尺寸 / 缩放策略、与面板的层叠与焦点关系。
2. 对话面板状态机：收起 / 悬停唤起 / 展开 / 钉住四态，触发区与阈值，收展动画参数（收展时长、曲线与位移量）。
3. 双 register 细化：行类型清单（玩家 / 角色 / 旁白 / 掷骰 / 判定 / 系统事件）↔ 视觉规则（气泡 vs 等宽行 / LED / 徽章），与 006 的记录块 / 预览 / 中断 / 未知 kind 语义完整映射；一个多段落事实块可拆多条视觉行，不要求物理一对一。
4. 输入区（composer）：面板内形态；游戏语境下的输入语义（对角色说话 / OOC 指令 / 骰子请求如何区分）。
5. 状态设计：空态、加载、流式中、错误态的面板表现。
