## 范围与非目标

交付：db::open 便捷封装和 open_with_progress 的已提交进度回调、只读 current_version、排序后的备份枚举，以及 store_list_backups / store_get_migration 命令。Rust 使用 Serialize 载荷，TS api/store.ts 同步类型和薄调用；接口形状、时间戳精度与列表上限只在通信契约维护。

setup 通过 OnceLock 注入业务库路径，重复注入保留首次值。新安装静态快照为版本 0 / idle，不创建目录或数据库。真实迁移事件、在飞状态及序号快照由 [022](022-record-engine-impl.md) 在 006 定稿后接入；greet 和 UI 占位的退役随 008。备份恢复 / 删除、剧本导入导出不在本任务。

## 实施步骤与改动

1. db.rs 提供纯数据回调、备份枚举和只读版本查询。
2. commands.rs / lib.rs 注入路径、注册命令并序列化明确的载荷类型。
3. api/store.ts 提供同型 TS 声明；测试覆盖调用、精度和拒绝透传。
4. 同步契约、架构导航和本任务，执行完整门禁。

## 风险与回退

READ_ONLY 保证不写入业务库和不执行迁移；SQLite WAL 读锁仍由 SQLite 管理。元数据、目录或库读取错误必须透传，不得伪装成版本 0 或空列表。静态快照不是运行期事件快照；022 启用发送方时必须同时扩展状态与序号基线。
