## 目标与背景

原有 emit_event 将事件准备与投递绑定，无法表示输出提交与一致快照确认的边界。本任务交付共享回合门禁、分步事件端口、运行期快照及薄命令适配。

[LLM 规则与结构](../architecture/llm.md) · [通信契约](../architecture/ipc-contract.md) · [职责边界](../architecture/ts-rust-boundary.md) · [Rust 规范](../standards/rust.md) · [前端规范](../standards/frontend.md) · [注释规范](../standards/comments.md) · [测试规范](../standards/testing.md) · [提交规范](../standards/commits.md)。依赖任务及后续设计定稿文档从[任务索引](../task-index.md)查阅；规则数值以架构 / 契约原文为准，不在 task 重写。

## 范围与非目标

- 引擎分配 UUID、冻结请求、共享前台回合门禁、终态裁决、有限 ring 与序号清退。
- 注入不依赖 Tauri 的输出写入 / 事件准备接口；内存调试写入方先落地，持久化写入方由 022 接入。
- LLM chunk / done / failed、get_turn / cancel、开发构建 submit 与原生 set_key 适配；生产不注册调试提交。

非目标：不冻结记录格式，不实现完整阶段机；内存调试不宣称记录持久化。

## 前置条件与待决策

018 / 019 完成后开始。与 022 预先约定输出写入接口；产品目标引用 006 已定稿的 GrammarSpec / GuardSpec，开发夹具只验证机制。按 012 的 public / private 输出策略预留同一协调器接口，子调用借用 lease；不实现阶段决策。

## 实施步骤

1. 创建纯 Rust 回合协调模块及输出 / 事件接口，Tauri adapter 负责现有窗口事件设施。
2. 把事件准备与投递拆开；实现预留、确认 / 废弃基线、失败快照和清退，保持现有发送方行为。
3. 接入薄命令并验证 cancel / finish / 写入失败竞争，以及应用关闭和真实窗口投递；首个真实发送方接入时移除 `src-tauri/src/lib.rs` 的 `TODO(task 020)` 与对应 `allow(dead_code)`。若该函数被新适配替代，删除旧函数，不留下无消费方的发送路径。

## 实施安排

依赖图及端口归属见[职责边界](../architecture/ts-rust-boundary.md#回合协调与端口依赖)。先建立与 Tauri 无关的协调器和 lease；序号预留、输出提交、快照确认及平台投递分步执行。调度器增加输出提交确认端口，确保首交付与重试边界由接纳结果决定；提交中的写入由串行所有者完成，不被用户取消丢弃。预算端口为每次物理尝试登记身份，尚未有 035 账本时仅运行本地夹具。然后接同型 Rust / TS 命令及真实主窗口烟测，最后整体复核和十三项验证。

## 改动范围

新增 `src-rust/mythos-engine/` 协调器、请求冻结和输出 / 事件端口；扩展 LLM 调度器的提交确认及物理尝试身份 / 生命周期，接入 Tauri 薄命令、同型 TS API 和真实主 Webview 集成夹具。同步 workspace、锁文件、聚合原生测试入口与依赖 / 目录文档。

## 验收标准

- [x] 重复提交原子拒绝 busy；输入校验失败不占门禁；取消与完成竞争只产生一个终态，旧 UUID 不复用。
- [x] 准备失败不写输出；写入失败不发对应 chunk；投递失败保持已提交文本及确认基线，废弃序号不复用。
- [x] 快照一致读取 text / outcome / 三事件基线；终态事件携带 chunkSeq；终态处理失败仍释放门禁。
- [x] ring 驱逐等待生产者退出并清理 seq；无锁跨 await；生产构建不暴露 llm_submit。
- [x] 内部提议与 public 正文复用门禁 / 请求策略，private 不泄漏到公开 ring / 事件 / partial，子调用借 lease 无死锁。
- [x] Rust 签名与 TS 类型在同次提交同步；真实主窗口投递烟测有记录。
- [x] llm.empty-output 的 failed 事件 / 快照均必有真实 finishReason 且同值；其他失败未知原因时省略，cancelled 不带该字段，覆盖 stop / guard / length 三条空输出路径。
- [x] 代码、注释、类型、文档与 task 同步；最终状态 `bun run verify` 全项通过。
