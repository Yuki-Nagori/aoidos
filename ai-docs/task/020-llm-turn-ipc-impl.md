## 目标与背景

现有 emit_event 尚不能覆盖准备载荷、预留序号、提交输出和快照确认的顺序。交付共享回合门禁、运行期快照及薄命令适配。

## 范围与非目标

- 引擎分配 UUID、冻结请求、共享前台回合门禁、终态裁决、有限 ring 与序号清退。
- 注入不依赖 Tauri 的输出写入 / 事件准备接口；内存调试写入方先落地，持久化写入方由 022 接入。
- LLM chunk / done / failed、get_turn / cancel、开发构建 submit 与原生 set_key 适配；生产不注册调试提交。

非目标：不冻结记录格式，不实现完整阶段机；内存调试不宣称记录持久化。

2. 把事件准备与投递拆开；实现预留、确认 / 废弃基线、失败快照和清退，保持现有发送方行为。
3. 接入薄命令并验证 cancel / finish / 写入失败竞争，以及应用关闭和真实窗口投递；首个真实发送方接入时移除 `src-tauri/src/lib.rs` 的 `TODO(task 020)` 与对应 `allow(dead_code)`。若该函数被新适配替代，删除旧函数，不留下无消费方的发送路径。

## 验收标准

- [ ] 重复提交原子拒绝 busy；输入校验失败不占门禁；取消与完成竞争只产生一个终态，旧 UUID 不复用。
- [ ] 准备失败不写输出；写入失败不发对应 chunk；投递失败保持已提交文本及确认基线，废弃序号不复用。
- [ ] 快照一致读取 text / outcome / 三事件基线；终态事件携带 chunkSeq；终态处理失败仍释放门禁。
- [ ] ring 驱逐等待生产者退出并清理 seq；无锁跨 await；生产构建不暴露 llm_submit。
- [ ] 内部提议与 public 正文复用门禁 / 请求策略，private 不泄漏到公开 ring / 事件 / partial，子调用借 lease 无死锁。
- [ ] Rust 签名与 TS 类型在同次提交同步；真实主窗口投递烟测有记录。
- [ ] llm.empty-output 的 failed 事件 / 快照均必有真实 finishReason 且同值；其他失败未知原因时省略，cancelled 不带该字段，覆盖 stop / guard / length 三条空输出路径。
- [ ] 代码、注释、类型、文档与 task 同步；最终状态 `bun run verify` 全项通过。
