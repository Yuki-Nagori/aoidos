## 范围与非目标

- 薄 API 与 Rust 同型声明、LLM 事件订阅和清理。
- 先订阅 / 有界缓存 / 快照替换 / 按基线消费；序号缺口与终态 chunkSeq 校验。
- 每回合单个快照请求、恢复代次、旧响应拒绝、窗口重连及主动恢复。

非目标：不新增游戏 UI 页面、不引入轮询恢复、不从 Webview 输入明文密钥。

## 实施步骤

1. API 只透传 invoke，消费算法进 utils，监听生命周期放 composable。
2. 用可控事件和延迟快照验证切换回合、缓存溢出、丢 chunk、旧响应与终态恢复。
3. 通过真实窗口 smoke 确认取消订阅、重连和恢复；同步错误展示与接口说明。

## 验收标准

- [ ] 订阅期间到达的事件不丢失；重复 / 旧事件不重复追加正文，终态正文缺失先恢复再展示完成。
- [ ] 快照请求不随事件数量无限增长；回合切换后的旧响应不能覆盖当前状态，确认基线不倒退。
- [ ] 缓存和正文有界；组件卸载释放所有监听，API 类型与 Rust 保持同型。
- [ ] 最后所有事件丢失的限制如实保留；重连 / 主动恢复可获得终态，不暗加持续轮询。
- [ ] failed 空输出的 finishReason 从事件 / 快照一致消费，区分 stop / guard / length；旧快照或取消不得残留上个终态的 finishReason。
- [ ] 代码、注释、类型、文档与 task 同步；最终状态 `bun run verify` 十项通过。
