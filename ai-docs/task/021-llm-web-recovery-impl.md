## 实施步骤

1. API 只透传 invoke，消费算法进 utils，监听生命周期放 composable。
2. 用可控事件和延迟快照验证切换回合、缓存溢出、丢 chunk、旧响应与终态恢复。
3. 通过真实窗口 smoke 确认取消订阅、重连和恢复；同步错误展示与接口说明。

## 实施安排

纯消费规则与注入式恢复协调放 utils，Vue composable 仅负责响应式身份、真实事件监听及卸载清理。先完成三类订阅再取快照；订阅准备和快照期间使用同一有界缓存。每轮恢复合并事件需求，响应已覆盖需求时不追加请求；仍落后时最多一次普通补取；终态在补取发出后才到达时，再允许一次终态后的读取。仍未追平则保留确认状态并等待新事件或主动恢复，防止旧快照造成持续轮询。回合切换和重连使用代次拒绝旧响应；同 UUID 跨代次也等待旧读完成再发新读，未完成身份数限定为 32。恢复错误保留已确认正文。

## 改动范围

新增 `utils/turn-consumer.ts`、`utils/turn-recovery.ts` 与 `composables/useLlmTurn.ts`，扩展 LLM 薄事件 API 及镜像单测。真实主 Webview 装载同一产品消费者，聚合原生入口先构建夹具资产到忽略目录。补齐仓库脚本类型检查与 import 类型标注规则，同步链路、目录、测试及数据根 / 凭据保护说明；修复 issue #68 的技术栈遗漏。

## 验收标准

- [x] 订阅期间到达的事件不丢失；重复 / 旧事件不重复追加正文，终态正文缺失先恢复再展示完成。
- [x] 快照请求不随事件数量无限增长；回合切换后的旧响应不能覆盖当前状态，确认基线不倒退。
- [x] 缓存和正文有界；组件卸载释放所有监听，API 类型与 Rust 保持同型。
- [x] 最后所有事件丢失的限制如实保留；重连 / 主动恢复可获得终态，不暗加持续轮询。
- [x] failed 空输出的 finishReason 从事件 / 快照一致消费，区分 stop / guard / length；旧快照或取消不得残留上个终态的 finishReason。
- [x] 代码、注释、类型、文档与 task 同步；最终状态 `bun run verify` 十三项通过。

## 风险与回退

事件与快照异步乱序容易覆盖新状态；使用回合身份和恢复代次，失败时保留最后确认正文。回退代码时同步撤销接口 / 依赖与文档；已有存档和凭据不因回退删除。
