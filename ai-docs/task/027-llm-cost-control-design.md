## 目标与背景

用户确认周目 / 全应用自然月额度都按费用控制，默认金额由默认 Token 用量和参考模型计价计算，用户界面以金额为主。Token 保留原始计量及单次输入 / 输出限制，不设第二套累计 Token 额度。独立计价模块负责用量换算，价格版本不修改原始 Token 用量。

## 范围与非目标

设计费用统计、模型计价版本、周目 / 自然月费用上限、预留 / 结算与用户展示。非目标：本次实现代码；购买额度 / 支付；修改原始 Token 用量；承诺供应商实际账单绝不超额。

## 前置条件与待决策

依赖 007 的统一请求身份与预算边界。计价数据需设计时核验供应商官方资料，不在当前记录中预填价格。待定缓存版本 / 更新失效协议、汇率来源 / 币种修改生效 / 金额精度、手动价格适用范围 / 过期、usage 不完整、额度值 / 参考 Token 分配与模型、上限修改生效 / 提示状态更新、缓存 / 推理用量及周期身份 / 时区切换衔接协议（请求发出时所属月份与周目归属已确认）。

## 产出物

1. 独立计价模块职责：物理请求用量与计价版本关联，不保存密钥，不将估算冒充实际账单。
2. 周目 / 自然月金额双重检查、参考 Token × 模型计价生成固定默认金额；换模型不自动改限额，每次物理请求冻结计价并累计费用，不能用新价格重算旧请求。
3. 预留 / 结算 / 未确认消耗协议：预算时区初始取系统并保存、设置可手动调整、自然月刷新，跨月请求按发出时周期结算；避免重复回调、恢复和重试漏记或重扣。
4. 预算币种可设置，首版 CNY / USD，中文语言默认 CNY、其他默认 USD，手动选择优先；格式化消费 028 契约。用户金额主视图及供应商 / 模型用量明细：已用费用、输入 / 输出 / 总 Token、物理请求次数；按周目 / 自然月查看，详情保留请求计价版本 / 单价和数据状态。80% 预警去重，未知用量 / 费用不显示为零。
5. 登记并校验成功后持久保存模型 / 计价配置，缓存复用、修改后更新、重启恢复；按供应商 / 模型区分，不混入密钥、不改旧请求冻结价格。
6. 规则与结构文档、验证计划；评审后再规划实现 task，不预建不存在的 API。

## 验收标准

- [ ] 计价与原始用量分离，价格变化不修改已保存 Token 消耗。
- [ ] 周目 / 自然月费用限制、默认金额计算及未知价格 / 用量的行为明确；未登记模型 / 必要价格缺失时强制补齐并校验，完成前不发送请求，不套其他价格或默认填零。
- [ ] 用户必须填写未登记模型的计价信息；历史未计价可手动补价，仅回填适用范围内未计价请求，保持原周期 / 原始 usage，已结算请求不按新价格重算。
- [ ] 月额度下未知价格主动提示补充，填写完成前不发请求；历史未计价小计 / 预警说明不完整。
- [ ] 来源、逐请求计价版本、模型切换后的合计、重复 / 恢复 / 跨周期及统计总量可核验。
- [ ] 默认金额换模型不自动变化，两个作用域 80% 提醒不重复弹出，预警不替代额度拒绝。
- [ ] 用户同时看得到费用和 Token，供应商 / 模型明细与同范围请求账本汇总一致，详情可核验计价依据。
- [ ] 设置可手动选择预算时区，设备时区变化不自动刷新；手动修改下一预算月生效并展示生效时间，当前月账本不变；跨月回调更新原周期，旧预留 / 未确认消耗不清零。
- [ ] 预算币种首版 CNY / USD 可设置，中文默认 CNY / 其他 USD，手动选择不因语言切换覆盖；每请求计价 / 汇率冻结，旧账不重算。
- [ ] 官方价格资料有核验日期；本地估算局限如实保留。
- [ ] 模型 / 计价信息缓存复用，供应商身份隔离，更新不改旧请求；登记成功后持久保存 / 重启恢复，修改使旧缓存失效，不混入普通缓存密钥。
- [ ] 文档评审通过，另行登记实现任务。

## 风险与回退

价格变更或 usage 缺失会影响费用估算准确性。提供计价状态与版本信息，不以估算代替账单；未登记 / 必需计价缺失时先填写，不以缺价放行；历史未计价标明合计不完整，Token / 上下文硬限保留，手动补价不编造用量或修改已有结算价格。
