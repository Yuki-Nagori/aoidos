# 027 — 设计：LLM 费用统计与费用控制

## 目标与背景

用户确认每局分别设置 CNY 与 USD 两个原币费用上限，不设全应用月度总额度。请求费用按实际服务商计价币种记录，并且只占用该局同币种上限；不换算、不互借。月报按服务商与原币统计，模型作为明细维度，不生成跨币合计。Token 保留原始计量及单次输入 / 输出限制，不设累计 Token 额度。

## 范围与非目标

设计费用统计、模型计价版本、每局分币种上限、预留 / 结算与用户展示。自然月只用于全应用报表分组，不设月度上限。非目标：本次实现代码；购买额度 / 支付；修改原始 Token 用量；承诺供应商实际账单绝不超额。

## 前置条件与设计结论

005 / 007 / 028 已定稿，精确协议见[计价与预算架构](../architecture/billing.md)。每局分别设置 CNY、USD 上限，各自按对应服务商原币费用检查；默认值分别由同币种参考 Token 与模型价格生成。账本及月报不换算、不跨币相加；月报按服务商和币种统计。PriceVersion、NanoMoney、发送意图持久预留、幂等结算、报表周期和可选余额均已定义。实施由 035 承接，当前不安装依赖、不发送收费请求。

## 产出物

1. 独立计价模块职责：物理请求用量与计价版本关联，不保存密钥，不将估算冒充实际账单。
2. 每局 CNY / USD 上限独立检查，分别用同币种参考 Token × 模型计价生成固定默认金额；换模型不自动改限额，每次物理请求冻结原币计价，只预留到对应币种上限。
3. 预留 / 结算 / 未确认消耗协议：报表时区初始取系统并保存，可手动调整；自然月只用于全应用统计。跨月请求按发送时刻归入月报，不存在月额度刷新；避免重复回调、恢复和重试漏记或重扣。
4. 每局分别设置 CNY / USD 上限，请求只消耗服务商该笔账单对应币种额度，不换算、不互借。用户按服务商和模型查看原币费用、输入 / 输出 / 总 Token、物理请求次数；全应用月报按服务商与原币统计，不设总上限、不跨币相加。CNY / USD 各自的 80% 预警按单局去重，未知用量 / 费用不显示为零。
5. 登记并校验成功后持久保存模型 / 计价配置，缓存复用、修改后更新、重启恢复；按供应商 / 模型区分，不混入密钥、不改旧请求冻结价格。
6. 规则与结构文档、验证计划；评审后再规划实现 task，不预建不存在的 API。

## 风险与回退

价格变更或 usage 缺失会影响费用估算准确性。提供计价状态与版本信息，不以估算代替账单；未登记 / 必需计价缺失时先填写，不以缺价放行；历史未计价标明合计不完整，Token / 上下文硬限保留，手动补价不编造用量或修改已有结算价格。
