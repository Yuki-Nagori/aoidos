## 目标与背景

用户要求筹备 i18n。本任务定稿语言 / 文案 / 格式化与偏好契约，由独立实施任务 034 交付运行时并完成验收；语言不决定模型价格币种或费用额度币种。

## 范围与非目标

设计范围包括语言选择 / 偏好持久化、文案资源与类型检查、缺失翻译回退、数字 / 金额 / 日期格式化、错误码映射、无障碍文案及应用启动对接；运行时由 034 实施。非目标：自动翻译玩家原文 / 记录 / 剧本内容；隐式改变模型生成语言；账号 / 云同步。

## 前置条件与设计结论

首版 zh-Hans / en，以英文资源作为源码与类型基准，简体中文由门禁逐键校验；system 由 Rust 检测。vue-i18n v11 预编译、独立 LocalePreference / LocaleBootstrap、原生单源资源、精确金额显示与错误码映射见[国际化架构](../architecture/i18n.md)。与 026 共用首窗初始化，025 消费底座，034 承接独立实施。没有有效偏好或 bootstrap 时确定性回退到英文；正常启动使用 Rust 持久化偏好及首帧 bootstrap。依赖已由 034 引入并验收。

## 产出物

1. i18n 规则与结构文档：locale、语言优先级 / 切换 / 回退、资源组织和命名、插值 / 复数及类型检查。
2. 文案归属：前端展示文本、脱敏错误码映射、设置 / 预警 / 待确认 / 辅助技术文案；不改变机器 ID、协议枚举、记录原文或日志事实。
3. 格式化与业务数据分离：界面 locale、金额自身币种、报表时区分别传入；金额精度与原始数值不因显示格式变化。不同币种各自显示，不相加或换算。
4. 偏好持久化 / 跨端同型 / 启动与更新协议，避免重复修改主题或业务偏好文件。
5. 当前示例与 025 正式界面的接入主责、资源完整性 / 缺键 / 切换 / 格式化验证，评审后新增实现 task 并同步依赖。

## 风险与回退

界面语言、剧本语言和计价币种混用会改变玩家原文或历史金额。保持输入事实与机器标识独立，翻译只影响展示；缺失翻译显式回退，不因格式化失败改写业务数据。
