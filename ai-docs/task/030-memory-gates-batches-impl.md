# 030 — 实现：记忆门控与授权批次

## 目标与背景

实现可信获知证据、来源片段、严格候选协议、实体 / 别名 / 待确认以及独立授权处理批次。本任务承接 [007](007-memory-design.md) 的阶段 B。043 已提供统一实体注册表；批次、候选协议和恢复等范围继续独立推进。获知证据与别名消费当前有效目录并分别执行权限校验；观察 / 传闻证据只消费 045 产生的权威事件，不反向参与场景或事件生产。

范围：下述实施步骤和验证。非目标：不实现高级 UI、向量检索、投影热路径、权威实体自动创建或独立计价。

## 前置条件与待决策

027 已定稿；035 的计费端口已合并并标记 `implemented`，本任务可据其接口开展实现与本地测试；043 的统一注册表已可供实体来源、角色证据和别名实现消费。030 的大部分实现不等待 045；仅观察 / 传闻证据验收依赖 044 协议及 045 权威事件源。收费批次仍须等 035 完成三平台实机验收并取得明确用户授权后才能开始；本任务开发期间只使用 mock / 本地夹具，不发起供应商收费请求。工程预算与算法开发值按 007 / 算法文档执行；生产默认只能由独立实验报告审定。实现中发现设计冲突先同步文档，不静默扩大权限。

- [x] 实现待确认问题持久化：稳定事件身份、严格类型候选、候选变化递增 revision、来源复核、历史 / 目录版本 CAS、迟到回答拒绝及每周目 512 项上限；可选提及名称须能从原始来源逐字复现。

- [x] 补齐待确认失效 / 恢复协调与面向 UI 的有界分页；过期来源 / 可信版本转 invalidated，分页最多返回 32 项、单次扫描 256 项，序号游标固定分页快照上界。
- [x] 实现纯定点强度计算：输入冻结策略、有效强化和逻辑锚点，覆盖指数、分段及无衰减策略；不负责核验来源、选择归档或写入效果。
- [x] 实现纯归档选择：必需优先，其余按强度、最近有效素材逻辑位置和 ID 字节序稳定排序；仅消费调用方已过滤的有效候选，必需条目超容量时拒绝。
- [x] 实现纯依赖组规划：共享素材或目标的候选合为原子组，按原始素材位置及 candidateId 稳定排序，每组最多触及 16 个条目。
- [x] 将候选与操作计划 / 恢复建立持久关联；批次候选绑定唯一操作，完成摘要声明 `applied` 前必须核验对应操作及提交回执，prepared / ready 操作保持批次未完成并可恢复。
- [x] 增加显式调用的授权批次执行入口：共享 `Coordinator` 空闲后取得 lease，沿用请求携带的 027 预算端口，在发送前持久登记唯一 turnId / requestId；单次 private 请求完成后保存 `received` 回执，结果不确定时记 `unknown`，不重发。不增加 012 第四次调用；无自动触发，真实供应商授权门仍关闭。
- [x] 实现别名幂等 / 撤销与来源回退重建：别名身份与来源支持分开保存，重复确认不重复写支持，修订 CAS 控制撤销 / 重新确认；读取时仅使用当前有效来源。
- [x] 持久保存 localDeferred 原因，并允许已完成批次仅从原始响应 / 冻结输入本地重新核验；原回执不变，不重新发送或定时重试。

## 预计改动

业务逻辑位于 `src-rust/aoidos-memory`，依赖 `aoidos-store` 的共享 SQLite / 原子存储边界；引擎在统一迁移列表追加批次回执、问题队列、候选—操作关联和旧回执兼容迁移。升级前完成的结果仅标记为历史数据并保持可读，不推造操作映射；新批次按严格关联规则校验。正式回合入口支持可选的固定场景角色接收对象，TS / Tauri / Rust 契约已同步；动态在场 / 可信获知事件协议归 044，事件生产归 045，030 单向消费可信事件，角色选择 UI 归 046，记忆专属 IPC 归 031，不扩大 025 / 023 范围。
