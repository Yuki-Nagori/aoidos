## 目标与背景

实现规则授权刻痕、独立生命周期、可信节点进展和有界停滞提示。本任务承接 [007](007-memory-design.md) 的阶段 D；动态 NPC 只有经 043 登记并具有稳定身份后，才可作为轮回刻痕对象；是否继承仍由本任务中的剧本规则授权，不能按名称匹配。设计定稿不表示运行时已实现，依赖未满足前不提前开工。

## 范围与非目标

范围：下述实施步骤和验证。非目标：不实现检索 / 动态注入，不继承旧世界状态，不加入第二套场景判定和自动晋级。

## 前置条件与待决策

可信剧本规则 / 证据接口由 023 提供；新增标记 / 规则字段必须类型化登记，模型不能填权威 priority。工程预算与算法开发值按 007 / 算法文档执行；生产默认只能由独立实验报告审定。实现中发现设计冲突先同步文档，不静默扩大权限。

## 实施步骤

1. 实现 CycleMarkV1、规则 / 对象 / imprintKey 稳定身份、来源分支锚点与可见对象；刻痕摘要沿用现有记忆请求，不另发模型请求，所有授权字段由引擎提供。
2. 同 ID 合并有效来源，按可信 priority / cycleGen / ID 排序，容量满归档不删除原始来源。
3. 保存 / 查询刻痕及准备投影端口，未经独立投影设计不注入热路径或修改现有 staticPrefix。
4. 消费 023 交付的 SceneRuleView / SceneRuleMatch，只维护派生进度 / 提示，规则持续为 true 或依据重复不算新进展；节点实例以当前分支修订和有效 SceneAdvanced 记录序号共同标识，完成回合校验 RoundAccepted 属于该进入实例，再以有效 RoundEnded 记录序号单调推进；roundId 重放幂等，OOC / 失败 / 回退分支不计。
5. 提示来自已登记规则和固定文本，冷却 / 次数有界，不额外调用模型、不伪造出口或世界结算。
6. 在来源记录追加前持久化生命周期事件，单项最多 64 KiB、每周目最多 128 项；记录确认后按当前有效分支经 `SourcePort` 重验并消费。启动 / 回退清理孤立或失效事件、补建当前节点基线；失败保留待处理项，不把已提交事实回报为失败。

## 预计改动

轮回刻痕与节点状态扩展现有 `src-rust/aoidos-memory`，Rust 实体身份由 043 提供，存储原语复用现有 aoidos-store；引擎侧只做可信规则结果装配，涉及命令时只在 src-tauri 做薄转发。尚未实现的 DTO / 子模块按实际落点在实施时登记，不能把已有记忆 crate 或存储能力描述为不存在；实现 commit 同步架构、契约与 task。
