## 实施步骤

1. 建立纯业务计价模块，集中 workspace 的 rust_decimal / jiff，单一 store 服务分配迁移；价格 / 汇率 / 日历不可变并有界校验。
2. 实现 NanoMoney、usage 映射、预估上界、最高价预留、两分配原子 CAS 与未知消耗恢复。
3. 接入每次物理尝试的发送意图 / 结算 / 重试，统一剧情、整理、调试与后续记忆端口，不保存敏感正文。
4. 实现周目 / 月份 / 时区 transition / 币种生效、revision 设置、80% 去重与历史补价审计。
5. 同 commit 定型 IPC / Rust / TS 类型；接 025 设置、分页明细、金额与 Token 同时显示，034 错误本地化。
6. 可选余额按白名单能力接入 019 凭据，显式查询与自愿有界对账，覆盖 unknown / stale / quota 与管理权限。
7. 运行故障矩阵、三平台展示及全量门禁，公布估算限制与未验证适配器。

## 验收标准

- [ ] 默认金额固定、未知价 / 汇率发送前阻止；价格更新不改原始 usage 或历史结算。
- [ ] 两作用域事务一致、每个重试独立预算；重复 / 冲突回调与提交不确定不重扣，恢复不重发。
- [ ] 合法正文完成与费用状态独立，用量异常不重生成或撤回正文；取消 / 无 usage 保留未知占用，实际超预留完整记录并阻止新请求，不伪退款。
- [ ] 跨月、时区 transition、DST、时钟回拨、币种 / 上限修改与迟到结算符合冻结归属。
- [ ] 精确金额无溢出 / f64 损失；Token 归一化不重加缓存 / reasoning，明细与账本一致。
- [ ] 80% 去重 / 历史补价审计 / revision 分页有效，未知消费不显示零或完整小计。
- [ ] 余额权限 / 解析 / 凭据变更 / stale / unavailable / 退避与卸载有夹具；不支持适配器不抓网页、不改本地账本。
- [ ] 三平台展示留证；代码、注释、类型与文档同步，最终 bun run verify 全项通过。
