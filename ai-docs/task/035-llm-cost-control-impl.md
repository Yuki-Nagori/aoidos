# 035 — 实现：LLM 计价与费用控制

- 状态：implemented
- 依赖：027、013、018、019、020、025、034、042
- 优先级：P2
- 创建 / 更新：2026-10-06 / 2026-10-21

## 目标与背景

交付 [计价与预算](../architecture/billing.md)的统一费用端口，剧情与记忆共用金额额度。027 已完成设计；当前已有精确计价、SQLite 原币账本、物理请求预算端口、IPC 与费用面板。OpenCode Zen / Go 的 Provider 由 042 提供；本任务负责匹配其模型费率、缓存写入用量和 Go DeepSeek 峰谷费率。Go token 费率只估算模型额度使用，不追踪 Go / Go Plus 固定订阅费用。历史恢复只处理完整持久用量和原冻结价格仍可验证的记录；余额查询首版仅支持玩家主动查询 DeepSeek 官方接口。三平台实机 UI 展示留证仍待补，故标为 implemented 而非 done。

## 范围与非目标

不可变价格 / 时段与登记缓存、原币账本、每局 CNY / USD 独立上限、统一调用预留与结算、费用设置 / 明细 / 提醒、受限历史恢复与 DeepSeek 余额查询。价格按实际服务商接入方式选择来源；OpenRouter 未作为当前产品 Provider 接入，相关多上游保守费率规则仅在未来增加该 Provider 时生效；OpenCode Zen 与 Go 分别计价。Go 模型按官方每模型 token 费率估算额度使用；订阅费用不纳入 Aoidos 计费功能。Go DeepSeek 按 UTC 峰 / 非峰时段分别计价，Zen fallback 如有可验证记录则计入 Zen，不推断控制台账单。请求费用始终按服务商实际账单币种保存，并只占用同币种额度，不换算、不互借。全应用月报不设上限，按服务商和原币统计。非目标：订阅费用统计、支付 / 充值、外部账单同步、汇率服务、累计 Token 限额、未授权付费测试。

## 前置条件与待决策

020 的物理尝试生命周期与租约、019 原生凭据、025 设置容器和 034 格式化完成。025 的实现已交付并通过仓库内验证；其三平台实机验收仍待补，但不属于费用功能实现前置，本任务接受 025 的 `implemented` 状态。费用 UI 仅消费现有设置容器，不改变或宣称 025 的平台验收结果。接入前核验官方价格、节假日覆盖及余额权限；内置条目必须有来源 / 日期，不以设计例子代替发布价格。020 预留端口，035 注入真实账本，不反向增加 020 依赖造成循环；035 之前只有本地夹具，禁止将未计费产品链路宣称可安全付费发布。

## 实施步骤

1. 建立纯业务计价模块，集中 workspace 的 rust_decimal / jiff，单一 store 服务分配迁移；价格 / 日历不可变并有界校验。PriceVersion 绑定服务商接入方式、部署、模型、路由策略、价格来源与实际计价币种；不实现跨币汇率。
2. 实现 NanoMoney、usage 映射（含输入缓存写入）、预估上界、按请求币种匹配单局 CNY / USD 上限的预留、原子 CAS 与未知消耗恢复。
3. 接入每次物理尝试的发送意图 / 结算 / 重试，统一剧情、整理、调试与后续记忆端口，不保存敏感正文。
4. 实现单局双币种上限与 revision 设置、自然月报表分组 / 时区、各币种独立 80% 去重与历史补价审计。
5. 同 commit 定型 IPC / Rust / TS 类型；接 025 设置、分页明细、金额与 Token 同时显示，034 错误本地化。
6. 首版仅接 DeepSeek 官方只读余额接口；用户显式查询、内存缓存与退避，不影响预算门禁，不抓取控制台网页或猜测其他 Provider 的余额 API。
7. 接入 OpenCode 官方每模型价格；OpenCode Go 和 DeepSeek API 分别按官方峰谷日历及 `dispatchAt` 选择费率，对在飞请求冻结价格版本；中国公众假日表版本化且只用于 DeepSeek API；界面按已选报表时区显示转换后的峰时段；Zen / Go 价格身份隔离。
8. 运行故障矩阵、三平台展示及全量门禁，公布估算限制与未验证适配器。

## 验收标准

- [x] 每局分别保存 CNY / USD 上限，分别由同币种参考 Token / 模型价格生成默认值；请求只占用服务商账单币种对应上限，不换算、不互借。未知价格或对应上限配置缺失时发送前阻止；价格更新不改原始 usage、原币费用或既有局次。
- [x] 单局对应币种的预留与结算在事务内一致、每个重试独立预算；重复 / 冲突回调与提交不确定不重扣，恢复不重发。
- [x] 合法正文完成与费用状态独立，用量异常不重生成或撤回正文；取消 / 无 usage 保留未知占用，实际超预留完整记录并阻止新请求，不伪退款。
- [x] 能证明发生在 `provider.start` 调用前的取消以 `notDispatched` 结算零 usage 并释放预留；进入 provider 调用后不从超时、取消或网络错误推断未发送。
- [x] 完整 usage 的结算计算 / 存储失败和冲突不得静默丢弃；提供有界可见诊断与不重发请求的恢复路径，且不改变已提交正文终态。恢复只读本地暂存用量与冻结价格，不请求供应商 API；待恢复与未决请求共用 256 条硬上限，达到上限后在发送前拒绝新请求。
- [x] 跨月报表、时区、DST、时钟回拨、两币种上限修改与迟到结算符合归属；时区只影响月报分组，不改变上限或原币账本。
- [x] 精确金额无溢出 / f64 损失；Token 归一化不重加缓存 / reasoning，明细与账本一致。
- [x] Provider 上报的缓存创建 Token 和对应 cache-write price 独立入账；Go DeepSeek 周一至周五 UTC 01:00–04:00、06:00–10:00 使用官方 peak price，其余时段使用 off-peak price；DeepSeek API 另排除中国公众假日并按已核验年份日历判定；每个请求冻结 `dispatchAt` 对应价格版本，界面将 UTC 窗口换算到用户选定报表时区显示。
- [x] OpenCode Go / Go Plus 的模型 usage 按官方 token 价估算额度使用，不展示或计入固定订阅费用。Zen 与 Go 的价格、请求、费用身份不串用；fallback 不确定时标为未确认而不虚构实际 Zen 余额扣费。
- [x] 计价身份绑定服务商、精确模型和路由策略；界面语言不推导服务商计价币种；来源、模型和路由策略无法对应或账户计价币种未知时，必须登记 / 确认后才放行。未来若增加 OpenRouter 多上游路由，需先落实保守预留或固定路由，不把该能力误记为当前已支持。
- [x] 当前产品不支持多上游 OpenRouter 路由；未来启用前，必须覆盖所有允许路由的有效保守上界，或固定路由 / 要求明确登记费率。
- [x] 玩家可分别设置每局 CNY / USD 上限；服务商请求只计入匹配币种。费用列表按服务商、原币和模型分组显示；不设全应用总上限、不换算或生成跨币总额。
- [x] 80% 去重 / 限定历史恢复审计 / revision 分页有效，未知消费不显示零或完整小计。
- [x] DeepSeek 余额权限 / 解析 / 凭据身份隔离 / stale / unavailable / 退避有夹具；其他 Provider 隐藏余额入口，不抓网页、不改本地账本。
- [x] CNY / USD 分桶均可独立设置、预留、结算、提醒、查询与格式化；当前局上限修改提交后即时生效且不返还费用；界面金额以 0.01 显示，异币种不能比较 / 相加，系统不暴露统一跨币总额。
- [ ] 三平台桌面实机展示留证。
- [x] 代码、注释、类型与文档同步；最终 `bun run verify` 全项通过。

## 风险与回退

- 2026-10-11：缓存写入费率通过追加 SQLite 迁移扩展。旧价格版本和旧请求的新增列保持 NULL；旧价格不能用于新预留，用户需登记明确写入费率（不收费也要显式登记 0）。在迁移前已发送的请求仍按原始未知状态处理，不能推断其缓存写入量或补算费用。

供应商价格 / usage 与估算可能偏离实际账单。已发生消费保留，未知不清零；只撤回新请求能力与失效依赖 / 接线，不能回退账本以退款。真实付费实验须明确用户授权及费用边界。
