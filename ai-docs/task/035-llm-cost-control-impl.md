## 范围与非目标

不可变价格 / 时段与登记缓存、原币账本、每局 CNY / USD 独立上限、统一调用预留与结算、费用设置 / 明细 / 提醒、历史补价与可选余额。价格按实际服务商接入方式选择来源，OpenRouter 只服务于 OpenRouter 接入，不作为全局价格基准；请求费用始终按服务商实际账单币种保存，并只占用同币种上限，不换算、不互借。全应用月报不设上限，按服务商和原币统计。非目标：支付 / 充值、外部账单同步、汇率服务、累计 Token 限额、未授权付费测试。

4. 实现单局双币种上限与 revision 设置、自然月报表分组 / 时区、各币种独立 80% 去重与历史补价审计。

6. 可选余额按白名单能力接入 019 凭据，显式查询与自愿有界对账，覆盖 unknown / stale / quota 与管理权限。

## 验收标准

- [ ] 每局分别保存 CNY / USD 上限，分别由同币种参考 Token / 模型价格生成默认值；请求只占用服务商账单币种对应上限，不换算、不互借。未知价格或对应上限配置缺失时发送前阻止；价格更新不改原始 usage、原币费用或既有局次。
- [ ] 单局对应币种的预留与结算在事务内一致、每个重试独立预算；重复 / 冲突回调与提交不确定不重扣，恢复不重发。
- [ ] 合法正文完成与费用状态独立，用量异常不重生成或撤回正文；取消 / 无 usage 保留未知占用，实际超预留完整记录并阻止新请求，不伪退款。
- [ ] 跨月报表、时区、DST、时钟回拨、两币种上限修改与迟到结算符合归属；时区只影响月报分组，不改变上限或原币账本。
- [ ] 精确金额无溢出 / f64 损失；Token 归一化不重加缓存 / reasoning，明细与账本一致。
- [ ] 直连与 OpenRouter 路径的同名模型不能串用价格；界面语言不推导服务商计价币种；来源、模型和路由策略无法对应或账户计价币种未知时，必须登记 / 确认后才放行。
- [ ] 多上游路由费率不同时，预留覆盖所有允许路由的有效保守上界，或固定路由 / 要求明确登记费率；不能拿 OpenRouter 单一目录价替代无法确认的本次路由成本。
- [ ] 玩家可分别设置每局 CNY / USD 上限；服务商请求只计入匹配币种。模型详情 / 全应用月报按服务商和原币种分组，模型作为下钻明细；不设全应用总上限、不换算或生成跨币总额。
- [ ] 80% 去重 / 历史补价审计 / revision 分页有效，未知消费不显示零或完整小计。
- [ ] 余额权限 / 解析 / 凭据变更 / stale / unavailable / 退避与卸载有夹具；不支持适配器不抓网页、不改本地账本。
- [ ] CNY / USD 分桶均可独立设置、预留、结算、提醒、查询与格式化；当前局上限修改提交后即时生效且不返还费用；界面金额以 0.01 显示，异币种不能比较 / 相加，系统不暴露统一跨币总额。
- [ ] 三平台展示留证；代码、注释、类型与文档同步，最终 bun run verify 全项通过。
