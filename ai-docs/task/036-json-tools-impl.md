## 目标与背景

023 的内部提议借用了记录 JSONL 解码并人为追加 LF；用户要求把共用 JSON 能力独立，并扩展到现有 Rust 消费方。统一递归重复键校验、输入容量、编解码、显式规范化与静态错误类别，领域协议继续由各模块维护。

## 必读

[架构总览](../architecture/README.md#json-共用能力) · [职责边界](../architecture/ts-rust-boundary.md) · [Rust 规范](../standards/rust.md) · [注释规范](../standards/comments.md) · [测试规范](../standards/testing.md) · [提交规范](../standards/commits.md)。底层 API 使用 [Serde](https://serde.rs/) 与 [serde_json](https://docs.rs/serde_json/)，依赖版本以根锁文件为准。

## 范围与非目标

`aoidos-json` 提供有界 UTF-8 / JSON 解码、递归重复键拒绝、DTO 转换、紧凑编码与按对象键排序的规范化。迁移记录、配置、凭据、偏好、SSE、引用及 IPC 的共用编解码调用；023 后续使用本库解析提议与规范化计划摘要，接线和验收由 023 承接。

领域 schema、未知字段策略、JSONL 行约束、原始记录摘要、文件 / 网络 I/O 和错误码映射由消费方维护。公共 API 明确绑定 `serde_json::Value`；消费方直接依赖 serde_json，不转导出其类型或宏。保留 serde_json 默认递归限制，不实现另一套解析器。

## 前置条件与待决策

## 风险与回退

从宽松解码迁移后，重复字段将按原域的错误码拒绝，不能继续采用末键覆盖。对既有合法数据保留原格式和数字精度；回退须同提交撤销消费方调用与 Cargo 依赖，不删除文件或重新编码原始记录。
