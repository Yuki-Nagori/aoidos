# 043 — 实现：Rust 权威实体注册与动态 NPC 身份

## 目标与背景

建立由 Rust 管理的统一实体注册表，使剧本固定实体和引擎正式创建的动态实体拥有可验证、可恢复的稳定身份。`resources/scripts/<scriptId>/entities.json` 只作为固定实体的只读种子数据；它不承担运行时注册、动态 NPC 创建或记忆持久化。

该注册表为 030 的实体关联 / 获知证据和 032 的轮回刻痕提供统一身份边界。生成文本或记忆候选只能提出 NPC 创建意图；只有引擎按已登记规则提交的世界操作才能创建身份。名称不是身份，禁止以同名、近似名或描述相似自动合并实体。

## 范围与非目标

范围：Rust 实体注册表、固定目录种子装配、动态身份创建与稳定 ID、持久化 / 分支可见性 / 崩溃恢复、与 030 / 032 的只读快照接口。

非目标：记忆模型自行创建世界实体、名称近似自动合并、别名审批与问询（030）、轮回刻痕授权或投影注入（032）、完整作者规则解析及 NPC 生成 prompt。实体创建不授予任何角色获知事件的资格。

## 实施步骤

- [ ] Rust `EntityRegistry` 持有固定种子与动态实体的合并快照；固定种子来源按 scriptId 通用装配，不在记忆模块硬编码 Mistbell 资源路径。
- [ ] 静态 `scriptRevision` 与运行期 `entityRevision` 分离；动态创建不能改写脚本修订或打包资源，快照 revision 随已提交注册变化单调推进。
- [ ] 动态 ID 由 Rust 分配并绑定正确的游戏世界 / 周目身份；稳定 ID 不从模型名称或描述推导。实体名称仅用于按类型 / 范围查找与冲突校验。
- [ ] 仅经 023 的可信世界操作提交新实体；持久化操作与世界事实同事务或同恢复协议确认，使用稳定幂等键，未知提交状态不重复创建。
- [ ] 重开、回退、分支切换及确认恢复重建同一可见注册表；不确定、未提交或外分支创建不可被记忆消费。
- [ ] 提供有界、只读、版本绑定的完整注册表快照给 030 / 032；注册实体不自动证明角色看到、听到、认识或记住它。
- [ ] 对 032 提供稳定动态实体身份；是否形成跨轮回刻痕和新周目对象的可见权限仍由剧本授权规则决定，禁止以名称自动匹配不同身份。

## 验收标准

- [ ] 固定和动态实体共用 Rust 身份及冲突验证；新增动态实体不修改 `entities.json` 或 `scriptRevision`。
- [ ] 分支、崩溃、重开、重复提交和不确定提交状态均保持身份唯一且恢复幂等。
- [ ] 两个独立游戏世界的动态身份互不串用；同一授权世界内引用保持稳定。
- [ ] 未提交 NPC 提议、仅有名称相似或无可见依据的实体不能进入记忆证据或轮回刻痕。
- [ ] 更新架构依赖图、剧本规范、030 / 032 边界；代码、注释、类型、文档一致，最终 `bun run verify` 通过。

## 风险与回退

实体身份错误会把事实、角色认知和跨轮回记忆连接到错误对象。拒绝猜测合并；来源分支、注册 revision 或提交回执不能验证时失败关闭。脚本种子修订和动态注册状态分别恢复，不把旧注册表静默改写成新剧本身份。

## 决策与工作记录

- 2026-10-12：确定 Rust 注册表是运行期实体身份真源；剧本 `entities.json` 只提供人工审核的固定初始数据。动态 NPC 必须经引擎规则提交并持久化；030 / 032 只消费稳定 ID，不以名称自行创建或合并实体。
