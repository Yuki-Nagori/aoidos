## 目标与背景

030 的 Rust / Tauri / TypeScript 提交入口已允许玩家显式选择当前场景登记的固定角色，但完整目录身份不代表角色此刻在场。动态 NPC 也尚无可恢复的场景在场关系。需要先定稿可信在场状态、输入目标选择及其与 `told` 证据的边界，再由独立实现任务接入产品；不扩大 023 或已交付的 025。

## 范围与非目标

范围：设计可信场景在场集合及 revision、固定 / 动态角色进入与离开、当前输入目标选择和过期选择拒绝、目标如何沿恢复链保持，以及这些事实何时足以形成定向告知证据。

非目标：不实现运行时代码、动态 NPC 生成规则、记忆候选 / 别名处理或记忆专属 IPC；不将实体已登记、同场景或玩家自由文本自动视为角色观察 / 获知证据；不修改 023、025 的既有交付范围。

## 前置条件与待决策

008、012、023、043 已定稿 / 实现。当前 030 明确接收对象的后端入口由 045 消费；记忆专属命令与查询由 031 接入。设计需检查 SceneCatalog / WorldMutation / 有效因果路径的现有能力，缺少可信状态载体时先定其单向扩展点，禁止 UI 成为在场状态来源。

## 设计产出

1. 冻结场景在场身份的权威来源、固定 / 动态角色成员关系、进入 / 离开规则、状态 revision 和分支回退 / 恢复行为。
2. 定义受限的角色可选项快照及 stale / absent / unknown 选择处理，保证拒绝发生在玩家输入追加前，并沿 023 回合恢复保持已接纳目标。
3. 区分“向角色说话”的 `told` 证据与观察 / 传闻：仅在何种引擎登记事件、当前在场和完整回合终态下建立；身份存在和场景共同出现本身不授予知识。
4. 更新 `turn-state-machine.md`、`ui-shell.md`、`memory.md`、`ipc-contract.md` 与架构总览；记录依赖图，确保 043 → engine → Tauri / TS 单向，无 023 / 025 回环依赖。

## 验收标准

- [ ] 在场状态由 Rust 可信规则 / 已提交记录建立；UI 只能读取和请求，不直接添加身份或修改成员关系。
- [ ] 固定 / 动态身份共用稳定 ID；离场、回退、重启和旧选择行为有明确结果，不把注册身份等同于当前可交互。
- [ ] 回合接收者与获知证据条件严格区分；旁白、非场内输入、失败 / 取消 / 恢复不完整等路径不得伪造角色获知。
- [ ] 当前 SceneCatalog / 世界操作如何承载在场状态及缺失字段的失败关闭行为明确。
- [ ] 架构文件、IPC 契约与依赖图一致；独立 subagent 评审通过。
