# 045 — 实现：动态角色在场与定向对话选择

## 目标与背景

044 定稿场景角色在场状态后，将固定 / 动态角色可交互快照接入正式提交入口，并在对话 composer 提供当前在场角色选择。复用 030 的接收者校验、目标持久化和 `CharacterSpeech` 写入；选项只消费可信场景状态，不从实体目录或对话文本猜测。

## 范围与非目标

范围：按 044 交付引擎权威在场快照 / 规则接入、动态角色加入与离场、接收者选项读取和前端选择交互，验证 stale / absent 请求在输入持久化前失败，并同步跨端类型 / 文档。

非目标：不实现角色自主排期、模型生成实体权限、记忆专属查询 / 批次 IPC、观察 / 传闻的语义推断或记忆系统设置；不回扩 023、025 既有任务。

## 前置条件与待决策

044 必须已评审通过；030 必须实现并验证目标后端入口，043 提供完整稳定的固定 / 动态实体注册表。025 的已实现组件作为 UI 基础消费，034 提供双语文案。本任务不以 025 的实机平台验收作为依赖，也不将 025 的遗留验收覆盖为本任务结果。

## 实施步骤

1. 按 044 在 `SceneCatalog` / 世界变更 / 恢复链建立有界、版本绑定的当前场景在场集合，并校验分支回退。
2. 将可信在场快照提供给角色选项读取和 `engine_submit_input`，服务端重查当前 revision；拒绝前不追加输入。
3. 接入 composer 的角色选择、旁白默认、切换 / 离场时清理失效选择、旧 session / phase 响应丢弃及双语显示。
4. 验证固定与动态角色的选择、拒绝、恢复、重启 / 回退及 `told` 证据一致性；更新架构、IPC 和 task 记录。
5. 候选完成后由 subagent 独立评审，处理发现并复验。

## 预计改动

engine 的 scene / entity registry 与 turn runtime、Tauri `game_commands` 装配、`src-web/api/engine.ts` 及对话 composer；IPC DTO 和架构文档以 044 定稿为准。记忆专属 API 归 031，别名流程仍归 030。

## 风险与回退

在场状态若无法沿 023 的有效分支重建，目标 UI 可能显示已离场人物。读取或恢复状态不完整时清空可选项并拒绝定向请求；旁白继续可用，不能将暂时缺失转换成永久知识证据。
