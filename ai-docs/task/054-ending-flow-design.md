# 054 — 设计：结局生成与周目落幕

- 状态：done
- 依赖：007、012、032、039、040、041
- 优先级：P1
- 创建 / 更新：2026-10-19 / 2026-10-23

## 目标与背景

`aoidos-art` 已提供 `ending-choice.html` 与 `ending.html`，但当前引擎没有可供 UI 消费的权威结局生成、提交和落幕状态。结局会影响周目是否结束、记忆刻痕何时生成、费用与记录如何封存、重启及分支回退如何恢复，不能由模型文本或前端按钮直接宣布。设计稿中的固定选项只作为视觉参考，不预设玩家从列表里选择结局。推荐分离“结局事实”和“结局叙事”：每个新周目在开局由 LLM 生成目标、标签目录和规则，引擎把完整快照锁定到当前周目的 SQLite 记录；剧本只登记可信状态字段 schema 和可选固定引导 NPC，不预置标签或规则。生成请求只在其预算身份已持久化后发出；具体初始化和崩溃恢复沿本任务的两阶段状态机执行。周目结束时引擎按隐藏数值求值并冻结可组合的语义标签，确定性地整理权威事实摘要；AI 据此创作文字，但不能决定、提交或改写事实，隐藏属性原值不传给模型。

## 范围与非目标

范围：定义周目何时满足结局条件、引擎如何依据隐藏状态及其他可信事实冻结唯一结局事实、AI 如何基于结局简报生成叙事、引擎如何提交权威终态，以及落幕记录如何持久化并与回合恢复、分支回退、费用结算和 032 记忆刻痕单向衔接。需明确自然语言生成的语义不可由 schema 或 prompt 完全保证，不能把提示词当作规则执行器。

非目标：不在本任务实现结局 UI、剧本编辑器或开放式世界属性；模型输出不得自行完成世界事实。剧本可登记可信状态字段输入 schema，但目标、标签和规则均由新周目开局生成，不在剧本资源中预置。

## 前置条件与待决策

007、012、032、039、040、041 的已定契约为输入。目标、标签和规则全部在新周目开局生成；剧本资源只提供已登记字段、合法范围 / 运算符与可选固定 guide NPC 身份，不存储目标、标签目录或规则。模型接收原文和字段 schema，不接收本局隐藏状态值；其输出可以生成标签、说明和规则，但规则只能引用白名单字段、有限比较运算符及同次响应生成的标签，不能产出任意表达式、属性、世界事实或身份 ID。完整结果经严格版本化校验、规范化和哈希，与 initializing run 身份、计费及 profile 绑定后冻结到 SQLite；开局后不得重算或受剧本文件更新影响。生成 / 校验失败时不启动新周目，不静默回退为旧模式。

到达独立的可信终局触发条件后，引擎在锁定规则上求值，把隐藏数值映射为零个或多个可组合标签，并冻结标签 ID、规则 ID / 版本与终局状态修订。标签表达具体成立的条件 / 后果，不泄露原值，也不只是文风指令；冲突组、优先级、缺失字段和未知值都必须有确定语义，不能将缺失值静默当零。只有公开策略允许的标签说明进入公开简报。引擎按固定顺序和确定性模板从标签构造权威摘要；AI 仅基于摘要生成非权威文学叙事，不负责判定标签、补充正史或提交世界事实。若同时展示两者，应明确区分。模型仍可能在自然语言中误述，prompt / schema 或第二个模型都不能提供可靠语义保证；逐句严格的事实文字应由模板或剧本作者文本生成。需设计规则生成与新周目事务、生成失败 / 计费 / 重试、标签冲突、分支回退和叙事存储恢复；重试复用同一冻结规则 / 标签 / 事实而不重新判定。若现有记录语法不足，先设计单向扩展，避免 memory / billing / UI 反向持有流程权威。

## 设计产出

1. 定义剧本可信状态字段输入 schema、可选固定 guide NPC 元数据和版本化的开局生成输出；剧本不得预设目标、标签或规则。
2. 定义生成结果严格校验、规范化 / 哈希及与新周目创建的持久化边界；规则一经锁定不可因重开、恢复、历史回退或剧本更新而重算，失败不能静默启动。
3. 冻结隐藏数值到语义标签的规则、版本、来源追溯、标签并存 / 冲突语义及缺省含义；标签由引擎确定，原始数值不会作为玩家选项或模型输入。
4. 定义终局触发、标签求值和从冻结标签到结构化事实及确定性规范结局摘要的映射，明确对外可见字段与剧本声明边界。
5. 定义规范结局摘要与 AI 文学叙事之间的关系；如同时展示，明确区分其权威性。AI 叙事不得成为新的世界事实、记忆证据或后续规则输入。
6. 设计可公开的结局简报与 AI 写作边界，规定结构 / 长度校验及失败处理；明确自然语言语义无法可靠验证，逐句严格的事实文本须由引擎模板或作者内容承担。
7. 规定供应商失败后的显式恢复 / 重试；重试复用同一冻结标签和事实，不重新判定结局或重复提交终态。
8. 定义“规则已冻结、满足终局条件、标签与事实已冻结、请求叙事、叙事已提交、周目已结束”的状态及其持久化、幂等、恢复、分支回退和重放行为。
9. 明确结局记录与计费终态、剧情正文、记忆批次 / 刻痕和下一周目创建之间的事务边界。
10. 定义 UI 可消费的快照 / 事件 / 错误类型；`ending-choice.html` 作为视觉参考的可复用部分单独标注，旧任务范围通过单向依赖接入，不在 023、032 或 052 中补写新的世界规则。
11. 规划独立实现 task、模块边界、迁移策略与故障注入 / 关键路径验收矩阵。

## 状态、身份与恢复协议

每个新周目先以稳定 `runId` 持久化 `initializing` 状态、script revision / input schema hash、profile revision 和 CNY / USD 预算快照；再由 035 幂等创建该 run 的预算身份。预算和初始化记录确认后，才允许发送生成目标 / 标签 / 规则的物理请求。若跨 crate 共用事务做不到原子提交，恢复必须根据已保存的预算快照用同一 runId 补齐，不读取变更后的设置。完整开局快照保存后才能由 initializing → playable。生成失败或结果 unknown 时 run 保持不可玩；物理费用、预留和 unknown 仍归该 run，不能删预算、另建 run 隐藏费用或自动重发。玩家明确重试时用新 requestId，沿用原 run / 预算；也可显式放弃未开局周目，历史费用仍保留。旧存档缺少初始化快照时按既有 legacy 语义处理，不为它补造规则或目标。

新 run 进入结局生命周期 `initializing → playable → endingPending → ended`；初始化失败后玩家显式放弃可转 `abandoned`。旧 run 缺少初始化快照时保持既有 `sessionEnded` 恢复语义，不补生成或猜测规则。`sessionEnded` 是现有世界终局条件事实，不单独代表摘要完成；该事实经 022 applied 后进入 `endingPending`，engine 根据锁定 ruleHash 与同一 terminal mutation 派生 `resolutionId`，具体字节算法见[剧本格式](../standards/scenarios.md#周目初始化输入与引导角色)，输出为 `sha256:<hex>`。随后追加已登记的 `endingResolved` 系统记录并经 022 JSONL / `store_applied` 协议确认；只有 applied 后状态才为 `ended`。`endingResolved` 必须包含固定 tag / rule provenance、公开事实、summaryLocale、模板版本、精确摘要字节及 summaryHash。

恢复优先于重新开放玩家输入：仅 enabled run 的有效历史若只有 applied `sessionEnded` 而没有 `endingResolved`，才按原 terminal anchor、rule snapshot 和 hidden world revision 确定性重建相同 resolutionId 并补交；已写 JSONL 未有 applied 回执时由 022 恢复；endingResolved 已 applied 时直接读取保存摘要，不重算。disabled / legacy-disabled run 保持原有终态恢复行为，不进入该补交路径。禁止调用 LLM 完成权威标签 / 摘要，也不允许崩溃恢复重发规则生成请求。摘要 / 终态持久化后才可生成文学叙事；该产物另存 `pending / complete / failed`，显式重试复用冻结摘要、locale、template / prompt version 与 style 参数，只使用新的物理 requestId。改变应用语言或提示词版本不重写已结束周目的摘要或旧叙事输入。

标签求值只使用终局锚点上已提交、类型合法的整数状态；任一规则引用字段缺失、未 applied、越界或类型不符时停止 resolution 并恢复，不当作零也不跳过。规则多条之间是 OR，每条条件是 AND；普通标签可并存，互斥组按剧本唯一优先级选择，不唯一则校验失败。规则生成不得接触本局隐藏值。`endingResolved` 是显式登记的系统记录，不把 AI 叙事注册成 `narration` / 世界 mutation；032 仅在权威 resolution applied 后单向消费允许的周期事实，不能反向触发结局。

## 验收标准

- [x] 开局生成的目标、标签与规则受版本化 schema / 白名单 / 范围校验，并在新周目开始前冻结到 SQLite；剧本不预置标签或规则，失败不静默切换流程。
- [x] 隐藏数值经冻结的引擎规则生成语义明确、可组合且可追溯的标签；原值不直接暴露为玩家选项或模型输入。
- [x] 冻结标签按确定性规则整理成规范事实摘要；阈值、缺省、冲突和公开边界明确。
- [x] 引擎规范摘要从冻结事实确定性生成并保留为结局正史；AI 叙事不能成为世界事实、记忆证据或后续规则输入，并如实说明自然语言校验的限制。
- [x] 逐句严格的事实文本由引擎模板或作者内容承担；AI 叙事的失败恢复和重试复用同一冻结事实，不重复判定或提交终态。
- [x] 触发、重试、崩溃恢复、回退、重放及重复请求均有明确且可验证的语义。
- [x] 记录封存、费用结算、记忆刻痕与新周目入口有无环的依赖图和事务边界。
- [x] `turn-state-machine.md`、`record-engine.md`、`memory.md`、`scenarios.md`、`billing.md`、`ipc-contract.md` 与 task-index 同步；独立实现任务依赖准确。
- [x] 每个新周目的开局生成快照使用版本化 schema 并作严格白名单校验；旧存档沿用 legacy 恢复语义，不合成历史规则。
- [x] 设计经独立评审并处理发现；本任务不声称结局页面或流程已经实现。
