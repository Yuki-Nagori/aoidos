## 目标与背景

人工游玩发现许多本应直接叙述的常规行动也会触发骰判。现有 `CheckProposal` 请求只列出 JSON 形状、登记规则和角色，没有给模型判定门槛，导致决策尺度不稳定。本任务明确骰判应该覆盖有不确定性且有实质风险 / 后果的行动；平常移动、观察、取用可及物、表达或不改变世界状态的尝试在没有阻力时直接叙述。若行动结果显而易见、玩家在描述中已选择了放弃/接受某结果，或失败不会带来不同后果，优先 `noCheck`。骰判保留给规则相关、结果不确定且会改变局势的关键行动。

决策只决定是否调用已有登记规则，不得让 LLM 修改骰值、规则、角色范围或引擎执行结果；提示文字不能替代 Rust 对规则和角色身份的校验。

## 范围与非目标

- 在 `CheckProposal` 专用请求中加入明确、简洁、双向的 `check` / `noCheck` 决策准则和典型边界例子。
- 测试检查提示包含统一门槛，并验证格式约束与已登记 rule / actor 白名单继续保留。
- 不修改骰判协议、规则、结果分档、随机数、费用或 IPC；不以固定比例强行限制每局骰判次数。
- 不新增叙事选项按钮；这属于另一个产品设计任务。

## 实施步骤

1. 核对 `CheckProposal` 请求最终拼接的玩家输入、记录上下文与目标格式，确保决策门槛能读取行动语境。
2. 将必要条件写入 Rust 提示构造处：存在真实不确定性、失败 / 代价会产生有意义且不同的结果、已有规则能准确覆盖行动；任一条件不满足时 `noCheck`。
3. 加单元测试锁定门槛文本和格式，并确认规则 / 角色白名单校验不变。
4. 运行受影响 Rust 测试、格式与 Clippy；候选完成后由 subagent 独立评审，修复后复验。

## 验收标准

- [x] 检查提示明确鼓励常规、无阻力、无实际风险的行动走 `noCheck`，并限制骰判为结果不确定且有实质后果的行动。
- [x] 提示要求模型不推断/伪造未登记规则和角色，既有 Rust 校验继续作为最终门禁。
- [x] 回合测试覆盖 `noCheck` 与 `check` 分支；提示文本测试检查双向准则，避免只有“何时掷骰”的单侧提示。
- [x] 相关 Rust 测试、格式、Clippy 通过；独立评审完成并处理发现。
- [x] 文档只描述本任务实际增加的提示准则，不承诺模型始终正确或骰判频率的定量目标。

## 风险与回退

模型仍可能违反自然语言决策标准；该改动只能改善建议倾向，不能提供严格的概率保证。若提示退化或影响已有规则选择，可回退专用决策说明，不动确定性骰判路径与身份校验。

## 决策与工作记录

- 2026-10-23：人工测试显示常规行动被过多送入骰判。检查现有提示后确认缺少决策门槛；将改动限制为引擎专用 check-proposal 提示和相应测试。
- 2026-10-23：加入“不确定性 + 有意义的失败/代价后果 + 准确登记规则”三项同时满足才提议判定，并为普通无阻力行动、结果显而易见或无后果差异的行动明确 `noCheck`；同步回合状态机原则。
- 2026-10-23：独立评审发现原测试只验证提示常量。已改为捕获并断言实际 Provider 提示，包含玩家行动、双向门槛、JSON 两分支和规则 / 角色列表；复核无新发现。PR #203 已合并到 main。
- 2026-10-23：main CI #39903376713 的引擎测试偶发在“检查对象已有但尚未进入稳定等待阶段”时注入取消事件，导致观察到 Failed。065 分支将该测试同步点收紧为 `AwaitingCheck + Waiting`，并重复运行 10 次通过；完整引擎测试也通过。

## 完成摘要

调整了 `CheckProposal` 专用提示的骰判门槛，并用真实 Provider 输入测试锁定其完整拼接。门槛可改善模型倾向，不保证统计意义上的骰判频率。
