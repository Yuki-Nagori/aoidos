## 目标与背景

目录中的“结算待恢复”需要跟随账本当前义务刷新。用户进一步确认：删除周目时勾选不可撤销确认，就代表允许删除该周目全部本地数据，包括未结算费用请求和本地账务记录，不应再卡在无法完成的结算门禁上。

目录读操作以 ledger 当前义务刷新陈旧的 `settlement-pending` 展示状态。仍有未结账务时，删除对话框明确说明这些账务也会永久删除；勾选后向引擎传递显式确认，并将确认写入删除 journal，确保重启恢复不扩大用户授权。周目 / 记忆 / 账务身份映射仍需通过校验，不能借用户确认删除归属不明的数据。

## 范围与非目标

- 周目分页只读时，针对历史持久化的 `settlement-pending` 按实际账本状态刷新摘要；不为无关状态添加重算或迁移。
- 投影前核验目录与 `memory_run_sessions` / `memory_runs` 的身份映射；映射不一致时显示需修复并禁用删除，不显示成费用已结清。
- 更新删除提示与恢复按钮文案，明确未结请求及本地账务也会被删除；保留恢复后重试 / 补登入口。
- 未勾选确认且账务未结时，后端拒绝登记删除；勾选确认后将授权持久化，删除只清理经身份校验的本局 scope。
- 不伪造零用量、不重新请求供应商、不清理共享价格 / profile / 归属不明记录。
- 通用剧情行动选项不属于本任务。

## 验收标准

- [ ] 列表状态随账本实际义务变化：未结请求显示待处理；义务全部结清后旧状态自动恢复到可继续或未配置费用状态。
- [ ] legacy 账务范围存在未结请求但记忆身份映射损坏时，列表显示需要修复且禁用删除；最终删除检查仍独立拒绝。
- [ ] 未结请求时未确认删除被后端拒绝；明确确认后可创建删除 journal 并清除本局账务 scope。
- [ ] 删除确认和授权能跨启动恢复；身份映射异常仍失败关闭，不能清理不明 scope。
- [ ] 中英文提示完整说明处理路径。
- [ ] 后端目录测试覆盖从 pending 到 settled 的刷新；前端受影响测试、Rust 检查、i18n 与格式通过，独立评审完成并处理发现。

## 风险与回退

删除授权是破坏性操作，UI 明示包含未结账务并要求勾选。journal 持久化确认，未确认的账务义务不能通过启动恢复被清除；身份映射不一致时继续失败关闭。

## 决策与工作记录

- 2026-10-23：确认账本有本地 settlement retry 与 usage backfill 入口，但持久目录状态未随费用处理刷新；同时将删除勾选明确定义为允许清除本局全部数据，包括未结账务。
- 2026-10-23：独立审查发现目录 memory ID 缺失时可能漏查已映射的 legacy 账务范围。投影现在复用删除校验的身份对应关系；异常显示“需要修复”并禁用 UI 删除。
- 2026-10-23：确认状态写入独立 deletion journal 表；旧操作缺少授权记录时按未授权恢复。集成测试验证未确认请求与结算 outbox 可随本局一起清除。
